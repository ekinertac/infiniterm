# infiniterm: working notes for agents

Terminal, editor, diff, transcript and browser cards on an infinite zoomable canvas, driven by Claude Code hooks and `ift`. Rust: gpui for the window, `alacritty_terminal` for the grid and VT parser, tree-sitter for the editor, CEF for the browser card. macOS only. `README.md` is the product description and the key table; this file is what an agent needs to work in the tree.

The installed `/Applications/infiniterm.app` is this repo's release bundle and runs on Ekin's real data dir. Never launch a second copy without `INFINITERM_DATA_DIR`: the socket lock makes it exit, and a scratch data dir is the only safe way to test.

## Rules that shape the code

- `core` knows rects, ids and kinds, never what a card body draws. A body is a `CardBody` in the ui crate; the model reaches it only through `Effect`s and reads back through `EditorEvent`s.
- Logic is a pure function in its own file with tests; gpui elements are wiring. Every command is registered in `model/`, so the palette, the keymap and `ift` cannot drift. Nothing is mouse-only.
- `Cmd` owns every app binding except `ctrl`+digit and the card switcher's `ctrl+tab` / `ctrl+shift+tab`; a focused terminal gets everything else. Chords are built from the PHYSICAL key: `keycode.rs` keeps an NSEvent monitor that records every key-down's key code and real Shift flag, and `keymap.rs` names the chord from those, so Turkish Q and every other layout get the keys the panel shows. Alt+Arrow and Cmd+Arrow belong to the shell. Inside a LOCKED editor the find, replace, comment, undo and select-to-boundary chords are the editor's (`editor_keys.rs`); an editor merely focused with Cmd+Alt+Arrow is a card like any other and the canvas keeps them (since 2026-09-24: Cmd+/ on an arrowed-to editor commented a line instead of opening the shortcuts panel), and a chord the canvas does not bind does nothing there; inside a browser the zoom chords are the page's (`browser_keys.rs`). The emoji panel is `app.emoji` on `cmd+ctrl+space`, ours through the same path, because macOS handles that chord system-wide too and with a gpui action bound to it as well the three fought and it worked sometimes.
- Text that is not a key (the emoji panel, a dead key's composed letter, an input method's commit) arrives through `ime.rs`, the app's one view as gpui's `EntityInputHandler`, and goes to the open field else the focused card's body (`CardBody::insert_text`). The contract that makes this safe: gpui hands `key_down` every key FIRST and lets only an untaken key reach the input context, so a body says `BodyAction::Ignored` and a field says `Edit::Ignored` when they did not take a key, `key_down` stops propagation when they did, and typed text cannot arrive twice. A dead key is recognised from the NSEvent's empty `characters` in `keycode.rs` (`last_dead`) and refused at the top of `key_down`, never from the keystroke: gpui reports it as the standalone accent. Marked text is held in `AppView::composing` so macOS keeps composing, and drawn: `composing.rs` paints it underlined at the focused body's caret (`CardBody::caret_bounds`, the terminal's cursor cell or the editor's `painted_caret`) in the terminal font at the size the cell implies, and a field draws it inline (`Field::inline_composing`).
- Positions are permanent; nothing re-tiles. A new card takes the first free slot of a square block grown from the workspace's top-left corner (`layout::block_order`, `block_slot`): ring n adds column n top to bottom, stopping above the corner, then row n left to right ending on it, so 4 cards are a 2x2, 9 a 3x3, 17 is the top of column five. It does not depend on the focused card, and a hole a closed card left is filled first. The lattice is laid over the WHOLE workspace (`layout::fill_slot`, 2026-09-26): free slots inside the box the cards already cover come first, in block order from its top-left, and only a full box grows, right and down, never up or left; the lattice stays anchored at the canvas's half cell so new cards line up with old ones. Counting from the canvas origin alone missed every hole in a workspace whose cards had been moved up and left of it (Personal Stuff reached x = -5237), and Cmd+T kept growing past them. Cards have the screen's shape, so the block does too and fit-all fills the window. Before 2026-09-24 a card took the free slot NEAREST the focused card, ties to the window's aspect; Ekin could not say where Cmd+T would land, which is the reason it went. No fixed column count. Nothing re-tiles on its own; `canvas.tidy` (palette only, 2026-09-24) does it when asked: the workspace's cards in reading order go back into the same block from the top-left of their bounding box, each keeping its size, a column as wide as its widest card and a row as tall as its tallest (`layout::tidy`), then fit-all; Cmd+Z scatters them again. Groups move to a free block right of everything.
- Anything that reads card geometry is scoped to one workspace. Card placement treats other groups' frames as occupied. A card may not be dropped over another. Dragging a single card moves a GHOST (`Gesture::ghost`: an outline, focus-ring colour when the space is free, `warn` when not) and the card goes there on the drop (`Model::drop_card`, gliding) or stays where it never left; the card sliding under the pointer from the first pixel read as a mistake being made rather than a choice being offered. The ghost snaps to the SLOTS the cards around it offer (`slot_snap.rs`: a neighbour's edge, or its far edge plus the gutter, on each axis within a quarter of the ghost's extent; else the placement lattice), because there is no fixed lattice of quarters when a split makes 1000 and 975 from 2000. A drop with the ghost's centre on another card swaps the two (the arrow-swap's rule); Escape mid-drag cancels. A group drag still moves the cards live and `Model::end_gesture` puts them back on an overlap. A drag shows alignment guides on exact matches only, against the ghost while there is one. Every move, swap, drop and resize calls `Model::remember_layout` first, so `layout.undo`/`layout.redo` (Cmd+Z / Cmd+Shift+Z; an editor keeps those for its buffer) walk one trail of `UndoStep`s: `Rects` (a move) and `Closed` (a card; undo reopens it in its slot through `reopen_card`, the same path `card.reopen` uses, and takes it out of the reopen ring so Cmd+Ctrl+T does not bring a twin). Undo NEVER closes a card: making a card was a step (`Created`) from 2026-09-21 to 09-26, and Cmd+Z on a card Ekin had opened and started working in closed it, shell and all; there is no redo of a close either, for the same reason. `Model::undoing` keeps the reopen an undo performs off the trail. Closing a card with several tabs, browser or editor, asks first unless the card is locked (there Cmd+W is one tab); Ekin closed an editor of tabs meaning one tab. One card is a focus and wears the white ring; in a SELECTION the active card stays white so you can see where you are and the rest wear blue, all at one strength, because a command acts on all of them and a dimmed ring made it unreadable which.
- Every viewport change is animated; the system's reduced-motion switch outranks `ui.animations`. UI affordances are sized in screen pixels then divided by the zoom; the interface multiplier (`ui_scale`, Cmd+Shift+= / -) reaches every piece of chrome (card labels, the title bar and its tabs, the status bar, the palette, the dialogs, the shortcuts panel; `titlebar_h()` / `statusbar_h()` in main.rs) and never terminal text, borders or focus rings. The traffic lights stay where macOS put them.
- One tagged event stream for all panes; the reader thread moves bytes, the UI thread parses one budget per frame (the scheduler in `infiniterm-term`). Backpressure is 256 KiB unacknowledged per pane.
- Four card states, because `Notification` and `Stop` answer different questions: working (mid-turn, or a long command running; violet), waiting (blocked on you: a permission prompt, a question; yellow), failed (a non-zero exit, a `StopFailure`, OSC 9;4;2; red) and done (the turn finished; green). They get four HUES, not brightnesses, because two oranges are one colour at 40% zoom; failed was split from waiting on 2026-09-25 (Ekin: asking and broken are different news), and working left Claude's clay for violet the same day because clay and red blur at fit-all and blue is the selection ring's. A group frame carries NO agent state: it holds several sessions and one colour cannot say which of them wants you, so colouring it drew the eye to the box instead of the card that was asking. The workspace tab wears ONE DOT PER CARD in the cards' reading order on the canvas, top row first, left to right (`workspaces::reading_order`, then `tab_dots`), grey for a card with nothing to say and the card's hue when it is working, waiting, failed or freshly done, a row of lamps that light one at a time; done counts only for turns that FINISHED AFTER YOU LEFT that workspace (against `Model::left_at`, stamped in `show_workspace`, session-only) and never on the active tab: a Done card stays Done until its next turn, so counting every one lit the dot for good, which is the same as having no dot. Nothing else in the chrome may borrow an agent colour; `warn` exists for that. A card's title is a name somebody chose; the label derives name, else the agent's session name (its terminal title, trusted only on a card that `runs_agent`: a transcript this session or a saved `agentSession`, and saved itself as `agentTitle` since 2026-09-25, because after a relaunch an idle Claude card had neither the transcript nor the title in its ring and was labelled by its directory), else process, else directory.
- Settings: defaults and overrides are separate files, the defaults rewritten at launch; a new setting needs a `settings_doc.rs` entry or the test fails. Writes to the user file patch the text, never reserialise. Keys are FLAT and dotted (`"terminal.fontSize": 16`, VS Code's shape) since 2026-09-18, because extending a nested value meant copying the nesting; `config::flatten` reads the old nested shape too, a setting spelled both ways takes the flat one, and nothing writes the nested shape any more (`patch_json_text` replaces a value where it finds it, flat or nested, and inserts a missing one flat).
- The save file is never written before it is loaded, and never written back by an older build (read-only mode). Under the local backend a restored card gets a fresh shell in its saved directory; under tmux it adopts the window it had.
- `terminal.backend` names three backends (`pty`, `tmux`, `daemon`), and `daemon` is the default. What stands behind the flip: `infiniterm-term/tests/backend_equivalence.rs` renders the same inline redraw through the local pty and through `iftd` and compares the grids, and Claude Code itself ran in a card under `iftd` on 2026-09-17 with none of the corruption tmux produced. That was the question the whole design existed to answer. `tools/drive/daemon.sh` is the scripted version and is still worth running as a regression; it had not been run when the default flipped. Reverting is one line in `config.rs`. Our own daemon, `iftd`, is a sidecar per card, not a server for all of them: one socket per pane makes backpressure the kernel's problem rather than a protocol we have to get right, because when the app stops reading the socket, `iftd`'s write to it blocks, so it stops reading the pty, so the child blocks at the kernel's pty buffer. There is no ack frame anywhere in `session_protocol.rs` because of that chain. `iftd` parses no VT at all, which is the entire reason it exists instead of another tmux: a reattach replays the ring's raw bytes into our own parser, so what our emulator sees is byte for byte what it would have seen live, and there is no second emulator's idea of the screen to disagree with. Sockets live at `<data>/s/<id>.sock` (`paths::sessions_dir`), under the data dir on purpose, so `INFINITERM_DATA_DIR` isolates a scratch instance's sockets for free the same way it does everything else. A card's handle in the save file is `session` now, whichever backend holds it (a tmux window id or a daemon's socket id); `tmuxWindow` is still read as a fallback for canvases saved during the tmux evening, just no longer written. `Panes::we_are_the_terminal()` gates whether the emulator's query replies (`TerminalBody::replies`) are sent: true for local and for the daemon, because under both WE are the terminal, and false only under tmux, which answers first itself. Get this backwards and a second answer reaches the program as keystrokes (tmux bug 9, docs/tmux-handover.md). The kitty keyboard protocol (`Grid::kitty_keys`) is what makes Shift+Enter a line break in Claude Code and Pi: alacritty answers `CSI ? u` with `kitty_keyboard: true`, and the gate is "the program ASKED", not "a flag is pushed", because Claude never pushes one. The ring keeps a session's first 8 KiB (`PREAMBLE_BYTES`) and replays it ahead of the rest once it has wrapped, so an adopted card gets back every mode its program set at startup, and the flag is also saved per card (`kittyKeys`) because Claude was measured never re-asking.
- `iftd`'s protocol (`session_protocol.rs`) must stay BACKWARDS COMPATIBLE from 2026-09-23: an update swaps the app and restarts it, and the daemons the previous build started keep running under the new app, which must still adopt them. A change that breaks an old daemon's handshake turns every friend's update into a canvas of dead cards.
- `ift attach` DISPLACES the app on purpose (`iftd` serves one client; a new connection evicts the old): the app's reader sees EOF without `Exited` and reports `PaneEvent::Detached`, the card is marked `displaced` (a banner, keys swallowed, the pane id kept so nothing spawns a second shell), and `terminals.rs` polls the daemon's meta once a second (`attached`, rewritten by `iftd` on every attach and detach, decided by epoch so an eviction mid-handshake cannot clear the newcomer's flag) and re-adopts the moment the outside client lets go; the grid is reset first because the adopt replays the whole ring. Before this the card simply froze. `ift attach 7` takes the card's number, since a daemon's id changes with every reboot.
- tmux stays selectable (falling back to local PTYs when tmux is missing) because `ift attach`-style outside access was its one real advantage and the daemon now has its own version of that (`ift sessions`, `ift attach <id>`); it is not the default because it was the default for one evening and was pulled, see docs/tmux-handover.md for the ten bugs that evening produced and the one that is still open. One `tmux -C` control client on the default socket, one session, and a card is a WINDOW with one pane, never a pane inside a shared window: `refresh-client -C '@0:100x30'` gives each window its own size, panes tile and would have to share one. tmux draws nothing; it reports bytes and our emulator renders them, which is why scrollback, selection and the mouse are unchanged. Quitting DETACHES. The ack ledger drives `refresh-client -A '%0:off'` / `'%0:on'` at the same 256 KiB mark the local backend stalls at, or one flooding card would delay every other through the single socket; `pause` is NOT the verb, it discards. A scratch instance uses the session `infiniterm-dev`, never `infiniterm`. See spikes/tmux/NOTES.md for what was measured.

## Decisions taken in this codebase

- Frames are painted on demand: `needs_frame()` (animation, gesture, pending output, dirty bodies, an expiring notice) gates `request_animation_frame`; a 16 ms poll task drains the backend channels, runs the save debounces and the editors' disk polls. The status bar fps is stale while idle. `frame_reason()` says which condition asked; `[paint]` in `run.log` under `INFINITERM_KEYLOG` says where a frame went. Chrome that changes from a backend event after the element tree was built (a find count, a suggestion list, a browser's address after back) sets `redraw`, the owed-frame flag, or it shows one frame late.
- A card's state also comes from ANY program, not only an agent's hooks (2026-09-24, `program_state.rs`): the model scans each card's LIVE output (`PaneEvent::Output`, never `Replay`, or old marks relight cards) for OSC 133 (133;C a command started, 133;D;<status> it ended), OSC 9;4 progress (1/3 working, 2/4 waiting, 0 done) and OSC 9 / 777 / 99 notifications (waiting). A command that runs `LONG_MS` (5 s) shows working and ends done on status 0, so an `ls` never leaves the card green (green on every shell card would say nothing); a FAILURE shows failed however quick it was (Ekin, 2026-09-25), except Ctrl+C's 130; the next command clears the last result; a full-screen program (the alternate screen: vim, htop) never colours it; a hook during the command, or an agent session on the card, leaves the hooks in charge; and the stale sweep skips a running command, a quiet build is not a crashed agent. zsh sends no marks itself: `shell_integration.rs` writes a `.zshenv` shim and `infiniterm.zsh` to `<data>/shell/zsh` at launch and a shell card's zsh starts with ZDOTDIR there (the user's own ZDOTDIR handed over as `INFINITERM_ZDOTDIR`); the shim puts ZDOTDIR back and reads the user's files, the way Ghostty and VS Code load theirs. Only zsh, and only shells started after the update: an adopted daemon session keeps the shell it had. Every mark goes to `agent.log` as a `[shell]` line, a command's end with how long it ran (before cb280fd they went to the debug stream, and a failure that showed nothing left no trace).
- Every agent state change is appended to `agent.log` beside the save file (time, card, hook event, transition; capped at 512 KiB). It is the first thing to read when a card's colour looks wrong. A `Notification` flips a card to waiting only from working: one that arrives after `Stop` is a late echo, not a question.
- The terminal cell is the advance of `M` at the configured weight; `letterSpacing` is ignored. Wide characters put `SPACER` in their second cell. Every terminal font carries the bundled `Symbols Nerd Font Mono` (`assets/fonts/`, MIT) as its fallback (`terminal_body::term_font`, named by its PostScript name `SymbolsNFM`), registered with CoreText itself by `icon_font.rs` (`CTFontManagerRegisterGraphicsFont`) because gpui resolves a fallback through CoreText by name and a font given to gpui's `add_fonts` is invisible there (the first try, 912373c, still drew boxes on the Air; 1563c47 was checked there with a screenshot of the prompt, 2026-09-24), because Nerd Font icons live in the private use area and CoreText does not borrow an installed font for it: a card in Menlo drew boxes for the prompt's icons on the MacBook Air, which had six Nerd Fonts installed (2026-09-24); WezTerm ships the same font for the same reason. A terminal row is shaped ONCE as one line and every glyph is painted at ITS CELL (`terminal_body::paint_row`: `cell_w * col` plus the glyph's offset from the first glyph of its own character, so combining marks and ligatures keep their shape); the shaper's own advances are never used for placement, which is what removed both the drift and the fifteen `shape_line` calls a Claude row used to cost. The zero-width characters alacritty keeps on a cell (U+FE0F, the ZWJ, combining accents) ride beside the row's text in `Row::zerowidth`, never in it, because the bar painter, the backgrounds and the link underlines count one character per column; `shape_row` puts them after their cell's character in the shaped text and on its slot, so ⚠️ shapes as the colour emoji and 🏃‍♀️ fuses (the wide cell's spacer never enters the shaped text). Before 2026-09-24 they were dropped, and ⚠️ drew as a flat ⚠. A fused ZWJ emoji is still three cells in alacritty's grid where the program counted two: the glyph covers the first two and the third stays blank. A body keeps its `Frame` and `Grid::update_frame` rebuilds only the rows alacritty damaged; links are rescanned for those rows only. Below the legible line text is drawn as bars; the line is `chrome::legible_font_px(scale_factor)`, 7 DEVICE pixels (enough to draw a glyph) but never under `LEGIBLE_FLOOR_PX` 4.5 logical (big enough to read), so 7 px on a 1x screen and 4.5 on Retina (2026-09-24: the fixed 7 px turned a card on the MacBook Air to bars at 48% while its text was 13 device pixels). The history of the number: below a 5 px font, text was drawn as bars (was 3; at 4 px nothing was readable and eleven cards at fit-all cost 85 ms a frame in glyphs, measured 2026-09-19: gpui's `paint_glyph` is 1.7 µs of CPU each and a frame repaints every card). Since 2026-09-24 there is ONE rule past legibility, the frame's glyph budget (`chrome::GLYPH_BUDGET_CELLS`, 30,000 cells, about two full cards, or 1.5 windowfuls at 100% when that is more, `GLYPH_BUDGET_WINDOWS`: the fixed number was less than one windowful on the 4K, and three big cards covering the screen drew bars at 98%, 2026-09-24; the windowful is measured from the densest visible card): `paint_world` sums `CardBody::text_cells` over the visible cards, each weighted by the fraction of it the window shows, and over the budget every card draws bars (`set_crowded`) and content frames are rationed to one per `FAR_REFRESH_MS` (`AppView::far` is `crowded`); the terminal painter skips rows outside its content mask (`row_on_screen`), which is what makes a half-shown card cost half. The cost is the total, since a card's GRID does not shrink when the canvas does. Before, a font-size rule (`FAR_FONT_PX`, 12 px) drew bars while the viewport moved and rationed frames at rest by size alone; it stood in for the budget before the budget existed (2026-09-22), and it turned a single readable card at 57% (10.8 px, a smaller window on Ekin's 4K) into bars at 4 fps. Counted from the grids, not their contents, so the flag does not flip as output scrolls; only terminal bodies report cells so far. Rendering a card's text to a texture was checked and not done: gpui keeps its glyph rasteriser `pub(crate)`, so it would mean our own font path.
- A text selection is alacritty's, in grid points, painted in the app's selection pair. Its TEXT is ours (`Grid::selection_text`): Claude Code writes every screen row with a hard newline (checked in a Claude card's ring: no printable run longer than a row), so a copy across a wrapped paragraph came out broken mid-sentence; the WIDTH is the text's own (the widest row within 20 rows of the selection, because Claude wraps at the width it had when it drew, 73 columns on a 150-column card), at least two rows must reach it (one long row among short ones is the longest line, not a wrap) and it must be 40 or more (shorter rows are a listing); then a row within `SOFT_WRAP_SLACK` (12) of it whose next row continues at the same indent is joined with a space, the wrap indent dropped. A heuristic, said so. A body that starts a drag says so (`captures_drag`) and gets the moves and the release wherever the pointer goes. Shift+click extends the selection to the click (every Mac text view's rule) and the drag that follows keeps extending; a drag held past the card's top or bottom edge scrolls the grid a few lines a frame (`TerminalBody::autoscroll`, applied in `paint`, faster the further out, capped at `AUTOSCROLL_MAX_LINES`) with the selection's end following to the edge row.
- The cursor blinks from the frame clock; `wants_frame(now)` reports the next flip.
- The editor is ours: a rope with one cursor, undo grouped by CodeMirror's 500 ms rule, whole-text tree-sitter spans per buffer version, visual rows for wrapped prose (up/down move by visual row since 2026-09-20, `move_visual`), drafts half a second after a change, a two-second disk poll (which also re-lists the tree's shown directories, `Tree::refresh`, so a file made outside the app appears). JSON files use the JavaScript grammar because the config files are JSONC.
- The transcript card tells four speakers apart (`transcript::classify_user`, 2026-09-26): you, the agent, another agent session (`Role::Peer`, from a `<cross-session-message>` user record, named by its `from-name`, wrapper tags stripped, in the theme's magenta) and the harness (`Role::Notice`, a `<task-notification>` reduced to its summary line). Before, every one of those was a "you" turn with its tags showing. A message this session SENT (`SendMessage`) is written into the agent's turn as `→ name` and the whole message, not a tool line whose input is cut at `INPUT_CAP`.
- The diff card's rows come from `similar` with the merge view's collapse rule (margin 3, minSize 4). Bodies paint under a content mask.
- The browser lays out at the card's world size and is painted as a texture; the device scale follows the zoom in half steps above 100%. CEF starts before gpui, pumps every 4 ms, and reads its profile and the extension from `<data>/browser/`, seeded from Chrome's install and, once, from the spike's signed-in profile. A card can hold several tabs (`Card.tabs`/`active_tab`, one CEF surface each via `BrowserBody`'s `Vec<Tab>`); a popup, a `target=_blank` link, a Cmd+click on a link or "Open link in new tab" opens a tab on the same card now, not a card of its own — "Open link in new card" still exists for that. Saved only when `tabs.len() > 1`, the `session`/`kittyKeys` convention. The first click on an unfocused browser card only focuses it.

Double-Escape, both presses inside `DOUBLE_ESCAPE_MS` (400 ms), unlocks. A locked card's focus ring is `chrome.warn`, the same colour `warn` exists for elsewhere, and the status bar carries a text indicator too (`overlays.rs::browser_lock_indicator`) — two places because the ring alone is easy to miss and the status bar alone is off to the side.

## Traps already hit

- Both `cef` and `gpui` glob-export `App`, `Window`, `Point`, `MouseEvent`: import gpui by name.
- CEF aborts on `isHandlingSendEvent` unless `app_protocol::install` runs before `initialize` (gpui owns the NSApplication subclass). A helper invocation must run `execute_process` and exit before gpui starts.
- `alacritty_terminal::event_loop` gives 1 fps under flood; the scheduler is why it is not used.
- A binary started from a shell is not activated and gets no key events, and has no framework beside it. Bundle and `open`.
- CEF reads native-messaging manifests from `<cache-path>/NativeMessagingHosts/` only. `navigator.userAgentData` exists only in secure contexts; never probe the moat on a `data:` URL.
- gpui's `Keystroke` has no key code and delivers shifted punctuation shifted with the flag cleared: on Turkish Q, Cmd+= arrived as Cmd+Shift+0 and Cmd+Shift+= collided with it. Hence `keycode.rs`: the code and the Shift flag come from the NSEvent, not the keystroke. Checked on Ekin's keyboard.
- macOS delivers a Cmd key first as a key equivalent and, unless that is marked handled, again as a key down; gpui drops the repeat only when both parse identically, which Cmd+= on a non-US layout does not. Cmd+= zoomed twice per press until a handled chord called `stop_propagation`. Any new key path that takes a chord must do the same.
- A chunk of shaped text drifts after any non-ASCII glyph (an icon, an emoji has its fallback font's advance, not the cell's); the prompt's seconds digit vanished under a powerline segment. The first answer was 24-cell ASCII chunks with every other glyph shaped alone, which cost a dense canvas its frame rate while zooming; the answer that held is one shape per row and each glyph placed at its cell by hand (see the terminal cell rule above). The editor, diff and transcript bodies still chunk.
- `terminal.fontWeight` and `fontWeightBold` were parsed and never read for two days. A setting that reaches the config struct is not applied until something reads it; `settings_doc.rs` cannot catch that.
- The app inherits the environment of whatever launched it. Launched from a WezTerm shell, every card claimed to be a WezTerm pane. `local_pty.rs` removes the parent terminal's identity variables and sets `TERM_PROGRAM=infiniterm`.
- `serde_json` parses floats one ULP off without `float_roundtrip`; `Number` 14 and 14.0 are not equal, compare parsed `Config` values.
- A test must never bind `/tmp/infiniterm.sock`: the installed app holds it. `hooks::listen` takes the path; tests use a temp one.
- `cargo fmt` reformats a file under an edit made from a stale copy, and a text patch then silently matches nothing. Re-read after fmt; never `cargo fmt --all` (it touches the cli and hook crates).
- cliclick keys never arrive as gpui keystrokes. `screencapture -o` drops the window shadow, which offset every click by ~58 px.
- An effect that needs state from before the command (swap animation's old rects) must carry it.
- A notice or a pending save must not hold the frame loop open: a launch notice ran the app at 120 fps for five seconds.
- The palette matches "stress flood" to the calm command first; the driver types "run yes". Palette queries in scenarios must match a real label ("browser open a url", not "new browser"; "workspace: close", not "close workspace").
- System Events `keystroke "0" using {command down, shift down}` drops Shift to produce the character; use `key_code 29 "command down, shift down"` (and 24 for Equal, 27 for Minus) when a scenario needs a shifted chord. Chords are physical now, so scenarios press key codes, not characters.
- `resized` on a body was never called until the browser needed it; `paint.rs` now calls it when a card's rect changes. The terminal ignores it: `terminals.rs` refits and resizes the PTY together.
- Two apps named infiniterm with the same bundle id: a driver that finds windows or processes by name typed into Ekin's real canvas once.
- cef-rs's bundler sets `LSFileQuarantineEnabled`, so every file a card's shell wrote carried a `com.apple.quarantine` xattr naming infiniterm and Gatekeeper blocked builds made inside a card. `tools/bundle.sh` sets it false. Files already tagged need `xattr -dr com.apple.quarantine <dir>`.
- tmux, the short list (the long one is docs/tmux-handover.md): address by id (`%0`, `@0`), never index or name; one command per line, a `;` list is N reply blocks; every command sent pushes exactly one `Expect`, including `new-session`'s own reply, or the queue drifts; `refresh-client -A '%N:pause'` discards output, `off` holds it; `set-option -w -t <session>` hits the CURRENT window, tag by id; the ui asks for a size before tmux has named the window, so remember it and apply on the reply; `capture-pane` pads lines with tmux's widths, strip trailing blanks before replaying; a pane redraws the moment a client attaches, before we know whose it is, hold that output rather than drop it.
- A `Notification` hook can arrive a minute after `Stop`; mapping it to waiting unconditionally turned every finished card orange again.
- `git checkout <file>` to undo one thing reverted an uncommitted change in the same file. Reverse edits by hand.
- gpui's macOS view answers `mouseDragged:` but never registers `otherMouseDragged:`, so a middle-button press started a pan and no movement ever followed: middle-drag panning did nothing while Cmd+drag worked. `middle_drag.rs` adds the method at startup, pointing at `mouseDragged:`'s own implementation (gpui translates the event by its type and already maps middle drags to mouse moves).
- Cmd+click on links: `starts_pan` claimed every Cmd+left press. A Cmd+press that never moved is delivered to the body on release.
- A wheel over an open overlay reached the canvas; `Model::overlay_open()` gates `wheel`.
- gpui reports a dead key as the standalone accent (it translates the key with a space after it to have something to show), so nothing downstream of the keystroke can tell Option+E from a layout that types an acute. The NSEvent's `characters` is empty for a dead key and for nothing else.
- With Option held, gpui's `key_char` is the character the LAYOUT composes (`ş` on Turkish Q), not the base letter; the encoder assumed the opposite and sent `ESC ş`, which zsh showed as `<ffffffff>`. Where the layout composes something the character goes alone; where it does not (US: Option+S is `s`) Alt stays Meta.
- Greeking (word silhouettes by x-height, ascender, descender instead of flat bars below the legible size) was built and reverted the same hour, 2026-09-20: Ekin found the flat bars better and faster (4795b55, reverted in 2f6b61e). The bars are already per word; the next step past them is a texture per card, not a cleverer bar.
- Zoom quantisation: drawing text at whole pixel sizes while the zoom moves took glyph time down and shaping nowhere, and the text snapped between sizes inside a smoothly scaling frame. Reverted; the real cost was one `shape_line` call per non-ASCII glyph, fixed 2026-09-19 by shaping each row once.
- A replay must not go through `feed`: the ring holds the program's own past queries, and answering them again sends replies into the input of the program still running (tmux bug 9 by another road) and an old OSC 52 onto the clipboard. `feed_replay` keeps the title and nothing else.
- Cargo fmt on the cli and hook crates is not just a preference: a subagent ran `cargo fmt -p infiniterm-cli` and 15 lines of the reference's text went into a commit about something else. The Makefile says never.
- A backtick in a double-quoted shell string is command substitution. A commit message written that way ran `open` and lost three phrases; use a heredoc.
- macOS keys a privacy grant (Screen Recording, Accessibility) to the app's code signature. cargo's ad-hoc, linker-only signature has no stable identity, so the toggle in System Settings flipped itself back off and `tccutil reset` found five dead rows per service, one per rebuild. `tools/sign.sh` signs every bundle with the Developer ID, inside out: the framework's dylibs on their own (a framework's signature does not cover `Libraries/`, and the notary refused each one), the framework, the helpers, the app. The driver's keystrokes and screenshots need those grants on whatever app HOSTS the session running it, not on the scratch instance.
- An edit script run twice (a retry after an unrelated assertion) wrote a test function twice; `make check` failed while `make install` and the push went ahead, because the release build runs no tests. `grep -c "test result: ok"` is not a pass: read `make check`'s exit status.
- gpui's `add_fonts` puts a font in its own memory source, which a `FontFallbacks` name never reaches: gpui's mac `generate_fallback_array` asks CoreText (`CTFontDescriptorCreateWithNameAndSize`), and CoreText only knows fonts registered with it. A bundled fallback font must go through `CTFontManagerRegisterGraphicsFont` and be named by its PostScript name. `CGFont::as_ptr` needs the `ForeignType` trait from the foreign-types 0.5 family in scope.
- The MacBook Air is the small-screen test bed (`ssh air`; deploy by rsync of the bundle, screenshots with `screencapture -x` over ssh, keys by System Events key code). A claim about how the app looks there needs a screenshot from it, taken, not assumed.
- A unix socket path is capped at `sizeof(sockaddr_un.sun_path)`, 104 bytes on macOS including the NUL. A full UUID session id joined onto `<data>/sessions/<id>.sock` overflowed it on a long home directory; the directory is `<data>/s` and the id is 16 hex characters for the budget it leaves, and `backend::daemon::check_socket_path` refuses a spawn over the limit with a message naming the path rather than a bare bind failure.
