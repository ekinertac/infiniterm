# UI chrome, input and overlays

What this covers: how keys and text reach the app (Cmd owns the bindings, physical key codes, the text input system), when frames are painted, the window frame and menu, full screen, dialogs, find in a card, text fields, the palette's fuzzy match, the keycast, the shortcuts panel, and a batch of small decisions about the chrome.

Read it before touching `infiniterm-ui/src/input.rs`, `keycode.rs`, `ime.rs`, `composing.rs`, `overlays.rs`, `prompt.rs`, `field.rs`, `fullscreen.rs`, `keycast.rs`, `omnibox.rs`'s find bar, `paint.rs`'s chrome, or `infiniterm-core/src/keymap.rs`, `fuzzy.rs`, `shortcuts.rs`.

Related: `canvas-interaction.md` (mouse gestures, switcher), `editor.md` and `browser-and-pages.md` (the locked-card key tables), `traps-code.md` (key, dead key, cursor and overlay traps).

Moved here from CLAUDE.md on 2026-10-19 with the text unchanged.

- `Cmd` owns every app binding except `ctrl`+digit and the card switcher's `ctrl+tab` / `ctrl+shift+tab`; a focused terminal gets everything else. Chords are built from the PHYSICAL key: `keycode.rs` keeps an NSEvent monitor that records every key-down's key code and real Shift flag, and `keymap.rs` names the chord from those, so Turkish Q and every other layout get the keys the panel shows. Alt+Arrow and Cmd+Arrow belong to the shell. Inside a LOCKED editor the find, replace, comment, undo and select-to-boundary chords are the editor's (`editor_keys.rs`); an editor merely focused with Cmd+Alt+Arrow is a card like any other and the canvas keeps them (since 2026-09-24: Cmd+/ on an arrowed-to editor commented a line instead of opening the shortcuts panel), and a chord the canvas does not bind does nothing there; inside a browser the zoom chords are the page's (`browser_keys.rs`). The emoji panel is `app.emoji` on `cmd+ctrl+space`, ours through the same path, because macOS handles that chord system-wide too and with a gpui action bound to it as well the three fought and it worked sometimes.
- Text that is not a key (the emoji panel, a dead key's composed letter, an input method's commit) arrives through `ime.rs`, the app's one view as gpui's `EntityInputHandler`, and goes to the open field else the focused card's body (`CardBody::insert_text`). The contract that makes this safe: gpui hands `key_down` every key FIRST and lets only an untaken key reach the input context, so a body says `BodyAction::Ignored` and a field says `Edit::Ignored` when they did not take a key, `key_down` stops propagation when they did, and typed text cannot arrive twice. A dead key is recognised from the NSEvent's empty `characters` in `keycode.rs` (`last_dead`) and refused at the top of `key_down`, never from the keystroke: gpui reports it as the standalone accent. Marked text is held in `AppView::composing` so macOS keeps composing, and drawn: `composing.rs` paints it underlined at the focused body's caret (`CardBody::caret_bounds`, the terminal's cursor cell or the editor's `painted_caret`) in the terminal font at the size the cell implies, and a field draws it inline (`Field::inline_composing`).
- Frames are painted on demand: `needs_frame()` (animation, gesture, pending output, dirty bodies, an expiring notice) gates `request_animation_frame`; a 16 ms poll task drains the backend channels, runs the save debounces and the editors' disk polls. The status bar's fps (`ui.showFps`, off by default since 2026-10-01) counts only frames drawn back to back (`frame_rate.rs`) and shows nothing at rest: frames per wall-clock second read "6 fps" in the warn colour on a rationed canvas that was not slow at all (#16). `frame_reason()` says which condition asked; `[paint]` in `run.log` under `INFINITERM_KEYLOG` says where a frame went. Chrome that changes from a backend event after the element tree was built (a find count, a suggestion list, a browser's address after back) sets `redraw`, the owed-frame flag, or it shows one frame late.
- The window frame is `window.json` beside the save file. The socket is the single-instance lock. The app menu is built by hand (no File, no Edit), so Cmd+H, Cmd+Alt+H, Cmd+M and Cmd+Q are unbindable.
- Full screen (`ui.fullscreen`, default `cover`, 2026-09-24): `fullscreen.rs` gives gpui's `GPUIWindow` its own `toggleFullScreen:`, so the green button, `app.fullscreen` (Cmd+Ctrl+F) and the Window menu all reach it; cover keeps the window titled (a borderless one has no traffic lights and gpui's `windowDidResize:` panics on the nil buttons), hides the lights, sets the frame to `NSScreen.frame` and auto-hides the menu bar and Dock, so the notch sits over empty title bar; `native` passes the message up to NSWindow. A toggle from inside gpui is deferred a run-loop turn, or gpui drops the resize and draws at the old size.
- One dialog, three shapes (`prompt.rs`, drawn by `render_prompt`): a text prompt (label, field, the two keys captioned under it), a confirm (question, Cancel and the action's verb as buttons, `confirm(label, action, pending)`), and an alert (message, OK; unused so far). All sit under a dim sheet that cancels on a click outside; buttons click through `prompt_press`. Enter and Escape are the primary path; the buttons exist so a mouse is not refused. Since 2026-09-26 a confirm's buttons are walked by the keyboard (`Prompt::choice`: arrows and Tab move a highlight that starts on the action, Enter presses the highlighted one, one key for one thing where macOS splits Return and Space), and `confirm3` adds a third button, the macOS save sheet: a dirty editor's close asks Save (Enter) / Don't Save (Cmd+D, taken by `Prompt::chord` before the canvas, which would otherwise split the card behind) / Cancel (Escape, Cmd+.). Save saves and closes only when the editor mirrors the card clean (`save_then_close`, `close_when_saved` in `tick`, given up after `SAVE_CLOSE_MS` with a notice), so a failed save closes nothing. It replaced a two-press Cmd+W that discarded work on a double press. `tools/drive/dialogs.sh` shows them.
- Find in a card (2026-09-26): Cmd+F is `card.find`, the card's own search; it was card hints (`focus.hint`, now Cmd+J) from the first day, "find, loosely", which is how a terminal went without search until Ekin asked. A terminal and a browser share the find bar and `FindState` (`find_cmd.rs`); `Effect::Find` goes to `terminals.rs::terminal_find` for a terminal and to `browsers.rs` for a page. `Grid::find` searches the WHOLE scrollback with alacritty's `RegexSearch` on a literal pattern (smart case: lowercase ignores case), up to `MAX_FIND_MATCHES`, starts on the NEWEST match (what you look for in a terminal has just scrolled past) so Enter steps UP; every match is the theme's yellow, the current one the selection pair, built into rows the way selection is (matches filtered per row first). Output shifts the matches by the lines that entered history (`advance_bytes`); a full scrollback stops growing and cannot be tracked. Cmd+G / Cmd+Shift+G step while the bar is open and are group / ungroup otherwise. Cmd+E (`card.findSelection`) opens it holding the terminal's selection (`Effect::FindSelection`). Closing the bar leaves the current match SELECTED where it is, the view not moved, so Cmd+C copies it; Cmd+C while the bar is open copies it too unless the search field has a selection (`find_current_text`). Escape used to clear it and jump to the bottom, and nothing found could be copied. A hint jump (Cmd+J, then a letter) frames the card, as Cmd+1 does. Cmd+F on an editor opens the editor's own search and locks it.
- Small decisions of 2026-10-04: Cmd+Ctrl+Enter (`card.size.reset`) also grows the PHANTOM slot with the same corner rule (a slot beside a card keeps that card's size on purpose, `focus_neighbour`, so it can reach a freed quarter; this is how to change it before the card exists). The find bar is drawn inside the card it searches (`omnibox::find_bar_place`: top right, under the label chip, narrower in a small card, inside the window when the card is partly off screen). About is a dialog with no buttons (Enter, Escape or a click outside closes it; the update check is the app menu's), and a button with no key draws no key badge. The app sets a 512 pt copy of its icon at startup (`instance_icon::init`, `ICON_PT`): the running app reports 32 pt, and the Cmd+Tab switcher enlarged a small bitmap into stair steps; a badge is drawn at 512 pt from it. With a window colour set, the workspace tabs follow it (`chrome::tab_colors`).
- Every text field is `field.rs`: a caret and an optional anchor, macOS's chord set for a single-line field plus the Emacs handful, drawn through `Field::inline` (div fields) or a three-part paint (the editor's find bar) so the caret and the selection land where they are. gpui was checked for a field of its own and ships the IME trait and an example, not a component; gpui-component 0.4 has one but costs 40 crates for a field plus a code editor we already have, and Ekin skipped it.
- The palette's fuzzy match (`fuzzy.rs`) tries every occurrence of the first character as a start and prefers a character that continues the run; the first-occurrence greedy walk made "rgs" take the r of "Card" and lose CG-RGS to scattered letters in "Group: go to the previous". Same scoring, best alignment wins.
- The palette's own match is `fuzzy::strict_match` (2026-10-19, #490, Ekin: typing `check` listed "Canvas: tidy the cards into a block" and "Card: mask with a decoy / unmask"): a query of FOUR letters or more (`STRICT_MIN_CHARS`) must be a real match, which is the whole query in one run anywhere in the label (so a long card label that ends in "unchecked" is found), or initials (every letter starts a word), or at most two runs of two letters or more that each start a word (`tidy cards`); scattered letters and a piece that starts mid-word (`che` + `ck` in "chess game stack") do not count, and a one-run match earns `CONTIGUOUS_TIER` so the rows that hold the word come first. A shorter query is the loose `fuzzy_match` unchanged (`rgs`, `ntc` are abbreviations). The palette's recent rows are filtered by the same match. Editor completion (`complete.rs`, `words.rs`) and the shortcuts panel keep `fuzzy_match`: `hmap` for `HashMap` is a fuzzy match there on purpose. A row's label is cut to the room the row leaves beside its keys (`palette::fit_label`, measured in the palette's own font in `render_palette`, #492; a card's label can be a whole sentence): an ellipsis at the end, or when the first matched letter would fall in the cut part the window moves to it (`…` before, a few characters of context, the match), and the highlights follow the text.
- The keycast (`app.keycast`, bottom left, 22 px) is a runtime toggle, not a setting: on for a recording, off after. Entries fade on their own clock and `needs_frame` asks for frames only while one is alive. The label comes from `register::resolve_chord`, the same resolution `handle_chord` runs, taken before the chord runs, so on a locked card Cmd+T reads the tab command it opened.
- The shortcuts panel is a centred filterable overlay. A card has ONE label, in the corner, sized in screen pixels and stepped up as you zoom out (`chrome::corner_label_scale`: 1.0x `ui.cardLabelSize` above 60%, 1.1x to 25%, 1.45x below; 1.2 / 1.8 / 2.4 until 2026-09-25, when Ekin shrank the whole interface to 60% to get smaller labels zoomed out) on the focus ring's steps and for its reason. A second, larger label used to be drawn across the middle of the card below 60%; it existed because the corner label was believed to go unreadable, which it did not, since it never shrank with the canvas. Two labels saying one word, so it went. The panel also lists the mouse (`shortcuts::GESTURES`, gesture, what it does, its `usage.log` id); two tests hold it to `usage_log::MOUSE_GESTURES` both ways, so a recorded gesture cannot go undocumented.
