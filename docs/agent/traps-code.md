# Traps in the code

What this covers: mistakes already made in the code, kept so they are not made again: sockets and threads, gpui, CEF and macOS behaviour, keys and text input, painting, menus and overlays, files and settings, replay and tmux.

Read it before touching the area a heading names. Each trap says what went wrong and what to do instead.

Related: `traps-workflow.md` (traps about tests, git, building, signing and driving the app), and the topic file of the area (`terminal.md`, `ui-chrome.md`, `daemon-and-backends.md`, `join-viewer.md`).

Moved here from CLAUDE.md's "Traps already hit" on 2026-10-19 with the text unchanged; the headings are new.

## Sockets, processes and threads

- A unix socket connection ends only when EVERY copy of its fd is closed, and `shutdown(Both)` cannot be relied on to wake anything: on macOS it answers ENOTCONN once the peer has shut its write side. The join server's first end-to-end test never ended because a writer thread parked on its queue held a clone of the socket, so the viewer's ssh waited forever. Writers poll a closed flag their reader sets (`WRITER_POLL` in `backend/join.rs`); anything else that splices sockets across threads needs the same.
- A unix socket path is capped at `sizeof(sockaddr_un.sun_path)`, 104 bytes on macOS including the NUL. A full UUID session id joined onto `<data>/sessions/<id>.sock` overflowed it on a long home directory; the directory is `<data>/s` and the id is 16 hex characters for the budget it leaves, and `backend::daemon::check_socket_path` refuses a spawn over the limit with a message naming the path rather than a bare bind failure.
- `alacritty_terminal::event_loop` gives 1 fps under flood; the scheduler is why it is not used.
- The app inherits the environment of whatever launched it. Launched from a WezTerm shell, every card claimed to be a WezTerm pane. `local_pty.rs` removes the parent terminal's identity variables and sets `TERM_PROGRAM=infiniterm`, and `terminal_identity()` also sets `FORCE_HYPERLINK=1` (2026-10-09): Claude Code and the supports-hyperlinks package decide by terminal name, not by OSC 8, so without it a markdown link printed as `text (url)`. Only new cards get it; an open card keeps its environment.
- `ift read` is answered from the 16 ms poll timer (`terminals.rs::answer_reads`), not in a frame: terminal output is parsed inside a frame, and a hidden window draws none, so a read there returned a stale or empty screen. `ift sessions` checks each socket's pid; a killed daemon leaves its files behind.

## gpui, CEF and macOS

- Both `cef` and `gpui` glob-export `App`, `Window`, `Point`, `MouseEvent`: import gpui by name.
- CEF aborts on `isHandlingSendEvent` unless `app_protocol::install` runs before `initialize` (gpui owns the NSApplication subclass). A helper invocation must run `execute_process` and exit before gpui starts.
- CEF reads native-messaging manifests from `<cache-path>/NativeMessagingHosts/` only. `navigator.userAgentData` exists only in secure contexts; never probe the moat on a `data:` URL.
- gpui's macOS view answers `mouseDragged:` but never registers `otherMouseDragged:`, so a middle-button press started a pan and no movement ever followed: middle-drag panning did nothing while Cmd+drag worked. `middle_drag.rs` adds the method at startup, pointing at `mouseDragged:`'s own implementation (gpui translates the event by its type and already maps middle drags to mouse moves).
- gpui's `add_fonts` puts a font in its own memory source, which a `FontFallbacks` name never reaches: gpui's mac `generate_fallback_array` asks CoreText (`CTFontDescriptorCreateWithNameAndSize`), and CoreText only knows fonts registered with it. A bundled fallback font must go through `CTFontManagerRegisterGraphicsFont` and be named by its PostScript name. `CGFont::as_ptr` needs the `ForeignType` trait from the foreign-types 0.5 family in scope.
- gpui's `paint_image` has no alpha and `with_element_opacity` is crate-private, so a faded picture is a div's `.opacity()` around a `canvas` that paints it, and a div cannot be built inside a paint callback (`request_layout` panics outside prepaint: "this method can only be called during request_layout, or prepaint"). The background pictures are therefore elements in `render` under the canvas element (`background_show.rs`), and `paint_world` stops filling the window while a list is set. gpui also keeps every decoded image for good (`remove_asset` + `Window::drop_image` free one): only the shown, fading and preloading pictures stay resident.
- Dragging a workspace tab moved the window (#414): the main window has a transparent title bar and AppKit's own title bar layer starts a window drag from any press in that strip, above gpui's view; overriding `mouseDownCanMoveWindow` on `GPUIView` did nothing. `title_drag.rs` makes the main window not movable and drags it by hand from the bare bar (`performWindowDragWithEvent:`, `begin`), double-click through gpui's `titlebar_double_click`; a tab or the "+" stops the press so only the bare bar reaches it. Ctrl+Cmd+drag no longer moves that window.

## Keys and text input

- gpui's `Keystroke` has no key code and delivers shifted punctuation shifted with the flag cleared: on Turkish Q, Cmd+= arrived as Cmd+Shift+0 and Cmd+Shift+= collided with it. Hence `keycode.rs`: the code and the Shift flag come from the NSEvent, not the keystroke. Checked on Ekin's keyboard.
- macOS delivers a Cmd key first as a key equivalent and, unless that is marked handled, again as a key down; gpui drops the repeat only when both parse identically, which Cmd+= on a non-US layout does not. Cmd+= zoomed twice per press until a handled chord called `stop_propagation`. Any new key path that takes a chord must do the same.
- gpui reports a dead key as the standalone accent (it translates the key with a space after it to have something to show), so nothing downstream of the keystroke can tell Option+E from a layout that types an acute. The NSEvent's `characters` is empty for a dead key and for nothing else.
- With Option held, gpui's `key_char` is the character the LAYOUT composes (`ş` on Turkish Q), not the base letter; the encoder assumed the opposite and sent `ESC ş`, which zsh showed as `<ffffffff>`. Where the layout composes something the character goes alone; where it does not (US: Option+S is `s`) Alt stays Meta.
- Cmd+click on links: `starts_pan` claimed every Cmd+left press. A Cmd+press that never moved is delivered to the body on release.
- A wheel over an open overlay reached the canvas; `Model::overlay_open()` gates `wheel`.
- `handle_bare_key` must step aside for EVERY overlay (`modal_open()` plus the find bar), not a list of them: it ran before the modal checks in `key_down` and only knew the palette and dialogs, so with a phantom waiting, Enter in the omnibox opened the kind picker again (2026-10-06, #253). An editor's tree divider is dragged with the mouse (2026-10-06, #258): `EditorBody::on_divider` (a 4 world px grab zone each side of the line), the press holds it (`divider_drag`, `captures_drag`), the moves send `EditorEvent::Sidebar(width)` and `editors.rs` clamps it into `Card.sidebar`; its cursor reaches the window through `apply_hover_cursor` (`divider_cursor`). gpui gives a WINDOW-level cursor (`set_window_cursor_style`) precedence over every element's `cursor_pointer`, so the app asks for one only when it means it (a browser page under the pointer, a card edge, a held gesture, never while an overlay is up) and drops the canvas's hover state when the pointer is over the title or status bar; asking for the arrow every frame had made every pointer in the overlays a no-op (#256). An empty input shows the caret before its placeholder (`Field::empty_with_placeholder`). A clickable overlay element gets `cursor_pointer()` and a `hover` fill (`chrome::hover_fill`), a sheet's backdrop closes it on a click and the sheet stops the click (palette, shortcuts, omnibox, dialogs).

## Text and painting

- A chunk of shaped text drifts after any non-ASCII glyph (an icon, an emoji has its fallback font's advance, not the cell's); the prompt's seconds digit vanished under a powerline segment. The first answer was 24-cell ASCII chunks with every other glyph shaped alone, which cost a dense canvas its frame rate while zooming; the answer that held is one shape per row and each glyph placed at its cell by hand (see the terminal cell rule above). The editor, diff and transcript bodies still chunk.
- `resized` on a body was never called until the browser needed it; `paint.rs` now calls it when a card's rect changes. The terminal ignores it: `terminals.rs` refits and resizes the PTY together.
- Greeking (word silhouettes by x-height, ascender, descender instead of flat bars below the legible size) was built and reverted the same hour, 2026-09-20: Ekin found the flat bars better and faster (4795b55, reverted in 2f6b61e). The bars are already per word; the next step past them is a texture per card, not a cleverer bar.
- Zoom quantisation: drawing text at whole pixel sizes while the zoom moves took glyph time down and shaping nowhere, and the text snapped between sizes inside a smoothly scaling frame. Reverted; the real cost was one `shape_line` call per non-ASCII glyph, fixed 2026-09-19 by shaping each row once.
- An effect that needs state from before the command (swap animation's old rects) must carry it.
- A notice or a pending save must not hold the frame loop open: a launch notice ran the app at 120 fps for five seconds.

## Menus and keybindings

- The right-click menu is NATIVE (2026-10-07, #278): `context_menu.rs` holds the menus as data (an `Area`: terminal, frame, canvas, tab, editor; rows are registered command ids with a Title Case title, a `show` and an `enable` clause in the `when` language, a one-level submenu), `menus.rs` works out the area from the hit and builds the rows from the live registry and keymap, `native_menu.rs` is the one place AppKit is touched. The popup MUST run from a spawned task: `popUpMenuPositioningItem:` runs its own loop, and inside a gpui handler that re-enters the app and aborts with `RefCell already borrowed`; the chosen command id is run after the menu closes (`run_command`). A shortcut hint is `shortcuts::mac_key_equivalent` of the keymap's first chord for the command (a body's own chord, Cmd+C and Cmd+V in a terminal, comes from the table). A terminal whose program asked for the mouse keeps its right-click unless Shift is held. A click on a card's frame or label opens the SAME menu its body does (`context_menu::card_area`: terminal, editor; a diff, transcript, page or browser gets the generic Frame menu, as does any card of a selection of several): a card is a card, and a label or border click is hard to discover (Ekin, #421). The three CARD menus (a terminal's text, an editor's text, the generic frame) share `CARD_SECTION` (split, New, Group, Size, Move to Workspace, a Canvas submenu with Fit Card / Fit Selection / Fit All / Actual Size / Tidy / Select All, Rename, Protect, Mask, Clear State, Close) and differ only in their own top rows (`TERMINAL_TOP`, `EDITOR_TOP`, `FRAME_TOP`); a test holds them identical from Split Right down, so a card action is added once (#419). Cmd+A is `focus.selectAll`, every card of the workspace; a locked editor or browser keeps its own. Two more areas, `Tree` (a file tree row: the row is lit by `EditorBody::menu_row` while the menu is open, and the popup waits 80 ms so a frame is drawn first, since the blocking popup stops the frame loop; its commands act on that row through `EditorAction::Tree`) and `TabStrip` (a right-click on a tab switches to it, then the menu's commands act on the active tab). The browser PAGE menu is native too (`browsers.rs::show_page_menu`: Chromium's request becomes rows with actions, not commands, because they depend on the link or selection under the pointer). Not done: Ctrl+click and the group frame's menu.
- A command label ends with an ellipsis when the command needs a second action from the user (a name, a file, a choice): `a_command_that_asks_for_more_ends_its_label_with_an_ellipsis` runs every command on a terminal, an editor and a browser card and fails for one that leaves an overlay or a file picker open without it (information panels and a save that asks only for an untitled file are named exceptions; a command that asks only with state the probe lacks is named in `ALSO_ASK`). A new command that opens a prompt gets the ellipsis (2026-10-07, #277).
- Keybindings take a `when` (2026-10-06, #269, phase 1: user bindings only, defaults unchanged). `when.rs` is the pure parser and evaluator over a fixed key set (`when::KEYS`, VS Code's names where they match) and a `Context` the model builds (`Model::key_context`; the popup, find panel and selection are the ui's, written each key into `Model::ui_context` by `sync_ui_context`). `keymap::parse_keymap` accepts `{chord: id|null|{command, when}|[...]}`; a binding with a `when` goes to `CondBinding`s (`Model::conditional_keys`, last match wins, `command: null` unbinds there), and a chord WITHOUT cmd is accepted only if its `when` is false for `Context::terminal_focused()`, so no binding can take terminal input. Resolution: `resolve_chord` asks `conditional_for` first for cmd chords; `input.rs` asks it for bare keys before the built-in Escape and bare-key rules (and `command: null` on `escape` switches the built-in unlock off there). Not done: the hard-coded editor/browser lock tables are still Rust (phase 2: move them into default bindings with whens), and the shortcuts panel and `ift commands` list plain bindings only.

## Files and settings

- `terminal.fontWeight` and `fontWeightBold` were parsed and never read for two days. A setting that reaches the config struct is not applied until something reads it; `settings_doc.rs` cannot catch that.
- `serde_json` parses floats one ULP off without `float_roundtrip`; `Number` 14 and 14.0 are not equal, compare parsed `Config` values.
- Writing a file by temp file and `rename` replaces a symlink with a regular file: Ekin keeps `settings.json` in a dotfiles repo and linked it, and the first palette setting change or editor save broke the link. `files::write_atomically` canonicalises first and writes beside the target (`files::resolve_link` is the same step for a writer with its own temp file: the layout file, the licence, the browser history); `config_write` and the cli's hook installers go through it. Any new writer of a file that is renamed into place must too. A plain `fs::write` follows a link by itself.

## Replay, hooks and tmux

- A `Notification` hook can arrive a minute after `Stop`; mapping it to waiting unconditionally turned every finished card orange again.
- A replay must not go through `feed`: the ring holds the program's own past queries, and answering them again sends replies into the input of the program still running (tmux bug 9 by another road) and an old OSC 52 onto the clipboard. `feed_replay` keeps the title and nothing else.
- tmux, the short list (the long one is docs/tmux-handover.md): address by id (`%0`, `@0`), never index or name; one command per line, a `;` list is N reply blocks; every command sent pushes exactly one `Expect`, including `new-session`'s own reply, or the queue drifts; `refresh-client -A '%N:pause'` discards output, `off` holds it; `set-option -w -t <session>` hits the CURRENT window, tag by id; the ui asks for a size before tmux has named the window, so remember it and apply on the reply; `capture-pane` pads lines with tmux's widths, strip trailing blanks before replaying; a pane redraws the moment a client attaches, before we know whose it is, hold that output rather than drop it.
