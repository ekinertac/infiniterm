# Browser, page, transcript and diff cards

What this covers: the cards that are not a terminal or an editor: the Page card (read-only Markdown), the transcript card, the diff card, the browser card with its tabs and keyboard lock, and the omnibox.

Read it before touching `infiniterm-core/src/page.rs`, `transcript.rs`, `omni/`, `infiniterm-ui/src/page_body.rs`, `transcript_body.rs`, `diff_body.rs`, `omnibox.rs`, or `infiniterm-browser/` (owned by the `ift-browser` session: tell it).

Related: `editor.md` (the same lock and tab strip, the editor's own find), `ui-chrome.md` (the find bar both bodies share), `release-and-site.md` (the welcome and docs Page cards).

Moved here from CLAUDE.md on 2026-10-19 with the text unchanged.

- A Page card (`CardKind::Page`, #42) is a Markdown document drawn read-only: core's `page.rs` parses it with pulldown-cmark into blocks and lays them out into wrapped monospace lines (the terminal font, so wrapping is counting cells), `page_body.rs` paints them, scrolls (wheel; arrows, Page Up/Down, Space, Home, End while focused) and follows links (a web address to the system browser, a `.md` beside it as another Page). It NEVER takes the keyboard: any other key returns `Ignored` and stays the canvas's. A thumb at its right edge says it scrolls, and an editor card has the same one (`scrollbar::thumb`, pure, in core; `infiniterm-ui/src/scrollbar.rs` paints it, 6 screen pixels wide, faint, only when there is more than shows; the editor counts lines, not wrapped rows, so its thumb is a little long on prose). A terminal card has none yet. The welcome card is the first one; before, it was a read-only editor, and keeping read-only editors from locking (so a newcomer's click did not trap the keys) left the docs and the settings defaults without arrows or Cmd+F, so that was reverted (#41) and the welcome card got its own kind instead (Ekin, 2026-10-02).
- The transcript card tells four speakers apart (`transcript::classify_user`, 2026-09-26): you, the agent, another agent session (`Role::Peer`, from a `<cross-session-message>` user record, named by its `from-name`, wrapper tags stripped, in the theme's magenta) and the harness (`Role::Notice`, a `<task-notification>` reduced to its summary line). Before, every one of those was a "you" turn with its tags showing. A message this session SENT (`SendMessage`) is written into the agent's turn as `→ name` and the whole message, not a tool line whose input is cut at `INPUT_CAP`.
- The diff card's rows come from `similar` with the merge view's collapse rule (margin 3, minSize 4). Bodies paint under a content mask.
- A frame is drawn at the size it was LAID OUT at, never stretched to the card (#479, 2026-10-19, Ekin: "resizing a browser card stretching the texture"): CEF hears a resize at once (`Surface::resize` every frame) but its repaint at the new size arrives a moment later, and until then the newest frame is the old size; painting it into the new bounds squashed the page. `Frame::css_width/css_height` (surface.rs) record the `view_rect` CEF last asked for when it painted, the tab keeps them with its texture (`Tab::texture_css`), and `frame_fit::frame_draw_size` gives the size to draw: layout size times the canvas zoom, within 1.5 px of the card's page area counts as filling it. A mismatch is drawn anchored top-left under a content mask of the page area, with the card's own background beside it. A canvas ZOOM is not a stretch: the layout size is unchanged, so the natural size follows the zoom and a settled card fills its bounds exactly. A background tab's texture can be old too: switching to it shows its last page at its own size until its repaint arrives. Not rate-limited: the new size already goes to CEF every frame of a drag.
- The browser lays out at the card's world size and is painted as a texture; the device scale follows the zoom in half steps above 100%. CEF starts before gpui, pumps every 4 ms, and reads its profile and the extension from `<data>/browser/`, seeded from Chrome's install and, once, from the spike's signed-in profile. A card can hold several tabs (`Card.tabs`/`active_tab`, one CEF surface each via `BrowserBody`'s `Vec<Tab>`); a popup, a `target=_blank` link, a Cmd+click on a link or "Open link in new tab" opens a tab on the same card now, not a card of its own — "Open link in new card" still exists for that. Saved only when `tabs.len() > 1`, the `session`/`kittyKeys` convention. The first click on an unfocused browser card only focuses it.
- Focus lock (2026-09-19, docs/superpowers/specs/2026-09-19-browser-tabs-design.md): the next interaction past that focusing click — one that reaches the page, or a bare `Enter` on a card focused but not yet locked, the keyboard's way in for a card you arrow-focused — locks the keyboard to the card the way alt-tabbing into a real Chrome window would. `Model::handle_chord` (`register.rs`) checks `card.locked` before its own table and routes through `browser_keys::lock_override`, real Chrome bindings (`Cmd+T/W/Shift+T`, `Cmd+1..9`, `Cmd+Shift+]`/`Cmd+Shift+[` for next/prev tab — chosen over `Ctrl+Tab` because that one is Windows muscle memory, and `keymap.rs` had already reserved those two chords for `workspace.prev`/`.next` as a stand-in before real tabs existed) with `browser_override`'s always-on page list as the fallback; an unmatched chord falls through to the page (`None`), never gets swallowed. `is_locked_carveout` keeps `cmd+l` (omnibox) and `cmd+escape` (leave the page) app-side regardless, and `Ctrl+1..9` (workspace switching) is never in the lock table at all. Double-Escape, both presses inside `DOUBLE_ESCAPE_MS` (400 ms), unlocks. A locked card's focus ring is `chrome.warn`, the same colour `warn` exists for elsewhere, and the status bar carries a text indicator too (`overlays.rs::browser_lock_indicator`) — two places because the ring alone is easy to miss and the status bar alone is off to the side.
- The omnibox (Cmd+L, `omni/`) is not the palette: the palette fuzzy-matches a fixed list of commands, this takes free text and decides whether it is an address or a search. Ranking IS the section order, never a score: what you typed, suggestions, history, open cards, with the best history prefix lifted to a "best match" row so Enter goes where the inline completion says. On a browser card it opens holding that card's address and Enter navigates in place; anywhere else it makes a card, and the card it was opened on is never one of its own results. History is ours (`history.json`, frecency, written on the layout's debounce) rather than Chromium's, because reading the CEF profile's SQLite means a dependency and a lock fight with the browser that owns it; every navigation is seen in `browsers.rs`, which is why it is recorded there. Google's suggestions are off unless `browser.suggestions` is on and are fetched by a thread running `curl`, so a name lookup cannot hold a frame and no HTTP crate is in the tree. `ift omni <term>` prints the ranking from the running app.
