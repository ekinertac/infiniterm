# Browser, page, transcript and diff cards

What this covers: the cards that are not a terminal or an editor: the Page card (read-only Markdown), the transcript card, the diff card, the browser card with its tabs and keyboard lock, and the omnibox.

Read it before touching `infiniterm-core/src/page.rs`, `transcript.rs`, `omni/`, `infiniterm-ui/src/page_body.rs`, `transcript_body.rs`, `omnibox.rs`, the diff card (`infiniterm-ui/src/editor_body/diff.rs`, `infiniterm-editor/src/diff.rs`), or `infiniterm-browser/` (owned by the `ift-browser` session: tell it).

Related: `editor.md` (the same lock and tab strip, the editor's own find), `ui-chrome.md` (the find bar both bodies share), `release-and-site.md` (the welcome and docs Page cards).

Moved here from CLAUDE.md on 2026-10-19 with the text unchanged.

- A Page card (`CardKind::Page`, #42) is a Markdown document drawn read-only: core's `page.rs` parses it with pulldown-cmark into blocks and lays them out into wrapped monospace lines (the terminal font, so wrapping is counting cells), `page_body.rs` paints them, scrolls (wheel; arrows, Page Up/Down, Space, Home, End while focused) and follows links (a web address to the system browser, a `.md` beside it as another Page). It NEVER takes the keyboard: any other key returns `Ignored` and stays the canvas's. A thumb at its right edge says it scrolls, and an editor card has the same one (`scrollbar::thumb`, pure, in core; `infiniterm-ui/src/scrollbar.rs` paints it, 6 screen pixels wide, faint, only when there is more than shows; the editor counts lines, not wrapped rows, so its thumb is a little long on prose). A terminal card has none yet. The welcome card is the first one; before, it was a read-only editor, and keeping read-only editors from locking (so a newcomer's click did not trap the keys) left the docs and the settings defaults without arrows or Cmd+F, so that was reverted (#41) and the welcome card got its own kind instead (Ekin, 2026-10-02).
- The transcript card tells four speakers apart (`transcript::classify_user`, 2026-09-26): you, the agent, another agent session (`Role::Peer`, from a `<cross-session-message>` user record, named by its `from-name`, wrapper tags stripped, in the theme's magenta) and the harness (`Role::Notice`, a `<task-notification>` reduced to its summary line). Before, every one of those was a "you" turn with its tags showing. A message this session SENT (`SendMessage`) is written into the agent's turn as `→ name` and the whole message, not a tool line whose input is cut at `INPUT_CAP`.
- The diff card is the EDITOR in a read-only diff mode (2026-10-20, Ekin: "why diff cards using a different base. let's just make them read only editors. that way they inherit all the editor features we already solved"). It replaced a body of its own (`diff_body.rs`, about 970 lines with its own cursor, scroll, painter and keys) that had no selection, copy or find, and where #372 had just rebuilt a line cursor by hand. How it is built, so it does not grow a second base again:
  - `CardKind::Diff` stays (saved as "diff", `ift diff`, the palette commands, `Card.root`/`path`/`explorer` unchanged), but `CardKind::has_editor_body()` is true for it, and every lock site asks that instead of `== Editor` (`resolve_chord`, the lock ring, the status bar's "locked: diff", `browser.leave`, Cmd+F, the `card_locked` context, Cmd+Alt+Arrow inside the card). The body is `EditorTabs::new_diff`: the editor's wrapper with ONE body and no strip (`strip: false`), so the lock, the key swallowing and the mouse rules are the editor's code, not a copy. A diff card keeps its corner label (`paint_labels` skips only Browser and Editor, whose strips carry the title).
  - `EditorBody::diff` (`Some` only for a diff; the mode lives in `infiniterm-ui/src/editor_body/diff.rs`, a child module of `editor_body` so it can reach the private state) makes the body read-only and fills its `Buffer` with the MERGED text. The pure part is `infiniterm-editor/src/diff.rs`: `merged(original, current)` weaves HEAD and the working tree into one text in file order (context, removed, added; NO `+`/`-` prefixes, joined by `\n` with no trailing newline so the editor's line count equals `lines.len()`), with a `DiffLine { kind, old, new }` per line and the fold ranges; `merged_spans` moves syntax spans onto it. The kind lives in the decoration, so the highlighted text is real code. Lines are compared whole, endings included, and shown without them.
  - Syntax colours: the two sides are highlighted SEPARATELY (HEAD's text for removed lines, the working tree's for the rest) and the spans moved onto the merged lines. Highlighting the woven text would parse a file with a removed `fn a() {` beside an added `fn a(x) {` and colour everything below it wrongly.
  - Unchanged stretches (margin 3, minSize 4, the merge view's `collapseUnchanged`) are REAL FOLDS over a PLACEHOLDER line "⋯ N unchanged lines" that is the fold's header: a fold hides what comes after its header, and a stretch at the top of a file has no line above it. `Buffer::set_fixed_folds` makes those the only blocks that can fold (indentation folding is off in a diff); the gutter click, Enter on the placeholder and Cmd+Alt+[ / ] open and close them; the placeholder is drawn in the gutter's colour between two hairlines and is left out of a copy (`selected_for_copy`).
  - Painting (`editor_body.rs` calls `paint_diff_gutter`, `paint_diff_back`, `paint_diff_list_row`): the wash is the old one (theme `string` green, `operator` red, alpha 0.18), the gutter has two number columns (HEAD's, then the working tree's, blank where a line does not exist on that side), a `+`/`-` sign and the 3 px change bar; blame (Cmd+B, `editor.blame`) is a third column left of them, for the lines the working tree has. The status bar says the FILE's line number (HEAD's for a removed line), not the merged buffer's.
  - The file list is the editor's `Tree`, built `Tree::flat` over the changed files (no directories; `name` is the path in the repo), so the divider, the width, Cmd+K's three states, the focus and the keys are the editor's. `paint_tree` adds a heading row (`N changed +a -r`, `tree_head_rows`) and draws each row through `paint_diff_list_row` (the path drops parent folders, then `text::elide_start` cuts the name from the FRONT so the extension stays: the end of a file name tells files apart; counts at the right edge, red for a deleted file). It is never re-listed from the disk (`Tree::refresh` would list the repo): `diff_refresh` calls `set_flat`.
  - What a diff must NOT do is run the editor's file machinery, each guarded by `diff.is_some()`: `idle` goes to `diff_idle` (a poll of the shown file's mtime that reads the changes and the diff again, the old card's rule), `check_disk` (it would replace the merged text with the file), `refresh_git_head` (the git gutter against HEAD), `save` (it would write the removed lines into the source), the draft, `preview_from_tree`, and `EditorTabs::rebuild_tabs` (never called for a diff). `saved` is set to the merged text so the card is never "unsaved". Typing says "a diff is read-only"; Cmd+S says it too (`card.save`).
  - Keys: a diff card now LOCKS the editor's way. An arrowed-to diff takes no keys; a bare Enter or a click in the text locks it; Escape (with nothing else to close), Cmd+Escape or the `browser.leave` chord unlock. This replaces #505's "a diff card has no lock", under which bare arrows worked at once: opening `ift diff` on a folder now needs an Enter to enter the card and another to open the file under the list's cursor. Locked: every editor chord works (selection, word moves, Cmd+C, Cmd+F, Cmd+L, Cmd+D, find, fold keys, jump back/forward); the tab chords do not exist (`editor_keys::diff_lock_override`: Cmd+W closes the card, Cmd+S says read-only, Cmd+K and Cmd+B stay the list and blame commands, Cmd+T and Cmd+1..9 fall to the body, which ignores them). Between the list and the text: Right or Enter in the list opens the row and goes to the text (Right is Enter's twin only in a diff, `key_tree`); the file already on show is NOT reloaded, so the caret and scroll stay; Left at the FIRST COLUMN of a line, with nothing selected, goes to the list (`diff_left_to_list`; anywhere else Left is the caret's, which is why #505's bare Left could not survive unchanged); Cmd+Alt+Left/Right is the editor's `move_focus_within`; Cmd+K keeps its three states; Escape in the list gives the text the keys. A list ABOVE the diff (narrow card) uses Cmd+Alt+Up/Down for the same.
  - Binary files and pictures are what the old card did: `file_read` fails on bytes that are not UTF-8 (the working side reads as empty) and `git show` prints HEAD's lossily, so a changed binary shows as HEAD's text removed. Nothing in the diff mode shows a picture (`Language::is_image` is not asked); that is a follow-up, not a regression.
  - Gone with the old body: the line-cursor band (the editor's block caret and selection replace it; `highlight_line` gives the usual faint current-line wash), `infiniterm-editor/src/diff_cursor.rs`, `diff_rows`/`DiffRow` and `DiffBody` with its tests (their cases are `diff.rs`'s `merged` tests and `editor_body/diff.rs`'s). Right-clicking a diff body still opens the generic Frame menu (`card_area`); an editor-style menu with Copy is a follow-up.
- A frame is drawn at the size it was LAID OUT at, never stretched to the card (#479, 2026-10-19, Ekin: "resizing a browser card stretching the texture"): CEF hears a resize at once (`Surface::resize` every frame) but its repaint at the new size arrives a moment later, and until then the newest frame is the old size; painting it into the new bounds squashed the page. `Frame::css_width/css_height` (surface.rs) record the `view_rect` CEF last asked for when it painted, the tab keeps them with its texture (`Tab::texture_css`), and `frame_fit::frame_draw_size` gives the size to draw: layout size times the canvas zoom, within 1.5 px of the card's page area counts as filling it. A mismatch is drawn anchored top-left under a content mask of the page area, with the card's own background beside it. A canvas ZOOM is not a stretch: the layout size is unchanged, so the natural size follows the zoom and a settled card fills its bounds exactly. A background tab's texture can be old too: switching to it shows its last page at its own size until its repaint arrives. Not rate-limited: the new size already goes to CEF every frame of a drag.
- "Sometimes it works" was a RACE and a WEDGE (#479 follow-up, 2026-10-19, Ekin on the mini: "sometimes it works sometimes not, i think resize is not triggered or there is a race condition"; found with `[browser]` log lines under `INFINITERM_KEYLOG`: `view_rect asked`, `screen_info asked`, `resize`, `on_paint`, `ui takes frame`, `draws old size`, `kick`, and a scripted drag and `card.resize.*` bursts on the MacBook). After a quick burst CEF asks `view_rect` for the newest size and then delivers a frame it had already composited at an OLDER one (`on_paint 1500x800px tagged css 1550x800` in the log). Labelled with the newest ask, that frame looked current: it was stretched to fill the card, and CEF, believing it had painted the newest size, answered NO further `was_resized` (no `view_rect` ask followed the later steps, 3 paints in 140 resizes) so the page stayed stretched for good: before the fix 140 of 140 settled shots of a scripted run were stretched and 30 of 30 of a real mouse drag. Two changes. (1) A frame's layout size is what its own PIXELS prove (`frame_fit::frame_layout_size`: the (size, device scale) pair, among the last 8 `view_rect` and `screen_info` asks kept in `Shared::asked` and `asked_scales`, whose product is the pixel size, newest scale first; the pixels over the last scale when nothing fits), not the newest ask. (2) The card asks CEF to paint again when the newest frame is of another size than wanted and nothing more arrives (`frame_fit::needs_kick`: 150 ms quiet, at most one request per 400 ms, 5 per wanted size; `Surface::kick` tells the size and scale again and invalidates the view; `BrowserBody::paint` times it per tab in `Repaint`, and `wants_frame` keeps painting while a request is due so a still page does not stop the clock). `Surface::resize` also compares with what CEF was last TOLD (`Shared::sent`, set only when the browser host existed), so a size set before the host was there is not forgotten. After: 1 bad shot of 141 (a shot taken while a command backlog was still being resized, repaired by the next request) and 0 of 30 for the mouse drag. A window that is not in front draws no frames, so nothing of this can be exercised on a scratch instance in the background.
- The browser lays out at the card's world size and is painted as a texture; the device scale follows the zoom in half steps above 100%. CEF starts before gpui, pumps every 4 ms, and reads its profile and the extension from `<data>/browser/`, seeded from Chrome's install and, once, from the spike's signed-in profile. A card can hold several tabs (`Card.tabs`/`active_tab`, one CEF surface each via `BrowserBody`'s `Vec<Tab>`); a popup, a `target=_blank` link, a Cmd+click on a link or "Open link in new tab" opens a tab on the same card now, not a card of its own — "Open link in new card" still exists for that. Saved only when `tabs.len() > 1`, the `session`/`kittyKeys` convention. The first click on an unfocused browser card only focuses it.
- Focus lock (2026-09-19, docs/superpowers/specs/2026-09-19-browser-tabs-design.md): the next interaction past that focusing click — one that reaches the page, or a bare `Enter` on a card focused but not yet locked, the keyboard's way in for a card you arrow-focused — locks the keyboard to the card the way alt-tabbing into a real Chrome window would. `Model::handle_chord` (`register.rs`) checks `card.locked` before its own table and routes through `browser_keys::lock_override`, real Chrome bindings (`Cmd+T/W/Shift+T`, `Cmd+1..9`, `Cmd+Shift+]`/`Cmd+Shift+[` for next/prev tab — chosen over `Ctrl+Tab` because that one is Windows muscle memory, and `keymap.rs` had already reserved those two chords for `workspace.prev`/`.next` as a stand-in before real tabs existed) with `browser_override`'s always-on page list as the fallback; an unmatched chord falls through to the page (`None`), never gets swallowed. `is_locked_carveout` keeps `cmd+l` (omnibox) and `cmd+escape` (leave the page) app-side regardless, and `Ctrl+1..9` (workspace switching) is never in the lock table at all. Double-Escape, both presses inside `DOUBLE_ESCAPE_MS` (400 ms), unlocks. A locked card's focus ring is `chrome.warn`, the same colour `warn` exists for elsewhere, and the status bar carries a text indicator too (`overlays.rs::browser_lock_indicator`) — two places because the ring alone is easy to miss and the status bar alone is off to the side.
- The omnibox (Cmd+L, `omni/`) is not the palette: the palette fuzzy-matches a fixed list of commands, this takes free text and decides whether it is an address or a search. Ranking IS the section order, never a score: what you typed, suggestions, history, open cards, with the best history prefix lifted to a "best match" row so Enter goes where the inline completion says. On a browser card it opens holding that card's address and Enter navigates in place; anywhere else it makes a card, and the card it was opened on is never one of its own results. History is ours (`history.json`, frecency, written on the layout's debounce) rather than Chromium's, because reading the CEF profile's SQLite means a dependency and a lock fight with the browser that owns it; every navigation is seen in `browsers.rs`, which is why it is recorded there. Google's suggestions are off unless `browser.suggestions` is on and are fetched by a thread running `curl`, so a name lookup cannot hold a frame and no HTTP crate is in the tree. `ift omni <term>` prints the ranking from the running app.
