# Releases, updates, docs and licensing

What this covers: how a release is made and published (`make dist`, `make publish`, the update feed, the updater), the patch-only versioning rule, the changelog and what's-new sheet, the docs that ship inside the app, the welcome card, and the licence.

Read it before touching `tools/dist.sh`, `publish.sh`, `bump-cask.sh`, `infiniterm-core/src/update.rs`, `infiniterm-ui/src/updater.rs`, `changelog.rs`, `whats_new.rs`, `help_docs.rs`, `welcome.rs`, `licence.rs`, `site/`, or `CHANGELOG.md` rules.

Related: `browser-and-pages.md` (the Page card that shows the changelog and welcome text), `repo-map.md` (the site and tools layout), CLAUDE.md "Working here" (the CHANGELOG rule and who owns wording).

Moved here from CLAUDE.md on 2026-10-19 with the text unchanged.

- Releases are patch-only again: 0.5.3 carries remote instances (stages A and B). Editor and diff cards on remote files (stage C) are parked (Ekin, 2026-10-04: not needed on Linux yet); 0.6.0 is a number Ekin keeps for something bigger. The Linux packages come from `.github/workflows/linux.yml` on a published release; 0.5.3 is the first to attach them.
- Releases and updates (2026-09-23): `make dist` then `make publish` put a notarized, stapled DMG (first install) and zip (updates) on the main repo's releases (`ekinertac/infiniterm`, since #52: they lived on `ekinertac/infiniterm-releases` while the source was private; builds up to 0.4.0 poll that repo and accept downloads only from it, so `BRIDGE=1 make publish` also publishes there with its own zip, DMG and a `latest.json` pointing at them, `update.rs` `DOWNLOAD_PREFIXES` accepts both) with a `latest.json`, and `tools/check-update-feed.sh` replays the updater's checks against every feed it wrote (address, checksum, team signature, notarization, build); each release is tagged `v<version>` on both repos (semver since 2026-10-01, #19; `release-<build>` and `v<version>-<build>` before), so every publish needs a version bump in Cargo.toml (the PATCH number only since 0.5.0: 0.5.1, 0.5.2, ...) and `publish.sh` refuses a tag that exists; the private repo's history never goes there (notes are one line unless `NOTES=` says more). The updater is Tauri's shape without Tauri or Sparkle (Ekin declined Sparkle): `update.rs` is the pure half (manifest, newer is a higher BUILD number, `applies_to` only an app in an Applications folder, the swap script), `updater.rs` the thread (curl, `shasum`, `ditto`, then `codesign` against `TEAM_REQUIREMENT` and `spctl` for notarization instead of Tauri's minisign, so there is no update key to keep). It checks at launch and every hour (six before 0.5.14), stages under `<data>/update/`, and a staged update is installed by the next restart: the waiter `app.restart` already spawns moves the old bundle aside and the new one in after the process is gone, putting the old one back if the move fails. Commands `app.update.check` (also the app menu's Check for Updates…) and `app.update.install`; the status bar says "update N ready" until then. Never for a scratch instance or a bundle under `target/`.
- `help.changelog` (2026-10-09, `changelog.rs`) opens `CHANGELOG.md`, compiled in with `include_str!` and written to `<data>/changelog/Changelog.md` at every launch, as a Page card beside the focused one (`Model::open_page`, shared with the welcome card), minus the maintainers' note at the top of the file. The card itself stores nothing about versions. The first launch after an update shows the changelog in a MODAL SHEET instead (#402, `whats_new.rs`, 2026-10-15): `runtime.rs` writes `<data>/changelog/What's new.md` (`changelog::released_text`: the whole file without the Unreleased days) and compares the version in `<data>/last_version` with the running one (`version_newer`); older opens `Model::whats_new_open`, a missing file (first install, a scratch data dir), a remote instance or `ui.showWhatsNew` off only records the version. The sheet is a `PageBody` painted in a canvas element, owned by `AppView::whats_new_body` (built and dropped in `reconcile_whats_new`); Escape and the × close it, the scroll keys and the wheel scroll it, any other key, composed text or a click outside FLASHES it (`whats_new_flash_until`) and nothing else, per Ekin. `help.whatsNew` opens it any time.
- The docs live once (2026-09-30): the site's guide pages are compiled into the app (`help_docs.rs`, `include_str!` of `site/src/content/docs/guide/*.md`, front matter stripped, `<kbd>` back to text) with the reference pages rendered from the live tables by `site_reference.rs`, the same code `npm run reference` runs for the site. `help.docs` writes them to `<data>/docs` and opens that folder in an editor card. A test fails when the site gains a guide page the app does not ship. A new user's first card is the welcome Page (`welcome.rs`, `<data>/welcome/Start here.md`, keys from the live keymap, the agents found on this Mac); `help.welcome` brings it back. A first launch opens that card ALONE, centred at once (no glide) and framed, no terminal beside it (2026-10-04, #178): a terminal took the focus and the card went unread; the newcomer makes the first terminal with Cmd+T, which lands to its right, and comes back with Cmd+Alt+Left, the two steps the card's opening teaches (`seed_first_card`; `tools/drive/welcome.sh` checks it on screen). A later launch on an empty canvas still gets one terminal. A guide page or the welcome text that says a key must say the live one: the guide is hand-written, so a key change needs ift-publishing told.
- Licensing (2026-09-30): free for personal use, $29 per person one time for work, sold through Lemon Squeezy (store "infiniterm"). Honour system: nothing gates a feature on the key. `ift licence [<email> <key>]` (#106, 0.5.2) asks Lemon Squeezy whether the key and email match (`curl` with the key on stdin, so it is not in `ps`; exit 3 rejected, 4 unreachable; a release build refuses a test-mode key), keeps `licence.json` in the data dir (0600; `infiniterm-core/src/licence.rs` holds the acceptance rules), and About shows "Licensed to <name> (<email>)" when that file parses. With no arguments it prints the stored licence. The live checkout (Lemon Squeezy product 1407701, out of test mode 2026-10-03) is `BUY_URL` in `site/src/pages/index.astro` and the link on the install guide's licence line; the test-mode product (1407532) stays for trying the flow. Call it source-available, never open source (`LICENSE.txt`).
