# Editor card

What this covers: the editor's behaviour and the decisions behind it: the Sublime-style chords, multiple cursors, the git gutter, folding, completion (JSON Schema, words), editor tabs and the keyboard lock, the status bar, image files, and the painter safety rule.

Read it before touching `infiniterm-editor/src/`, `infiniterm-ui/src/editor_body.rs` (and its child `editor_body/diff.rs`, the diff card's mode), `editor_tabs.rs`, `editor_keys.rs`, `editors.rs`, or `infiniterm-core/src/complete.rs`, `jsonctx.rs`, `schema.rs`, `schema_store.rs`, `words.rs`.

Related: `browser-and-pages.md` (the browser card shares the lock and the tab strip), `cli-and-ift.md` (`ift <file>` edits in place over a terminal), `ui-chrome.md` (fields, dialogs, find), `traps-workflow.md` (driving an editor from a scenario).

- The editor follows Sublime's defaults (2026-09-24 to 10-06, the "Sublime tasks"; every chord below works only in a LOCKED editor, so none of them fights the canvas: a locked card falls through to the body for any chord `editor_keys` does not claim). Line commands (Cmd+Shift+D duplicate, Ctrl+Cmd+Up/Down swap, Ctrl+Shift+K delete, Cmd+Enter / Cmd+Shift+Enter add a line, Cmd+Shift+J join, Cmd+]/[ indent, Cmd+C/X with no selection take the line), Enter between `{}` opens the pair onto three lines, Ctrl+M / Ctrl+Shift+M jump to and select inside brackets, Cmd+L / Cmd+D select a line / word, Ctrl+G is `editor.goToLine` (a Model command, so it is in `editor_keys::lock_override`), and the palette-only text transforms (`EditorAction::Transform`, `transforms.rs`: case, sort, unique, reverse, trim, tabs and spaces). `is_locked_carveout` keeps Cmd+L for the omnibox on a locked BROWSER only. Typing a quote, backtick or opening bracket over a selection WRAPS it (`type_char`, #188). MULTIPLE CURSORS: `Buffer.extra` holds the cursors beyond the primary (empty almost always, so every single-cursor method is unchanged) and `Buffer::for_each_cursor` runs one of those methods at each cursor right to left, then shifts the already-recorded positions by each edit's length change (the first version drifted without that); typing, Enter, Backspace/Delete, Tab, and character, word, line and page movement go through it. Cmd+click adds or removes one, Ctrl+Shift+Up/Down grows a column, Cmd+D ADDS the next occurrence, Ctrl+Cmd+G takes every occurrence, Cmd+Shift+L splits a selection into lines, Escape drops to one cursor first. Left primary-only for now: the line commands, bracket jumps, clipboard, wrapped (visual) movement, and undo (one multi-cursor edit is several Cmd+Z steps). A plain click, go-to-line and a search jump reset to one cursor in the UI call sites, never inside `set_cursor`/`select_range`, which `for_each_cursor` itself calls. Git gutter: HEAD's text is fetched on load and on the disk poll (never per key) and diffed in memory (`gutter_marks`; a delete run followed by an insert run is Modified), drawn as a green, yellow or red bar in the pad before the separator. Ctrl+- / Ctrl+Shift+- jump back and forward (`Jumps`, read by the physical Minus key, positions not shifted by later edits). Folding is by indentation: `Buffer.folds` are char ranges shifted by `apply`, undo and redo like cursors, Cmd+Alt+[ / ] (Shift for all), a gutter click toggles, up/down skip hidden lines, a caret that lands inside one opens it. The text pass is clipped twice: to the text area (a long line scrolled right drew over the file tree, #197) and, inside it, to the gutter's right edge (numbers and git marks have their own pass, #200). The editor is ours: a rope with one primary cursor, undo grouped by CodeMirror's 500 ms rule, whole-text tree-sitter spans per buffer version, visual rows for wrapped prose (up/down move by visual row since 2026-09-20, `move_visual`), drafts half a second after a change, a two-second disk poll (which also re-lists the tree's shown directories, `Tree::refresh`, so a file made outside the app appears). JSON files use the JavaScript grammar because the config files are JSONC.
- LSP completion (`infiniterm-editor/src/lsp.rs`, `editor.lsp.enabled`, `editor.lsp.servers.<language>`, #238 and #602, 2026-11-06): a small JSON-RPC client over a server's stdio (`encode`/`read_message` frame, `Client` owns the child, a reader thread and a shared `Shared` state), full-text sync (`didOpen` once, then `didChange` with the whole text, `didClose` when `LspState` drops), and only `textDocument/completion` (no diagnostics, hover or go to definition). Messages sent before the server answers `initialize` wait in `Shared::queue` and go out after `initialized`; a request FROM the server (progress, configuration, registering a capability) is answered with null so it never waits on us. `client_for` keeps a `Weak<Client>` per (language, project root) in a static registry, so the server is lazy (first completion), shared by every tab of that language and project, and killed when the last `Arc` drops (`Drop for Client` sends shutdown and exit, kills, and waits on a thread). With the setting off nothing is created. The root is `project_root` (nearest folder with `.git`, `Cargo.toml`, `package.json`, `tsconfig.json`, `go.mod`, `pyproject.toml` or `setup.py`, else the file's folder), the program is found by `format::find_program`. The body side is `lsp_offer` (starts, syncs when `buffer.version` moved, asks for the caret's state once, `Waiting` while it is out so the popup stays as it was), `lsp_poll` from `idle` (takes the answer, re-runs `update_completion` if the caret has not moved) and `lsp_popup` (the typed word filters with `fuzzy_match`, the server's `sortText` order breaks ties, 50 at most, a snippet flattened by `flatten_snippet`, Enter does not accept, as for words). A missing or dead server sets `lsp_failed` for that buffer and says so once; the popup falls back to words. `lsp_hint` says once per language and session that an installed server could be turned on. Positions are UTF-16 (`utf16_col`). Not done: diagnostics, hover, signature help, go to definition, incremental sync, `textEdit` ranges (the typed word is replaced, not the server's range), `resolve` for docs, files on a host, and a status-bar badge for a starting server.
- Format on save (`infiniterm-editor/src/format.rs`, `editor.formatOnSave`, `editor.formatters.<language>`, #602, 2026-11-06): `EditorBody::save` calls `format_buffer` first (local files, not read-only, only when the setting is on), so what goes to disk is what the buffer shows; `editor.format` calls the same through `format_document` and reports in the status bar. The command is the language badge's entry in `Editor.formatters` (flat dotted keys `editor.formatters.rust`, read by `merge_config` from the flattened section), else `format::default_command` (Prettier with `--stdin-filepath {path}`, `rustfmt --edition 2021`, `gofmt`, `black -q -`). It is words split on whitespace, never a shell, `{path}` substituted. The program is found by `find_program`: the nearest `node_modules/.bin` going up from the file, then `PATH`, then `/opt/homebrew/bin`, `/usr/local/bin`, `~/.cargo/bin`, `~/.local/bin`, `~/.asdf/shims`, `~/.volta/bin`, because a Mac app started from Finder has a bare `PATH`. It runs in the file's folder, 8 s timeout (killed, text kept), stdin and both pipes drained on threads so a chatty formatter cannot deadlock. Empty output for non-empty text is a failure (a formatter that printed nothing must not empty the file). A failure never blocks the save: the notice reads "saved x, not formatted: why". The result is one `set_text`, so one undo, and the caret is put back on its line and column. asdf shims need a `.tool-versions` that applies to the file's folder, or they print "No version is set" and count as a failure. Not done: remote (host) files, range formatting, a format-on-paste, a per-project settings file.
- Find and replace (`search.rs`, #602, 2026-11-06): the whole matcher is the `regex` crate, a literal query is `regex::escape`d, so one engine decides case and word boundaries. Positions are char indices; byte offsets are walked once (`CharIndex`), and an empty match (`a*`) is never listed. Case is SMART by default (a capital in the query makes it exact) and `match_case` forces exact; there is no "force insensitive" switch. In a regex the letter after a backslash does not count as a capital (`\S`). `^`/`$` are per line. The replacement expands `$1`/`${name}` and `\n` `\t` `\\` only in regex mode, a literal search inserts it as typed. Replace all is `Buffer::replace_ranges`, ONE undo entry covering the first to the last match (the other line commands are still one edit per cursor); the caret lands at the end of the last replacement, which is what makes a single Replace step on to the next match. `Search.scope` is a char range set by opening find with a multi-line selection, or by the Sel toggle; the replace shifts its end by the length delta, nothing else keeps it in step with edits made elsewhere, and closing the panel drops it. The toggles are `EditorAction::FindToggle` (commands `editor.find.regex|matchCase|wholeWord|inSelection`, no default chords: the Cmd+Alt+R/S/L chords Sublime uses are taken by `group.rename` and the focus moves, and an Alt+letter in the panel types a composed character), plus buttons on the find row whose rects come from `find_toggle_rects` for both the paint and the click. A right-column width change must go through `find_right_w`, or the field and the buttons overlap. Palette transforms `Remove Blank Lines` and `Strip Line Numbers` (the latter only acts when every non-blank line has a number, so a list that starts with a year is left alone).
- Find and Replace in Files (`find_in_files.rs`, `infiniterm-editor/src/grep.rs`, #602, 2026-11-06): Cmd+Shift+F (`editor.findInFiles`, plus `.regex`, `editor.replaceInFiles` and `.regex` in the palette only) is a chain of the model's prompts, not a panel: `Pending::FindInFiles` keeps the typed text in `Model::files_job` and pushes `EditorAction::FindInFiles`; the UI lists the project (`project_files`, the same list and root rule as Go to File), reads each file through the card's `FileSource` (skipping binary, over `MAX_FILE_BYTES` and non-UTF-8 files, in both the search and the replace, so a replace never rewrites what it did not search), runs one compiled pattern (`search::build`, so smart case, regex and the replacement escapes are the find panel's) over each line (`grep::search_text`, capped at `MAX_HITS`), and `Model::open_grep` shows the hits as `Source::Grep` rows (`path:line  text`, id `path<GREP_SEP>line`, file order kept, narrowed with the loose matcher). A pick opens the file as a tab (`grep_pick`) and sets `card.line`; the reconcile in `editors.rs` gives that to the active body (`pending_line` for a host file still loading) and clears it. Replace asks find, then the replacement (`Prompt::ask_allowing_empty`: an empty answer deletes, everywhere else it is a cancel), then the UI counts matches and files and asks a yes/no with the numbers; only that yes writes (`FileSource::write` with the read's mtime, so a file changed since is refused and counted, never overwritten). There is no undo beyond git, no preview of each change, and no whole-word or exact-case switch for a project search (smart case only). It runs on the UI thread, so a huge tree stalls the window for the length of the search.
- Go to Symbol (`editor.goToSymbol`, `symbols.rs`, #602, 2026-11-06): `infiniterm_editor::symbols::symbols(lang, text)` parses with `Language::grammar()` (the highlighter's grammars, without its queries) and walks the tree with a per-language table of declaring node kinds (`kinds`), the name being the node's `name` field except for a Rust `impl` (`Trait for Type`), a C function (the declarator chain), a JS/TS `const f = () => {}` (only a variable holding a function counts), a markdown heading (its level in `#`s, and its depth is the level because the tree nests sections, not headings) and a TOML table. No table, no symbols: HTML, CSS, JSON, YAML, SQL, Svelte. `EditorBody::symbol_rows` feeds `Model::open_symbols`, `Source::Symbols` lists them in file order (`keeps_its_order`, matched loosely, indented by depth, the kind as the hint) and a pick is `card.line` plus `EditorAction::GoToLine`, the existing path. The chord is Cmd+R only in a LOCKED editor, through `editor_keys::lock_override` like Ctrl+G (Cmd+R stays the terminal's redraw and the browser's reload everywhere else), and there is no keymap entry, so `keybindings.json` cannot rebind it; the palette command can be bound. Not done: symbols in a diff card, workspace symbols, a recent-symbols section.
- Go to File (`editor.goToFile`, Cmd+P, #602, 2026-11-06): `Source::Files` over `Model::quick_open` (card id, root, relative paths). The command pushes `EditorAction::GoToFile`; the UI (`editors.rs`) picks the root (the tree's root, else the open file's folder, else the card's cwd; on this machine then the git toplevel, `quick_files::repo_root`, because a card's cwd can be `$HOME`, where a capped walk fills up on shallow junk and never reaches the project), lists it (`git ls-files -z --cached --others --exclude-standard` locally, else `quick_files::walk`, breadth first, capped at 20 000 local and 3 000 through a host source, skipping `.git`, `node_modules`, `target` and a few others) and calls `open_quick_files`. A pick is `quick_open_pick`: the tab already showing the path, else a new one (`browser_tab_open`). The palette ranks Files rows with `rank_loose` (`fuzzy_match`), not `rank`: `strict_match` refuses letters scattered over a word, which is right for commands and wrong for `edbody`. A locked editor lets the chord through the way it does the palette's (`resolve_chord`, `opens_files`, any chord the keymap binds to the command). Off the Mac the chord is "palette only" (`platform_keys::CMD_CTRL_LAYER` holds an explicit `cmd+p`, and the twin rule ignores explicit chords, so Cmd+Shift+P stays Ctrl+Shift+P); inside a locked editor plain Ctrl+P works through the generic Ctrl-is-Cmd rule. A user's own keybindings.json that binds `cmd+p` (the author's does, to the palette) wins over the default. Not done: file names ranked above directory names, remote hosts beyond the capped walk, a recent-files section.
- Toggle Comment (`editor.toggleComment`, Cmd+/, #697, 2026-11-09): a registered command now, so the palette lists it and keybindings.json can rebind it; it was the body's own `"/"` key, in `editor_keys::KEPT`. Cmd+/ reaches it through `editor_keys::lock_override` (locked editor only; on the canvas Cmd+/ stays `app.shortcuts`, so it cannot be a second `DEFAULT_KEYMAP` entry on the same chord, and keybindings.json is an object keyed by chord). A chord the user binds to it gets through the lock the way Go to File's does (`resolve_chord`, `comments`). The palette, opened from a locked editor, shows the lock table's chords beside the editor's commands (`palette_items`), so Cmd+/ appears beside it (and Cmd+R beside Go to Symbol). `Buffer::toggle_comment(CommentStyle, now)` runs for every cursor in one undo group (`for_each_cursor`): one comment-or-uncomment decision for all of them, overlapping spans merged into one block with one indent, and a line two selections share toggled once (line numbers never change, so a `done` set holds them). `CommentStyle::Pair` is for languages with no line comment (CSS `/* */`, HTML, Svelte, Markdown `<!-- -->`): each line wrapped on its own, VS Code's behaviour, and a line counts as commented only if it starts with the opener and ends with the closer. A locked diff ignores Cmd+/ (read-only). Not done: a block comment (one pair around the selection), a language-aware comment inside an embedded language (CSS in a `<style>` tag gets `<!-- -->`).
- Review of a file changed on disk (`EditorBody::agent_base`, `diff::{hunks, hunk_at, revert_hunk}`, `ChangeAct`, #602, 2026-11-06): `apply_disk_text` on a CLEAN buffer keeps the text it had as `agent_base` (the first change since the last accept, so two in a row review as one; a diff card and an empty buffer never set it), and while it is set `gutter_for` diffs against it instead of HEAD, so the existing gutter colours mean "changed since the file changed on disk"; an unchanged result drops it. `hunks(base, current)` is the `similar` ops that are not Equal, each with its current line range (empty for a pure deletion, which belongs to the line after it) and the baseline's lines with their newlines, so `revert_hunk` is exact even without a final newline. The five commands (`editor.change.revert|revertAll|accept|next|prev`, palette only, no chords) go through `EditorAction::Change`; a revert is one `set_text` (one undo, caret kept on its line and column) and leaves the buffer different from the disk, so saving writes the reverted text. A dirty buffer keeps its own path (the "changed on disk" notice, `warned_stale`), and `load` resets the baseline. Marks are not drawn in the diff card, a host's file goes through the same `apply_disk_text`, and nothing clears the baseline but accept, revert all, a revert that leaves no hunk and loading another file.
- Grapheme clusters and indent rules (`buffer.rs`, #602, 2026-11-06): the caret, Backspace and Delete move by `unicode-segmentation` grapheme clusters, found in a window of `GRAPHEME_WINDOW` (64) chars either side of the position (`boundaries_near`), never the whole line, because a line can be a megabyte; `place` snaps any index to a boundary (`snap_to_boundary`), which also keeps a click or a vertical move out of the middle of an emoji, and a CRLF is one cluster, which fixes a caret between CR and LF. Word moves, selection by double click, `col_of` and everything else still count chars. KNOWN GAP: the painter places text by one cell per char, so a joined emoji drawn as one glyph leaves a selection highlight wider than the glyph; the buffer is right and the picture is not. `newline` indents one `INDENT` deeper after `{`, `(` or `[` (left of the caret, spaces skipped; not for a selection), and `type_char` on `}`, `)` or `]` takes one level off an indent-only line first (`dedent_before_closer`; one tab or one `INDENT`; not when stepping over an existing closer). Both are separate undo steps from the typed character. Not done: Python and YAML `:` indents, electric dedent for `else`/`case`, bracket matching that skips strings and comments.

- Editor completion (2026-10-05, #213, #215): a `Provider` (`infiniterm-core/src/complete.rs`) answers for the whole text and a caret and returns an `Offer` (`typed` chars to replace, items with a label, the text to `insert`, a detail, a doc, and `enter_accepts`); `editor_body.rs` asks after a key that changed the text (or while the popup is open, so an arrow narrows or closes it) and draws the popup under the caret (`paint_completion`, `painted_caret`). No LSP, by decision for now (#238 holds the plan: a JSON-RPC client over stdio, a server per language and root, `didChange` from the rope). The provider is JSON Schema: `jsonctx.rs` is a tolerant JSONC scanner (the text is invalid whenever a key is half typed) that gives the key path at the caret, key or value, and the typed prefix; `schema.rs` reads `properties`, `additionalProperties`, `items`, `enum`, `const`, `default`, `type`, `$ref` inside the document and merged `allOf`/`anyOf`/`oneOf`; `schema_store.rs` finds `"$schema"` near the top (a path beside the file, or `https://` only, fetched once by `curl` on a thread and cached in `<data>/schemas/`, refreshed after a week; the popup waits for the next key after the download). `settings.json` needs no `$schema`: its schema is built from `SETTINGS_DOC` and the default config, with `SETTING_CHOICES` giving the few settings that take fixed words an `enum` (a test checks each against the defaults), so keys AND values complete. The file is matched by real path: the app is handed `/private/tmp/...` for `/tmp/...`. Not yet: YAML (`# yaml-language-server: $schema=`) and TOML (`#:schema`) modelines, hover, diagnostics. Words (#239, merged 2026-10-11, after #247): `words.rs` offers words from the file (outside comments and strings via the tree-sitter spans) and the card's other tabs, nearest first, from two letters, `editor.completeWords` turns it off, Enter takes a row only after Up or Down.
- Tabs between cards (#265, 2026-11-06): `editor.tab.moveToCard`, `editor.card.moveIntoCard` and `editor.openFileInCard` open a palette picker of the workspace's other editor cards (`Source::MoveTab`, `MoveCardInto`, `OpenInCard`; rows from `Model::editor_card_rows`). The move is MODEL-ONLY: a handle leaves one card's `tabs` and joins the other's (`move_tab_to_card`, `move_card_into_card`), and the target's `EditorTabs` builds a body from the file as it does for any new handle. That is why a dirty tab is refused ("save b.rs first"): its unsaved text lives in the source body, which is dropped. `card.dirty` mirrors only the ACTIVE tab, so the check is that one tab, the same limit Cmd+W has. A file the target already has open is switched to, never doubled. The open-in variant is `Effect::PickFile { into }`: the open panel's pick goes to `open_file_tab`. Not built: terminal tabs.
- Editor tabs (2026-09-21): an editor card's body is `EditorTabs` (`editor_tabs.rs`), a strip (`tab_strip.rs`, shared with the browser card since 675e5cb; sized from `terminal.fontSize`) over one `EditorBody` per tab. `Card.tabs`/`active_tab`/`closed_tabs`/`locked` are the browser's fields with paths for handles ("" is untitled); `tabs_cmd.rs` is kind-aware, `editor.tab.*` stand beside `browser.tab.*`, and `editor_keys::lock_override` puts the same chords on them. Enter on a file in the tree ALWAYS opens a tab (`EditorEvent::OpenTab`; the tab already showing it is switched to), the tree travels with the active tab (`take_tree`/`put_tree`), bodies are matched to handles in order so a close never reloads the rest, drafts are keyed per tab (the first keeps the card's id). Lock: a click into the text, or a bare Enter, and nothing else (2026-09-24, Ekin: "too much freedom breaks the UI"); an editor you are not in takes NO keys and no composed text at all, every key is swallowed (`EditorTabs::key`), so nothing typed at the canvas can reach a file. It was every plain key for two days, which locked and swallowed the key; the strip, the tree and the find bar do not lock; Escape unlocks an EDITOR when it has nothing else to do (2026-10-06, #265: a popup, the find panel, extra cursors or a selection take the Escape first and the card stays locked; `EditorBody::escape_has_work`, decided in `input.rs`), a browser still takes a double-Escape because a page uses a single one; the chord you can REBIND is `browser.leave` (Cmd+Escape by default, "Card: leave the page or the editor": it unlocks a locked editor through `EditorAction::Unlock`, and `resolve_chord` lets whatever the keymap binds to it through a locked card, where the other carve-outs are fixed chords; keybindings.json takes only cmd chords or ctrl+digit, so a bare Escape cannot be rebound); ring and status bar as the browser's. Cmd+S is in the editor's lock table as `card.save` (2026-09-22), because an unmatched chord falls through to a body that has no save of its own and the file could not be saved without dropping the lock. No corner label on editor cards either. Every tab gets `idle()` (disk poll, draft timer) through `EditorTabs::idle`; the idle loop downcasts to the WRAPPER, which a downcast to `EditorBody` missed for a day.
- `editor_body::fit_runs` makes a row's `TextRun` lengths sum to its text and land on char boundaries before gpui sees them: gpui slices the line by those lengths and ABORTS the process on a mismatch, which Page Down in an editor once did. A painter must not be able to kill the app.
- An editor card whose file is a picture (`Language::is_image`) draws it through gpui's asset cache, fitted and never past its pixels at the zoom, with an empty read-only buffer so Cmd+S cannot write text over it; the tree shows a picture as the cursor LANDS on it (`TreeAction::Landed`) so a folder of screenshots is walked with the arrows, while text still waits for Enter. The lightbox idea is parked. Closing a card returns to the card focused before it (`Model::focus_trail`, session-only) and pans there; the split partner that took the space still wins, geometry is the fallback after a restart.
- Read-only DIFF mode and the decoration layer (2026-10-20): a diff card's body is an `EditorBody` with `diff: Some(..)` inside an `EditorTabs` that draws no strip (`EditorTabs::new_diff`); the decisions are written in `browser-and-pages.md` (the diff card), the parts that belong to the editor are these. The buffer holds text that is NOT a file (HEAD and the working tree woven together, `infiniterm-editor/src/diff.rs::merged`), so anything that treats `path` as the buffer's source is wrong in this mode and is guarded by `diff.is_some()`: the disk poll, the draft, the git gutter, `save`, a tree preview, `rebuild_tabs`. A new feature of the editor that reads or writes the file must ask `is_diff()` the same way. The per-line decoration is `diff.lines: Vec<DiffLine>` indexed by BUFFER line (kind, HEAD's number, the file's number), read by three painters in `editor_body/diff.rs`: `paint_diff_back` (the wash, or the hairlines of a placeholder, before the text and the selection), `paint_diff_gutter` (two number columns, the sign, the change bar, blame; it replaces the git marks) and `paint_diff_list_row` (the changed-files list through `Tree::flat`). `gutter_w()` answers for the diff's gutter (blame, two columns, sign, the usual padding) and everything that measures columns or maps a click uses it, so a wider gutter needs no other change. Syntax spans for a diff come from `merged_spans`, not from parsing the buffer (`spans_for`). Folds: `Buffer::set_fixed_folds` replaces the indentation rule with explicit blocks (the placeholder lines' stretches); `fold_range_at`, `enclosing_fold_line` and `fold_all` obey it, `set_text` forgets it. A diff buffer is never edited, so its folds are not shifted; if one ever is, `fixed_folds` needs `shift_folds` too.
