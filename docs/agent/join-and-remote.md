# Remote instances and the join host side

What this covers: `ift connect` (a second app whose cards run on another machine, over ssh) and the host side of `ift join` (the running app as the hub for viewers on other Macs: the relay, the join socket and its protocol).

Read it before touching `infiniterm-core/src/backend/remote.rs`, `relay.rs`, `join.rs`, `infiniterm-cli/src/connect.rs`, `proxy.rs`, `install.rs`, `remote_identity.rs`, or the Linux server package workflow.

Related: `join-viewer.md` (the viewer window, how its edits reach the host, connection loss, host settings), `join-serve-and-login.md` (`ift serve`, a host with no app, the login step), `daemon-and-backends.md` (`DaemonBackend`, the session protocol), `traps-code.md` (socket and splice traps).

- Remote instances (2026-10-04, #118; stage A of three): `ift connect user@host` opens a SECOND app (`open -n`, its own Dock tile) whose terminal cards run on that host. Not a viewer of another canvas: the instance has its own, saved per host under `~/.infiniterm/remotes/<host>/` (`$INFINITERM_DATA_DIR/remotes/` for a scratch run) with its own `config/` (EMPTY, so default settings: nothing is copied from the personal ones, 2026-10-05). The folder is SHORT on purpose: its `infiniterm.sock` must fit the 103 bytes of a unix socket path, and the usual data directory already takes 70 (the first real connect to a server failed on a 106-byte path, so the instance ran but `ift` and the hooks could not reach it); a long host name is cut and hashed (`folder_name`) and `ift connect` refuses a path that still does not fit, and the host runs only `iftd` and `ift`. The seam is `DaemonBackend::new_remote` (`backend/remote.rs`): `spawn_now` and `adopt` go over ssh as `ssh -T host ift proxy session <id> [--spawn ...]` (`infiniterm-cli/src/proxy.rs`, which copies stdin and stdout to the session's socket), the child's stdio spliced to a socketpair so the existing pane code (Hello, Replay, Resize, Kill, credit) runs unchanged; the live sessions are `ssh host ift sessions`; the pane has NO local pid (the inspect poller would match a process on this Mac). `INFINITERM_REMOTE` (and `_NAME`, `_COLOR`, `_ARGS`, `_IFT`, `_SSH`) put the app in the mode; it wins over `terminal.backend`. `remote_identity.rs`: the name and the colour, hashed from the host so it is the same every time (`window.color`, `model/color_cmd.rs`, changes it in two steps, named colours previewed live then a hex prompt; saved as `remote.json` in the instance's folder by the ui, which wins over `--color` and the hash; the LOCAL instance has the same command with the setting `ui.windowColor`, empty for none, and no host chip); the title bar leans toward it with a chip, the window title names the host, the Dock tile is the icon with a badge (`instance_icon.rs`, `setApplicationIconImage` per process), and the model refuses browser cards (`browser_refused`). ssh runs in BatchMode with keepalives; the remote command is shell-quoted (`drop::shell_quote`); a host that starts with a dash is refused. `ift connect <host> --install` (`infiniterm-cli/src/install.rs`, 2026-10-04, #159) sends this version's `infiniterm-server-v<version>-linux-<arch>.tar.gz` (from the GitHub release, checksum checked on THIS Mac before anything is sent, or `--from <file>`; `INFINITERM_RELEASE_BASE` redirects the download for tests) through ssh into `tar` on the host: `/usr/local/bin` for root, `~/.local/bin` otherwise, connecting by the full path afterwards, `--no-same-owner` because as root `tar` otherwise keeps the packer's uid; a Mac host uses the app already there; the host's `ift --version` is compared to this one and a difference is a line, not a refusal. Stage B (2026-10-04, #165): hooks and `ift` on the server reach the instance through one `ssh -R /tmp/infiniterm.sock:<instance socket>` kept up by `remote::forward` (its remote command is `cat` on a pipe we hold, so it ends with the app; sshd's own `StreamLocalBindUnlink` is off, so the stale file is removed over ssh first); the server needs `ift install-claude-hooks` once. Not built: editor and diff cards on remote files (stage C, parked), Windows hosts (no `iftd` there). The Linux packages come from `.github/workflows/linux.yml`, attached to a published release. Tests use a stand-in `ssh` script that runs its last argument locally against a separate "server" data dir (`infiniterm-cli/tests/common`).

- Join, the host side (#423, stage 1; `ift join <host>` itself is stage 2): the running app is the hub for viewers on other Macs, because `iftd` serves one client per card and a second client would displace the host's own window. `DaemonBackend` is the one client `iftd` sees, so `run_reader` taps every session's bytes into a `Relay` (`backend/relay.rs`: a replay ring per session, fed by the daemon's own Replay frames, and a bounded queue per viewer that DROPS a viewer that stops reading instead of waiting for it, since there is no ack frame to hold the host's pty reads back with), a host resize reaches viewers as a `Resize` frame and the hello carries the host's columns and rows. `backend/join.rs` serves `<data>/j.sock` (0600, `check_socket_path` first) behind one line, `ift-join <major> canvas|session <id>`, answered `ift-join <major> ok` or `ift-join <major> error <sentence>`: the version lives there so `session_protocol` (which old `iftd`s speak) is untouched, a higher major is refused with a sentence and a lower one served. Topic `session` is the same `Frame` wire the app reads from `iftd`; a viewer's `Data` goes to the session through `DaemonBackend::session_writer` (a cloneable, thread-safe writer: one connection to `iftd`, whole frames serialised by the pane's stream lock, never through the 16 ms poll), its `Resize`, `Kill` and anything else are ignored there, because a viewer's control (a close, a new card, a resize of a card) goes up on the `canvas` topic and the host carries it out through its own paths. Topic `canvas` carries messages of a 4-byte length, a kind byte and text: `L` the layout (exactly `Model::save_text`, published from `AppView::write_layout`, viewport and focus included for the viewer to ignore) always followed by `V` its revision (`Model::layout_rev`, decimal), `A` the agent states (`Model::agent_states_text`), which the layout leaves out on purpose, and, from a viewer up to the host (protocol major 2), `U` an edit: `{base, layout}`. `ift proxy join canvas|session <id>` carries the socket over ssh stdio like `ift proxy session`. The setting is `join.enabled` (default on: `<data>/infiniterm.sock` is already an owner-only socket that `ift send` can type into any card with, so this adds no trust level, and it is the off switch that socket lacks).
