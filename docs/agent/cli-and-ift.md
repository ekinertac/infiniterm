# The ift command line and file drops

What this covers: what `ift` verbs do and how they behave: `ift <file>` editing in place over a terminal card, `ift send` / `read` / `close` / `run`, the output of `ift ls`, `ift sessions`, `ift commands` and `ift completion`, and what a file dropped from the Finder does.

Read it before touching `infiniterm-cli/src/main.rs`, `ift.rs`, `completion.rs`, `infiniterm-core/src/model/ift_in.rs`, `model/cover.rs`, `drop.rs`, `save_as.rs`, or the hook installers.

Related: `editor.md` (the editor card that covers a terminal), `daemon-and-backends.md` (`ift attach`, `ift sessions`), `join-and-remote.md` (`ift connect`, `ift proxy`), `traps-workflow.md` (`ift send` text and Claude Code's paste).

- `ift <file>` run INSIDE a terminal card edits in place, the way `vim` would (2026-09-26, `model/cover.rs`): the app's `edit` verb opens the file in an editor card laid exactly over that terminal, born locked (`EditorTabs::locked` starts from `card.locked` in `reconcile_editors`, since the lock is otherwise the body's), and answers the request only when that card closes (`Model::edit_waiters`, `Effect::CliReply`, `reply_deferred` tells the ui not to answer now), so `ift` blocks like vim and `EDITOR=ift` works for `git commit`; `CliState::dispatch` waits with no timeout for `edit` alone, and the client reads with none. The cover is an ordinary editor card (lock, Cmd+S, the unsaved guard, drafts all its own); the pairing is session-only (`Model::covers`), a cover is never saved (a relaunch ends the waiting connection) and the save writes the terminal as focused instead; the covered terminal is out of `here()` so navigation, tidy and fit-all see one card; the drag's overlap checks let the pair share a rect (`paired`); `sync_covers` in `tick` moves whichever of the two did not move; closing a cover is `:wq`, no reopen ring, no undo step, focus back to the terminal. `ift -n <file>` is the old behaviour, a card of its own, returning at once; a directory, or `edit` from outside a terminal card, opens a card as before. A path that does not exist is a NEW file, vim's way: any argument that is not one of ift's verbs is a path (a typo'd verb opens an empty editor, chosen over a "has a dot or a slash" rule because that would be one more hidden thing), `ift` refuses a missing directory up front (`resolve` in the cli; vim finds out at the first write), and `EditorBody::load` opens a missing file empty with a "new file" notice so the first save creates it and a close without one leaves nothing. An untitled buffer's first save (`open_save_as`, `save_as.rs`) opens the save-as field on the card's directory and `untitled.txt` with only the stem selected (`Prompt::select`, `Field::open_selecting`), the macOS panel's shape in our own dialog; a missing directory returns to the field with the text kept, an existing file asks "Replace" first, and the close sheet's Save on an untitled buffer runs this and then closes.
- A file dropped from the Finder does what the thing under the pointer IS (`drop.rs`): a terminal gets the shell-escaped path as a paste, because a terminal is a terminal and the drop has to work mid-command; a browser goes to the file; everything else opens a card through `open_plan`, the same decision `ift <path>` reaches by typing. `shell_quote` is the whole security story: a file called `; rm -rf ~` reaches the prompt as text.
- `ift send <card> <text|--key K> [--enter]`, `ift read <card>`, `ift close <card>` and `ift run <cmd>` drive cards from a script (`ift.rs` parses, `model/ift_in.rs` runs, `Grid::text` is what read returns); `ift ls --agents` adds the agent column. Cards are named by number or id (`parse_card_ref`).
- `ift ls` and `ift sessions` print a padded table with a header on a terminal and tab-separated rows without one into a pipe (`is_terminal`), so `cut -f1` keeps working; on a terminal `ift sessions` is two columns, the card number and the label (else the directory), because the full table did not fit a phone over ssh (Termius), and `--full` is every column; a pipe always gets every column. `ift commands` lists every registered command as id, label, key from the running app (the palette's list as text; `keybindings.default.json` has only the bound ones). `ift completion zsh` prints `_ift` (completion.rs, held to `SUBCOMMANDS` by a test) and `ift install` writes it to `~/.local/share/zsh/site-functions/_ift`, naming the fpath line when that directory is not on `$FPATH`; `ift omni` is sections, not columns, and stays as it is. `ift sessions` reads the save file for the card number and label per session, and `ift attach 7` resolves a number to the session that card holds now.
