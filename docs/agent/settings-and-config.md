# Settings, config and look

What this covers: how settings.json and keybindings.json are read, validated and written, flat dotted keys, the look settings (window, card, background), settings for people coming from other terminals, the data and config folders of a scratch instance, snippets, and the default theme.

Read it before touching `infiniterm-core/src/config.rs`, `settings_doc.rs`, `config_write` and `patch_json_text`, `keymap.rs`, `themes.rs`, `snippets`, `paths.rs`, or adding any setting.

Related: `editor.md` (the settings.json schema for completion), `ui-chrome.md`, `canvas-and-layout.md` (`cards.*`), `traps-code.md` (keybindings `when`, atomic writes through a symlink, settings that are parsed and never read).

Moved here from CLAUDE.md on 2026-10-19 with the text unchanged.

- settings.json is VALIDATED before it applies (2026-10-06, #246, Ekin: "if it has errors we shouldn't accept it"): `validate_settings` rejects a file that is not an object or holds text, a number or a boolean where the default is another of those, nothing stricter (a valid file must never be refused: lists, unknown names and out-of-range numbers pass), the settings in force stay, a notice and a status bar segment say so, and keybindings.json keeps its bindings the same way. The editor's completion popup (#247) opens only after a word character or a quote and Enter takes a row only after Up or Down chose it. Before, A settings.json that stops parsing keeps the settings in force (2026-10-06, #246): it used to fall back to `default_config()`, and a double comma from `patch_json_text` (it added a comma after a last entry that already had one, `0.9,,`) made the whole app look as if it had lost Ekin's font, background and window colour. `insert_key` now puts the comma right after the last token, before a comment, and none when one is there.
- Settings: defaults and overrides are separate files, the defaults rewritten at launch; a new setting needs a `settings_doc.rs` entry and a `settings_schema.rs` row or the tests fail. Writes to the user file patch the text, never reserialise. Keys are FLAT and dotted (`"terminal.fontSize": 16`, VS Code's shape) since 2026-09-18, because extending a nested value meant copying the nesting; `config::flatten` reads the old nested shape too, a setting spelled both ways takes the flat one, and nothing writes the nested shape any more (`patch_json_text` replaces a value where it finds it, flat or nested, and inserts a missing one flat).
- Look settings (2026-10-03/04; since 2026-10-21 the look ones are keys of a ui theme, see the next bullet, only `fitPadding`, `fitMagnify`, `fitSplitSlot` and `workspaceIsolation` of this list stayed in settings.json): `ui.showGrid`, `ui.windowOpacity` + `ui.windowBlur`, `ui.cardOpacity` (a gpui global `CardOpacity`, `chrome::card_ground`; a background image is painted opaque because gpui's `paint_image` has no alpha), `ui.backgroundImage` (a string or a list that rotates, #210) + `ui.backgroundImageFit` + `ui.backgroundImageInterval` / `ui.backgroundImageFade` (`background.rs` holds the pure `Slideshow` clock, `background_show.rs` the loading and the layers; dusk, aurora and ember ship in `assets/backgrounds`, copied by `bundle.sh`), `ui.fitPadding` / `ui.fitMagnify` (Cmd+1's margin and the cap on magnifying a small card; `viewport::fit_rect_with`) / `ui.fitSplitSlot` (default on: Cmd+1 on a split piece frames the whole slot; off fits the card alone, `Model::slot_bounds`), `ui.workspaceIsolation` (the card switcher and navigation stay in one workspace), `ui.windowColor`. `ui.maximised` is gone. About is the confirm dialog with `Prompt::about`. `make run-clean` runs on empty settings.
- UI themes (2026-10-21, #511, Ekin: `theme.json` of #427 clashed with the terminal `theme` and could not hold several looks). The look lives in `ui-themes/<name>.json` in the config folder, one file per look; `ui.theme` in settings.json picks the file (default `default`). Files: `ui_theme.rs` (the key table `LOOK_KEYS`, `parse`, `strip_look`, names), `look_migration.rs` (the startup move), `config_files.rs` (`ui_themes_dir`, `ui_theme_read/write`, `list_ui_themes`, `migrate_look_keys`, the watcher `poll_ui_themes`), `settings_doc.rs` (`default_ui_theme_text`, the reference that also seeds `default.json`), `model/settings_in.rs`. Rules:
  - The look keys are the 16 that left settings.json (`ui.windowOpacity`, `windowBlur`, `windowColor`, `backgroundImage`, `backgroundImageInterval`, `backgroundImageFade`, `backgroundImageFit`, `cardRadius`, `cardOpacity`, `showGrid`, `inactiveDim`, `unfocusedDim`, `fontFamily`, `fontSize`, `fontWeight`, `fontWeightBold`), the new `ui.hideLabelWhenFitted`, and the four bar keys (`titlebar.*`, `statusbar.*`). They keep their `ui.` names inside the theme, so moving one is moving a line. Everything else (`panStep`, `animations`, the fit keys, label sizes, `hideLabelWhenMaximised`, `fullscreen`...) stays in settings.json. A new look key is a row in `LOOK_KEYS`, a line in `Ui::take_look_from`, a `SETTINGS_DOC` entry; a test holds the three together.
  - `ui.icon` (2026-10-31, `default` or `filled`) is the 18th look key and the first one with a fixed word list: `ui_theme::Kind::Choice(&[..])` rejects any other value with `"ui.icon" must be "default" or "filled"` (the other look keys clamp or fall back; `merge_config` still falls back to `default` for a value that gets past, such as a host's old file). `app_icon.rs` holds the two names and `source()`, the pure choice of picture: `default` clears the override (the bundle's own `AppIcon.icns`), `filled` reads `Resources/icons/filled.png` and falls back to the copy compiled into the binary when the file is missing (a scratch or dev bundle). `Model::sync_app_icon` pushes `Effect::AppIcon` only when the choice changes, from `apply_ui_theme_text`, so hot reload and the picker both move the Dock. `instance_icon.rs` keeps the base picture and the badge colour apart and redraws from both, so the badge of a remote, joined or coloured window sits on whichever base is in force. Only the Dock tile follows: the Finder, Launchpad and the bundle icon are a file of the app and cannot change while it runs. `assets/icons/{default,filled}.png` are the 1024 px sources; `tools/make-icns.sh assets/icons/default.png` rebuilds `assets/AppIcon.icns`, and `assets/icon.png` (About card, README, Linux tarball) is the default picture at 512 px. `site/public/icon.png`, the favicon and the touch icon are the site's own copies and were not changed. `INFINITERM_KEYLOG` prints the size of the image set (`[infiniterm/icon]`), which checks a scratch run without a screenshot of the Dock.
  - The fields stay in `config::Ui` so no reader changed. `Model::apply_ui_theme_text` runs the theme's look keys through `merge_config` (same clamps as before), keeps the result in `look_ui` and lays it over `config.ui` (`take_look_from`); `apply_settings_text` does the same after building a fresh `config.ui`, so neither file's change loses the other's. settings.json never sets a look field: `strip_look` drops the keys (flat and nested) before the merge, with a notice, never an error (a valid file must not be refused, and a host older than this build sends them to a viewer).
  - `ui.theme` loads a file only when it CHANGES (`note_ui_theme_setting`), so a picker preview is not undone by an unrelated settings edit. A name with no file keeps the look you had and warns; `default` needs no file (the built-in look). A theme with a mistake is not applied, the last good look stays (the #246 rule). A key that is in `SETTINGS_DOC` but not a theme key (`ui.hideBuildNumber`, `ui.hideLabelWhenMaximised`) gets "is a settings.json key, not a theme key: move it to settings.json" instead of "unknown key" (#598); the status bar marker for a rejected theme is not built. A name must be one plain file name (`ui_theme::valid_name`), because `ui.theme` is typed by hand.
  - Startup order: `migrate_look_keys` (before settings.json is read) cuts the look keys out of settings.json with `jsonc::remove_key` (text only, comments kept, a note after the opening brace says where they went) and patches them into `ui-themes/default.json` (seeded from `default_ui_theme_text` when missing); a key the theme already sets is not overwritten. There is no marker: once settings.json holds no look key it finds nothing. It runs in the app and in `ift serve`, never in a joined viewer. A file that does not parse is left alone.
  - The watcher polls every file in `ui-themes/` (a change arrives as `ConfigFile::UiTheme` with the name); the model applies only the one in force (`ui_theme_file_changed`). The window colour palette writes `ui.windowColor` into the theme in force (`Effect::SaveLook`), not settings.json.
  - Per client: a joined viewer keeps its own look. Host settings go through `apply_host_settings_text` (everything but `ui.theme`), the viewer's `ui.theme` comes from its own settings.json (`ui_theme_name_in`, and `SaveSetting` for `ui.theme` is the one setting a viewer may write), and its own ui theme files are read and watched. The host never publishes a ui theme.
  - Picker: `uitheme.pick` ("UI theme: switch…") is `Source::UiThemes`, built like `Source::Themes` (active first under its hint, order kept, no dim sheet, preview is `Effect::LoadUiTheme`, cancel puts `ui_theme_before_preview` back, Enter saves `ui.theme`). Not decided by Ekin and kept plain: no next/previous chords, no "open the folder" row, no bundled looks besides `default`.
  - `ui.hideLabelWhenFitted` (a look key) hides the chips of the card Cmd+1 fitted (`Model::card_label_hidden`: focused, `framing`, `framed_card`), with `hideLabelWhenMaximised` unchanged beside it.
- Card gradient (2026-10-22, #544): `ui.cardGradient` (a list of exactly two `#rgb`, `#rrggbb` or `#rrggbbaa` stops, `[]` is off, `Kind::ColorPair`, `ui_theme::is_gradient_stop`) and `ui.cardGradientAngle` (0 to 360, CSS-style: 0 up, 180 top to bottom) are look keys. gpui's `linear_gradient` takes two stops, so there is no longer list. A bad pair rejects the theme file; `merge_config` turns a bad pair off rather than paint half. The ui keeps them in a gpui global `chrome::CardGradient` set in `paint_world` beside `CardOpacity`; `chrome::card_ground` is the one place that picks gradient or flat fill and multiplies the stops' alpha by `ui.cardOpacity`, and `card_body_quad` calls it (terminal, editor, transcript and page bodies). Browser cards stay flat. A ringed card (focused or selected) with a gradient grows its fill by the ring gap (`chrome::CardRingGap`, set per card around `body.paint`, `ring_reach` and `grow` in `card_body_quad`; the content mask grows with it), so the gradient reaches the focus ring; and with a gradient on, `AgentState::None`'s hairline border is transparent (a gradient reaches the edge, a dark line over it read as padding; agent borders stay). `ui.focusRingWidth` (look key, 0 to 10, 0 = the zoom-stepped 3/4/5, `chrome::focus_ring_width_px`) sets the ring width at every zoom; the gap is `RING_GAP_RATIO` times it. The installed app rejects a theme with a key it does not know, so a theme file shared with the installed app must not get new keys before that app is updated.
- Tab keys (2026-10-22, #544): `tab.background`, `tab.activeBackground`, `tab.gradient` (`[]` or two stops, replaces `activeBackground`), `tab.opacity` (0.1 to 1, multiplies every tab fill), `tab.border`, `tab.activeBorder`, `tab.separator` (colour or `"none"`) `tab.radius` (0 to 40) and `tab.paddingX` (0 to 40, side padding, default 6 as `TAB_PAD_X_PX` in `overlays.rs`) live in `ui_theme::TabTheme` beside the bar keys (`BAR_KEYS`, not `LOOK_KEYS`: they are not `Ui` fields). `Chrome::tab_style` (chrome.rs) resolves them to a `TabStyle` and `render_title_bar` reads it; every field `None` is the tab as before. The outline is an absolute child div (the tab's own side borders carry the drag-drop line), the separator a 1 px div between two idle neighbours. `ColorSpec::Hex` accepts `#rrggbbaa` now (`chrome::hex_alpha`), bars included. Tab icons (#544 step 3): `tab.icons` (off unless true), `tab.iconStyle` (`glyph` default, `image`), `tab.iconMap` (program name to a glyph or a `.svg`/`.png` file name; `default` covers the rest). Rules live in `tab_icon.rs` (pure, tested): `representative` (the workspace's focused card, else its first in reading order), `shell_name` (the process table reports a job or a child of the shell, so a shell at its prompt has `Card::proc == None`; the icon is then `terminal.shell`'s first word or `$SHELL`), `choose` (map, then in image style `<program>.svg|png`, then the built-in glyph table, then the map's or table's `default`; a missing file falls back to a glyph), `safe_file` (one plain file name, so a map value cannot leave the folder). An editor card and a browser card run no process, so `subject` gives them their kind as the program (`editor`, `browser`, #706): a map key, a logo file name and a built-in glyph (file, globe) like any program; diff, transcript and page cards still fall back to the shell. Logos are read from `ui-themes/<theme name>/icons/` (`config_files::ui_theme_icons_dir`; the theme list and watcher only read `*.json`, so the folder is ignored by them). A glyph is drawn as a `StyledText` run whose font is `terminal_body::term_font`: the icon font is registered with CoreText only as a FALLBACK, so `font_family("SymbolsNFM")` drew a missing-glyph box. A logo is gpui's `img(path)` (SVG in colour, PNG). The file check is one `is_file` per tab per frame.
- Icon sizes (2026-10-31): `tab.iconSize` and `card.headerIconSize` (pixels, `tab_icon::ICON_SIZE_MIN..MAX` 6 to 64, clamped in `ui_theme::parse`, `None` is the built-in size; `tab_icon::size_px`). A glyph's size is its font size, a logo's its side. The tab's is multiplied by the interface size (`overlays.rs`, default `TAB_ICON_SCALE` 1.25 times the label), the header's by the card's zoom (`paint_header`, default 1.25 times the text size for a glyph and 0.6 of the header's height for a logo; a bigger icon widens its slot so it never overlaps the title). The built-in 1.25 made a tall glyph (`>_`, the pencil) read much larger than the lowercase text beside it, which is why the keys exist.
- Card tab keys (2026-11-09, #693): `cardTab.*` is `tab.*` minus the icon keys, parsed by the one `ui_theme::tab_look` into `UiTheme::card_tab` (a second `TabTheme`) and resolved by the same `Chrome::tab_style`, so equal values look equal. `tab_strip::strip_style` builds the strip's `StripStyle` for both the editor and the browser. The strip copies the workspace tab's measures from `render_title_bar` as constants in `tab_strip.rs`: label `TAB_LABEL_FONT_PX` (12, shared from `overlays.rs`), gpui's default line height (phi) plus `py_1` (4 px) above and below, `rounded_sm` (4 px), `gap_1` (4 px, half on each side of a fixed-width slot so `strip_hit` still counts whole slots), plus a 3 px inset above and below the tab. Change the title bar's tab and these must follow. Tabs keep their fixed width (9 font sizes): a content-sized tab would need shaped text widths in `strip_hit`, which runs without a window. The `×` ends `paddingX` in from the tab's edge and its click band moves with it (`strip_hit` takes `pad_x`). The folder header is drawn as an idle tab (`paint_tab_box`), with no divider line after it.
- Card tab hover label (2026-11-11, #742): `cardTab.hoverDetail` is the one card-only key (no `tab.` twin, so it is its own arm in `parse`, not in `tab_look`); unset means off, the name alone. Each body keeps `hover_tab` from `strip_hit` in `mouse_move`, clears it in `mouse_leave`, and calls `tab_strip::paint_hover_label` after its content so the label sits over the text or page. Shown at once, no delay, and hidden while a tab is dragged. The editor's second line is the path through `card_label::tilde_path` with this Mac's `$HOME`.
- Card header (#544 step 4): `card.header`, `card.headerIcons`, `card.headerButtons`, `card.headerButtonsActiveOnly` (`ui_theme::CardTheme`, in `BAR_KEYS`, not `Ui` fields; `CardTheme::buttons_for(focused)` is the one place that decides which buttons a card wears, and both `paint_header` and the hit test in `input.rs` ask it, so a hidden button is not clickable; "active" is the FOCUSED card, `selection.focused_id`, not the extra selection). Pure rules in `card_header.rs`: `HEADER_H` 30 world units (so it scales with the card and a terminal's rows do not depend on the zoom), `applies`/`inset` (terminal, transcript, page only: an editor, diff and browser have their own strip), the `HeaderButton`s and the commands they run (`card.split.right`, `card.split.down`, `card.maximize.toggle`, `card.close`), `button_rects` (right-aligned, a narrow card drops the leftmost first), `button_at`. Where the inset is applied, all of them: `terminals.rs` (the grid's `world` size), `paint.rs` (`body_sizes`, the rect a body paints into via `under_header`, `paint_header`), `input.rs` (`under_header` turns a card-local point into a header hit or a body-local point shifted up, `local_in`), and an extracted card (own window) wears no header. The body's ground quad reaches up under the header (`chrome::CardHeaderH`, `reach_header` in `card_body_quad`), so a gradient runs through header and body unbroken; the header paints only content. A header click that is not a button is `Hit::CardEdge { edge: None }` (it moves the card like the old label chip); a button is `Hit::HeaderButton`, found BEFORE the frame bands so the top edge does not eat it, and a left click focuses the card and runs the command. A header logo is drawn with `window.use_asset::<ImageAssetLoader>` + `paint_image`: the header is hand painted and gpui only lets an element be prepainted in the prepaint phase (`prepaint_as_root` from paint panicked: "this method can only be called during request_layout, or prepaint"). With the header on, `paint_labels` is not called for those kinds, so the corner chip's agent-state colour is not drawn; the border still carries state.
- The theme picker draws no dim sheet (`Source::dims_canvas`): the theme previews live on every card and the sheet hid the colours being chosen (2026-10-05).
- An instance with its own `INFINITERM_DATA_DIR` keeps its settings in `<data>/config` unless `INFINITERM_CONFIG_DIR` says otherwise (`paths::config_dir_for`, 2026-10-05, Ekin: a new instance must not read the personal files). `make run` starts clean too since 2026-10-05 (Ekin: it still read his settings; `CONFIG_DIR=~/.config/infiniterm` brings them back), and `make open` relaunches the built bundle; the driver's scenarios start clean.
- Settings added for people arriving from other terminals (2026-09-30, Ekin: "other users may want more control"): `terminal.copyOnSelect` (`TerminalBody::mouse_up` hands the finished selection to `clipboard_out`, flushed in `feed_terminals`), `terminal.scrollMultiplier` (scales the wheel's `dy`), `terminal.padding` (was the `PAD` constant, now `TerminalBody::pad`, set by the reconcile, and a change refits the grid), `terminal.env` (a list of `KEY=value`, put in front of ours so `INFINITERM_CARD_ID` wins a clash). No `shellArgs`: `terminal.shell` already runs through `$SHELL -lc` and takes arguments. The rest of alacritty.toml is Alacritty the app, which we replaced; more settings when someone asks, not before.
- Snippets (`snippet.paste`, Cmd+Ctrl+S, 2026-09-22): the folder `~/.config/infiniterm/snippets/` is the whole interface, one plain file per snippet, the file name without its extension the snippet's name, the contents pasted as written less ONE trailing line break (every editor saves one, and a plain shell would run it). It was one JSON file for a day; multi-line prompts in JSON were `\n`s or arrays of quoted lines, and YAML was passed over for its indentation and `|` / `|-` traps and a new crate. The ui re-reads the folder on every open (`Effect::RefreshSnippets`, `snippets_dir()`); a missing folder is seeded from the old `snippets.json` once (left in place) or else the two examples. The palette lists the names with the first line as the hint plus an "Edit snippets…" row that opens the FOLDER in an editor card, its tree listing the files, and a pick is `Effect::PasteText`, which goes through the terminal's paste path (bracketed when the program asked, so Claude takes a multi-line prompt as one block) or any other body's `insert_text`. No per-snippet chords, no placeholders; add them when missed.
- `notify.*` (2026-11-05, #616): `notify.ntfy.server` (default `https://ntfy.sh`; the Rust field is `ntfy_server` with `#[serde(rename = "ntfy.server")]` so the default file prints the flat key), `notify.waiting`, `notify.failed`, `notify.done` and `notify.skipWhenFocused`, all on. The ntfy TOPIC is deliberately not a setting: it is the secret, and settings.json is often synced or committed. It is the one-line file `ntfy-topic` in the config folder (`paths::config_dir()`, so `INFINITERM_CONFIG_DIR` and a scratch data dir move it), read at send time, never created or written by the app; empty or missing is off and an invalid one (`push_notify::valid_topic`) is a `[push]` line in `agent.log`. The docs tell people not to commit it. How the pushes are made: `agents-and-state.md`.
- `push-devices` (2026-11-08, #649): the relay destinations for the iPhone companion, one `<relay url> <push id>` per line in the config folder (`paths::config_dir()`), written 0600 by `files::write_private_atomically` (owner only from the first byte, even over a file that was wider). It is not a setting: the id lets anyone push to that phone, and settings.json is often synced or committed. Unlike `ntfy-topic`, which the app never writes, this file IS written, by `ift push add <id> --server <https url>` (prints `push: added <6 chars>…`; the phone counts a line starting `push: added` as done), `ift push remove <id>` and `ift push list` (url and 6 chars of each id), and by the sender when the relay answers `gone` for an id. Exit codes: 0 ok, 1 the file cannot be read or written, 2 bad usage. The docs tell people not to commit it. A missing file is no devices and no request.
- `browser.engine` (#761, removed in #826 with CEF): there is one engine now, so the setting, `config::BrowserEngine` and its `settings_doc.rs` entry are gone. A settings.json that still names it stays valid (`validate_settings` passes an unknown key, `merge_config` ignores it; `a_leftover_browser_engine_key_is_ignored_and_stays_valid` pins both). `browser.devtools` stays and means "make the page inspectable from Safari's Develop menu". See `browser-and-pages.md` ("The webview engine").
- The default theme is Violite (`config.rs`, a test holds it), out of the 522 in `assets/themes/`.
- Settings schema (2026-11-21, #745 step 1): `settings_schema.rs` gives every settings.json key a `Kind` (the control the settings window will draw: `Bool`, `Number`, `OptionalNumber`, `Text`, `Choice(&[..])`, `Color`, `Font`, `TerminalTheme`, `UiTheme`, `Folder`, `TextList`, `NumberList`, `SearchEngines`) and a `Section` (the window's left menu). The look keys are not in it: they live in the ui theme file and `ui_theme::LOOK_KEYS` is their schema. It is not validation: `validate_settings` and `merge_config` stay the judges, and a `Choice` lists the words the window offers, not the only words the file may hold. Tests hold that every key has exactly one row and a doc line, that each kind matches its default, and that every choice word round-trips through `merge_config` (a renamed enum variant fails it). Ekin's plan for the window (#745, 2026-11-21): no UI library, no AppKit-only parts in the first version so it ships on all three systems (dropdowns from the palette's gpui list, colours as a `#rrggbbaa` field with a swatch, NSColorPanel only later as a second way in, paths through `cx.prompt_for_paths`), order schema, then checkbox and rows, then the view, `ui.settings` off by default.
- Settings rows (2026-11-21, #745 step 2): `settings_rows.rs` is the window's logic with no gpui. `rows(text)` gives every schema key its value in force (what `merge_config` made of the file, clamps included, so the window shows what the app uses) and `set` (the file names it: the marker and the reset button; a file that does not parse sets nothing, as the app keeps the settings in force). `write_for` turns an edit into `Write::Set` or `Write::Remove`, removing when the value equals the default (numbers compared by value, `14` against the serialised `14.0`), as the issue asks. `apply` patches the text with `patch_json_text` or `remove_key` (comments kept), returns `Ok(None)` when nothing changes, and refuses with `validate_settings`'s reason a result the file itself would reject, so the window never writes a file the app refuses. `parse_field` reads a text field per kind (numbers finite, colours `#rgb`/`#rrggbb`/`#rrggbbaa` or empty, text kept as typed); `matches` is the search, every word in the key, section title or doc text. The gpui checkbox waits for the view: alone it would be dead code under `clippy -D warnings`.
- Settings window (2026-11-21, #745 view, first of two PRs; Tarik split it): `ui.settings` (off) makes `app.settings` push `Effect::OpenSettingsWindow` instead of opening the file pair; a joined viewer always gets the files (its settings are the host's, viewers are out of scope). `app.settings.file` opens settings.json either way, so the window never hides the file and nothing is mouse-only. `settings_window.rs` (ui) is wiring over `settings_rows`: opened and raised from the poll task in main.rs, never inside an `AppView` update (the `own_window.rs` rule), one instance kept in `AppView::settings_window`, Cmd+W or the red button clears it. It holds the file's text and writes through `settings_rows::apply` + `config_write`; the app's watcher applies the file as for a hand edit, and bumps `AppView::settings_gen`, which the poll task compares with `settings_gen_drawn` to make the window re-read the file after an outside edit. Controls: checkbox (`Bool`), a list under the row (`Choice`, drawn like the palette's rows, no NSMenu), a `Field` for `Number`/`OptionalNumber`/`Text`/`Color` (a swatch beside a colour; Enter or a click elsewhere commits, Esc cancels; a refusal keeps the field open with the reason under the row). Second PR (2026-11-21): `Font`, `TerminalTheme` and `UiTheme` open a `Picker` under the row (a filter `Field`, matches through `settings_rows::pick_matches`, best first, at most `PICKER_MAX_ROWS`; Enter takes the best); the items are `fonts::installed_families()`, `themes_files::list_themes(themes_dir)` and `config_files::list_ui_themes()` plus `default`. `Folder` is `cx.prompt_for_paths` from the window's own context (it works there; the result arrives on a spawned task). `TextList`, `NumberList` and `SearchEngines` draw their items under the row, one `Target { key, item, part }` cell each, × removes, "Add" opens a field one past the end (left empty, it adds nothing; an emptied item is removed). A list row edits `Row::raw` (what the file holds) through `Row::list`, because `merge_config` drops an incomplete engine and it would vanish mid-typing; `engine_problem` says why it is not used yet. The frame goes to `settings-window.json` (`WindowState::load_settings`/`save_settings`) on close and whenever `render` sees it change; it saves the frame's ORIGIN with the CONTENT size (`viewport_size`), because this window keeps a standard title bar and `window_bounds` is the outer frame, which grew the window by the bar on each reopen (672 became 704, seen on screen). The search field drops its caret while a picker or field has the keys. Nothing in a row's label is cut (Tarik, 2026-11-21: the text was cut off and the window had to be widened to read it): `settings_rows::summary` is the doc's first SENTENCE (the stored lines joined, cut after the first ".
