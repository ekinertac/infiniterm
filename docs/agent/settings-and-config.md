# Settings, config and look

What this covers: how settings.json and keybindings.json are read, validated and written, flat dotted keys, the look settings (window, card, background), settings for people coming from other terminals, the data and config folders of a scratch instance, snippets, and the default theme.

Read it before touching `infiniterm-core/src/config.rs`, `settings_doc.rs`, `config_write` and `patch_json_text`, `keymap.rs`, `themes.rs`, `snippets`, `paths.rs`, or adding any setting.

Related: `editor.md` (the settings.json schema for completion), `ui-chrome.md`, `canvas-and-layout.md` (`cards.*`), `traps-code.md` (keybindings `when`, atomic writes through a symlink, settings that are parsed and never read).

Moved here from CLAUDE.md on 2026-10-19 with the text unchanged.

- settings.json is VALIDATED before it applies (2026-10-06, #246, Ekin: "if it has errors we shouldn't accept it"): `validate_settings` rejects a file that is not an object or holds text, a number or a boolean where the default is another of those, nothing stricter (a valid file must never be refused: lists, unknown names and out-of-range numbers pass), the settings in force stay, a notice and a status bar segment say so, and keybindings.json keeps its bindings the same way. The editor's completion popup (#247) opens only after a word character or a quote and Enter takes a row only after Up or Down chose it. Before, A settings.json that stops parsing keeps the settings in force (2026-10-06, #246): it used to fall back to `default_config()`, and a double comma from `patch_json_text` (it added a comma after a last entry that already had one, `0.9,,`) made the whole app look as if it had lost Ekin's font, background and window colour. `insert_key` now puts the comma right after the last token, before a comment, and none when one is there.
- Settings: defaults and overrides are separate files, the defaults rewritten at launch; a new setting needs a `settings_doc.rs` entry or the test fails. Writes to the user file patch the text, never reserialise. Keys are FLAT and dotted (`"terminal.fontSize": 16`, VS Code's shape) since 2026-09-18, because extending a nested value meant copying the nesting; `config::flatten` reads the old nested shape too, a setting spelled both ways takes the flat one, and nothing writes the nested shape any more (`patch_json_text` replaces a value where it finds it, flat or nested, and inserts a missing one flat).
- Look settings (2026-10-03/04; since 2026-10-21 the look ones are keys of a ui theme, see the next bullet, only `fitPadding`, `fitMagnify`, `fitSplitSlot` and `workspaceIsolation` of this list stayed in settings.json): `ui.showGrid`, `ui.windowOpacity` + `ui.windowBlur`, `ui.cardOpacity` (a gpui global `CardOpacity`, `chrome::card_ground`; a background image is painted opaque because gpui's `paint_image` has no alpha), `ui.backgroundImage` (a string or a list that rotates, #210) + `ui.backgroundImageFit` + `ui.backgroundImageInterval` / `ui.backgroundImageFade` (`background.rs` holds the pure `Slideshow` clock, `background_show.rs` the loading and the layers; dusk, aurora and ember ship in `assets/backgrounds`, copied by `bundle.sh`), `ui.fitPadding` / `ui.fitMagnify` (Cmd+1's margin and the cap on magnifying a small card; `viewport::fit_rect_with`) / `ui.fitSplitSlot` (default on: Cmd+1 on a split piece frames the whole slot; off fits the card alone, `Model::slot_bounds`), `ui.workspaceIsolation` (the card switcher and navigation stay in one workspace), `ui.windowColor`. `ui.maximised` is gone. About is the confirm dialog with `Prompt::about`. `make run-clean` runs on empty settings.
- UI themes (2026-10-21, #511, Ekin: `theme.json` of #427 clashed with the terminal `theme` and could not hold several looks). The look lives in `ui-themes/<name>.json` in the config folder, one file per look; `ui.theme` in settings.json picks the file (default `default`). Files: `ui_theme.rs` (the key table `LOOK_KEYS`, `parse`, `strip_look`, names), `look_migration.rs` (the startup move), `config_files.rs` (`ui_themes_dir`, `ui_theme_read/write`, `list_ui_themes`, `migrate_look_keys`, the watcher `poll_ui_themes`), `settings_doc.rs` (`default_ui_theme_text`, the reference that also seeds `default.json`), `model/settings_in.rs`. Rules:
  - The look keys are the 16 that left settings.json (`ui.windowOpacity`, `windowBlur`, `windowColor`, `backgroundImage`, `backgroundImageInterval`, `backgroundImageFade`, `backgroundImageFit`, `cardRadius`, `cardOpacity`, `showGrid`, `inactiveDim`, `unfocusedDim`, `fontFamily`, `fontSize`, `fontWeight`, `fontWeightBold`), the new `ui.hideLabelWhenFitted`, and the four bar keys (`titlebar.*`, `statusbar.*`). They keep their `ui.` names inside the theme, so moving one is moving a line. Everything else (`panStep`, `animations`, the fit keys, label sizes, `hideLabelWhenMaximised`, `fullscreen`...) stays in settings.json. A new look key is a row in `LOOK_KEYS`, a line in `Ui::take_look_from`, a `SETTINGS_DOC` entry; a test holds the three together.
  - The fields stay in `config::Ui` so no reader changed. `Model::apply_ui_theme_text` runs the theme's look keys through `merge_config` (same clamps as before), keeps the result in `look_ui` and lays it over `config.ui` (`take_look_from`); `apply_settings_text` does the same after building a fresh `config.ui`, so neither file's change loses the other's. settings.json never sets a look field: `strip_look` drops the keys (flat and nested) before the merge, with a notice, never an error (a valid file must not be refused, and a host older than this build sends them to a viewer).
  - `ui.theme` loads a file only when it CHANGES (`note_ui_theme_setting`), so a picker preview is not undone by an unrelated settings edit. A name with no file keeps the look you had and warns; `default` needs no file (the built-in look). A theme with a mistake is not applied, the last good look stays (the #246 rule). A name must be one plain file name (`ui_theme::valid_name`), because `ui.theme` is typed by hand.
  - Startup order: `migrate_look_keys` (before settings.json is read) cuts the look keys out of settings.json with `jsonc::remove_key` (text only, comments kept, a note after the opening brace says where they went) and patches them into `ui-themes/default.json` (seeded from `default_ui_theme_text` when missing); a key the theme already sets is not overwritten. There is no marker: once settings.json holds no look key it finds nothing. It runs in the app and in `ift serve`, never in a joined viewer. A file that does not parse is left alone.
  - The watcher polls every file in `ui-themes/` (a change arrives as `ConfigFile::UiTheme` with the name); the model applies only the one in force (`ui_theme_file_changed`). The window colour palette writes `ui.windowColor` into the theme in force (`Effect::SaveLook`), not settings.json.
  - Per client: a joined viewer keeps its own look. Host settings go through `apply_host_settings_text` (everything but `ui.theme`), the viewer's `ui.theme` comes from its own settings.json (`ui_theme_name_in`, and `SaveSetting` for `ui.theme` is the one setting a viewer may write), and its own ui theme files are read and watched. The host never publishes a ui theme.
  - Picker: `uitheme.pick` ("UI theme: switch…") is `Source::UiThemes`, built like `Source::Themes` (active first under its hint, order kept, no dim sheet, preview is `Effect::LoadUiTheme`, cancel puts `ui_theme_before_preview` back, Enter saves `ui.theme`). Not decided by Ekin and kept plain: no next/previous chords, no "open the folder" row, no bundled looks besides `default`.
  - `ui.hideLabelWhenFitted` (a look key) hides the chips of the card Cmd+1 fitted (`Model::card_label_hidden`: focused, `framing`, `framed_card`), with `hideLabelWhenMaximised` unchanged beside it.
- Card gradient (2026-10-22, #544): `ui.cardGradient` (a list of exactly two `#rgb`, `#rrggbb` or `#rrggbbaa` stops, `[]` is off, `Kind::ColorPair`, `ui_theme::is_gradient_stop`) and `ui.cardGradientAngle` (0 to 360, CSS-style: 0 up, 180 top to bottom) are look keys. gpui's `linear_gradient` takes two stops, so there is no longer list. A bad pair rejects the theme file; `merge_config` turns a bad pair off rather than paint half. The ui keeps them in a gpui global `chrome::CardGradient` set in `paint_world` beside `CardOpacity`; `chrome::card_ground` is the one place that picks gradient or flat fill and multiplies the stops' alpha by `ui.cardOpacity`, and `card_body_quad` calls it (terminal, editor, transcript and page bodies). Browser cards stay flat. A ringed card (focused or selected) with a gradient grows its fill by the ring gap (`chrome::CardRingGap`, set per card around `body.paint`, `ring_reach` and `grow` in `card_body_quad`; the content mask grows with it), so the gradient reaches the focus ring; and with a gradient on, `AgentState::None`'s hairline border is transparent (a gradient reaches the edge, a dark line over it read as padding; agent borders stay). `ui.focusRingWidth` (look key, 0 to 10, 0 = the zoom-stepped 3/4/5, `chrome::focus_ring_width_px`) sets the ring width at every zoom; the gap is `RING_GAP_RATIO` times it. The installed app rejects a theme with a key it does not know, so a theme file shared with the installed app must not get new keys before that app is updated.
- Tab keys (2026-10-22, #544): `tab.background`, `tab.activeBackground`, `tab.gradient` (`[]` or two stops, replaces `activeBackground`), `tab.opacity` (0.1 to 1, multiplies every tab fill), `tab.border`, `tab.activeBorder`, `tab.separator` (colour or `"none"`) and `tab.radius` (0 to 40) live in `ui_theme::TabTheme` beside the bar keys (`BAR_KEYS`, not `LOOK_KEYS`: they are not `Ui` fields). `Chrome::tab_style` (chrome.rs) resolves them to a `TabStyle` and `render_title_bar` reads it; every field `None` is the tab as before. The outline is an absolute child div (the tab's own side borders carry the drag-drop line), the separator a 1 px div between two idle neighbours. `ColorSpec::Hex` accepts `#rrggbbaa` now (`chrome::hex_alpha`), bars included. Tab icons (#544 step 3): `tab.icons` (off unless true), `tab.iconStyle` (`glyph` default, `image`), `tab.iconMap` (program name to a glyph or a `.svg`/`.png` file name; `default` covers the rest). Rules live in `tab_icon.rs` (pure, tested): `representative` (the workspace's focused card, else its first in reading order), `shell_name` (the process table reports a job or a child of the shell, so a shell at its prompt has `Card::proc == None`; the icon is then `terminal.shell`'s first word or `$SHELL`), `choose` (map, then in image style `<program>.svg|png`, then the built-in glyph table, then the map's or table's `default`; a missing file falls back to a glyph), `safe_file` (one plain file name, so a map value cannot leave the folder). Logos are read from `ui-themes/<theme name>/icons/` (`config_files::ui_theme_icons_dir`; the theme list and watcher only read `*.json`, so the folder is ignored by them). A glyph is drawn as a `StyledText` run whose font is `terminal_body::term_font`: the icon font is registered with CoreText only as a FALLBACK, so `font_family("SymbolsNFM")` drew a missing-glyph box. A logo is gpui's `img(path)` (SVG in colour, PNG). The file check is one `is_file` per tab per frame.
- The theme picker draws no dim sheet (`Source::dims_canvas`): the theme previews live on every card and the sheet hid the colours being chosen (2026-10-05).
- An instance with its own `INFINITERM_DATA_DIR` keeps its settings in `<data>/config` unless `INFINITERM_CONFIG_DIR` says otherwise (`paths::config_dir_for`, 2026-10-05, Ekin: a new instance must not read the personal files). `make run` starts clean too since 2026-10-05 (Ekin: it still read his settings; `CONFIG_DIR=~/.config/infiniterm` brings them back), and `make open` relaunches the built bundle; the driver's scenarios start clean.
- Settings added for people arriving from other terminals (2026-09-30, Ekin: "other users may want more control"): `terminal.copyOnSelect` (`TerminalBody::mouse_up` hands the finished selection to `clipboard_out`, flushed in `feed_terminals`), `terminal.scrollMultiplier` (scales the wheel's `dy`), `terminal.padding` (was the `PAD` constant, now `TerminalBody::pad`, set by the reconcile, and a change refits the grid), `terminal.env` (a list of `KEY=value`, put in front of ours so `INFINITERM_CARD_ID` wins a clash). No `shellArgs`: `terminal.shell` already runs through `$SHELL -lc` and takes arguments. The rest of alacritty.toml is Alacritty the app, which we replaced; more settings when someone asks, not before.
- Snippets (`snippet.paste`, Cmd+Ctrl+S, 2026-09-22): the folder `~/.config/infiniterm/snippets/` is the whole interface, one plain file per snippet, the file name without its extension the snippet's name, the contents pasted as written less ONE trailing line break (every editor saves one, and a plain shell would run it). It was one JSON file for a day; multi-line prompts in JSON were `\n`s or arrays of quoted lines, and YAML was passed over for its indentation and `|` / `|-` traps and a new crate. The ui re-reads the folder on every open (`Effect::RefreshSnippets`, `snippets_dir()`); a missing folder is seeded from the old `snippets.json` once (left in place) or else the two examples. The palette lists the names with the first line as the hint plus an "Edit snippets…" row that opens the FOLDER in an editor card, its tree listing the files, and a pick is `Effect::PasteText`, which goes through the terminal's paste path (bracketed when the program asked, so Claude takes a multi-line prompt as one block) or any other body's `insert_text`. No per-snippet chords, no placeholders; add them when missed.
- The default theme is Violite (`config.rs`, a test holds it), out of the 522 in `assets/themes/`.
