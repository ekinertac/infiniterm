# The canvas

> Cards, where new ones go, moving and resizing, zoom, groups and workspaces.

Every card sits on one canvas you pan and zoom. Cards never move on their own: a card stays where you put it until you move it. ## Kinds of card [Section titled “Kinds of card”](#kinds-of-card) * **Terminal**: a real shell, your login shell, started in the card’s directory. See [Terminal cards](../terminal/). * **Editor**: a file with syntax highlighting (17 tree-sitter grammars), multiple cursors, find and replace, and a file tree beside it (`Cmd K`). No LSP, on purpose. See [Editor cards](../editor/). * **Diff**: `ift diff` opens the changes against git HEAD, the changed files on the left and one file’s diff on the right, in a read-only editor. `Cmd B` adds a blame gutter. See [The diff card](../editor/#the-diff-card). * **Transcript**: `Cmd I` on a card running Claude Code or Pi opens its session beside it as turns, with tool calls folded under each. * **Page**: a Markdown file rendered (headings, lists, code, links), read-only. It never takes the keyboard: the wheel scrolls it, and while it is focused the arrows, Page Up/Down, Space, Home and End do too; every other key stays the canvas’s. A scrollbar at the right edge shows when there is more below. Web links open in the browser, links to other `.md` files open as Pages. The “Start here” card a first launch shows is one. * **Browser**: Chromium inside the card, with the Claude in Chrome extension loaded, so Claude Code can drive a browser on your canvas. “Browser: open DevTools” in the palette opens Chromium’s DevTools for the page in a card beside it. It uses a debugging port on a random loopback port that only that DevTools page may use; a program running on your Mac could still attach to it, so `"browser.devtools": false` turns the feature off (restart the app after changing it). `Cmd L` opens the address bar, and so does `Cmd T` on the new blank tab. Middle-click or `Cmd` + click on a link opens it in a new tab, middle-click on a tab closes it, and the mouse’s back and forward buttons walk the history (Back on a tab a link opened closes it). ## Where a new card goes [Section titled “Where a new card goes”](#where-a-new-card-goes) `Cmd T` puts a new card in the first free slot of a square block grown from the top-left corner of your cards. Four cards make a 2x2, nine a 3x3. It does not depend on which card you were on, so you can predict where it lands. Holes in your grid of cards are filled first, top row first, before the grid grows. A new card is 16:9 and sized to fill the window at 100%. `cards.shape`, `cards.width` and `cards.height` change that. `cards.gap` is the space between cards, 25 pixels by default (0 to 200). New cards, splits, a grown card, Canvas: tidy and group frames use it; cards already on the canvas keep their places until you move them or tidy. Dragging still snaps to the 25-pixel grid. Other ways to place one: * `Cmd Ctrl T` letters every empty slot around the cards; press a letter. * `Cmd D` / `Cmd Shift D` split the focused card to the right or below. The halves remember each other, so closing one hands its space back. * Arrow (`Cmd Alt` + arrow) into an empty slot to get a hollow card; `Enter` asks what goes in it. ## Moving and resizing [Section titled “Moving and resizing”](#moving-and-resizing) Drag a card by its top edge or its label. The card stays put while an outline follows the pointer, and the grid’s slots for a card of that size show around it: halves for a half, quarters for a quarter. Near a slot the outline snaps to it; anywhere else it goes where you put it. It wears the focus colour where the card fits and the warning colour where it does not. Drop on free space to move, drop on another card to swap the two, `Escape` to cancel. Any other edge resizes. From the keyboard, `Cmd Alt Shift` + arrow swaps the card with its neighbour. `Cmd Ctrl Alt` + arrow slides the card that way into the next gap, which closes the space a resize (`Cmd Alt S`) leaves. The card stops one gutter short of the next card in line, or on the next grid slot when nothing is there, and never overlaps. `Cmd Z` undoes it. `Cmd Alt S` opens the size list. Full, Half, Quarter and Double resize the focused card. Three rows at the end act on every selected card (or on the focused card when none is selected). Each command is also in the palette and has an id for `ift run`. * **Resize to window** (`card.size.window`). Each card keeps its width and takes the window’s proportions, so a portrait card from a joined host becomes a landscape card. * **Default size** (`card.size.default`). Each card goes back to `cards.width` by `cards.height`. Without those settings, it takes the window’s shape. * **Custom size…** (`card.size.custom`). A prompt asks for a width and a height in grid squares. A square is 25 pixels, the unit of `cards.width`, so 50 is 1250 pixels. Type `60x90`, `60 x 90`, `60 90` or `60,90`. The prompt starts from the last size you typed, or from the default size. A side under 8 squares wide or 4 squares tall is raised to that minimum, and a notice says so. A side over 400 squares is refused. The notice after a resize gives the size in pixels. All three place the cards the same way. Each selected card sits one gutter right of the card on its left and one gutter below the card above it. A neighbour is pulled closer or pushed away, and nothing overlaps. Cards you did not select stay where they are. `Cmd Z` undoes the whole change in one step, and the view then fits the selected cards. A maximised card refuses, with a notice: restore it first. `Cmd Ctrl Shift` + arrow pans the canvas that way by 120 screen pixels a press, at any zoom, and a held key repeats. `ui.panStep` changes the step, from 20 to 1000 screen pixels; a smaller number is a slower pan. The focus stays where it is, as with the mouse. The commands are `canvas.pan.left`, `.right`, `.up` and `.down`, for the palette, `ift run` and your own bindings. `Cmd Ctrl Enter` grows a card into the gap it sits in, up to the default size, from whichever corner fills that gap. It grows an empty slot the same way: arrow onto a free slot (it has the size of the card you came from), press `Cmd Ctrl Enter`, and the card you make there has the new size. `Cmd Z` and `Cmd Shift Z` undo and redo on the canvas: a move, swap, resize or a closed card. Undo never closes a card you opened. Inside an editor they are the buffer’s. Canvas: tidy, in the palette, packs the cards back onto the grid in reading order, a gutter apart. A group or a split pair moves as one block and keeps its inside arrangement. `Cmd Z` scatters them again. ## Zoom [Section titled “Zoom”](#zoom) * Scrolling is for cards. A plain scroll, a mouse wheel or two fingers on the trackpad goes to the card under the pointer: a terminal’s history, an editor, a page. Over empty canvas it does nothing. To pan, drag with `Cmd` held, middle-drag, or use `Cmd Ctrl Shift` + arrow. * `Cmd` + scroll, or a pinch on the trackpad, zooms around the pointer. The palette has zoom in and out too. (`Cmd =` and `Cmd -` change the terminal font size; see [Terminal cards](../terminal/).) * `Cmd Alt` + two fingers (or `Cmd Alt` + the wheel) moves the focus like `Cmd Alt` + arrow, one card for each swipe. `Cmd Shift` + two fingers sideways switches to the next or previous workspace, once a swipe. The momentum after you lift your fingers does not keep moving. * `Cmd 0` actual size, `Cmd 1` fit the focused card, `Cmd 2` fit everything. `"ui.hideLabelWhenFitted": true` in a ui theme leaves the card’s label off on the card `Cmd 1` fitted to the window. It also leaves the label off the only card on a workspace, without `Cmd 1`. * `Cmd 3` fits the selected cards when several are selected. With one card it fits the card’s group, or else the block of cards around it (every card within a gutter of the next). * Double-click a card’s frame or label to fit it; double-click empty canvas to fit everything. A terminal card drawn as bars (only when `ui.textAsBars` is on, see below) fits on a double-click anywhere on it. Cards draw their text at every zoom. On a slow Mac you can turn on `"ui.textAsBars": true`: far out, or with many cards on screen, text is then drawn as bars, one per word, so a full card still reads as full. `ui.minTextPx` (7 by default) is how big a glyph must be, in device pixels, before text replaces bars, and `ui.glyphBudget` is how many terminal cells may be on screen before every card turns to bars. Neither does anything while `ui.textAsBars` is off. ### Zooming in on a card’s bottom [Section titled “Zooming in on a card’s bottom”](#zooming-in-on-a-cards-bottom) `Cmd 1` on a terminal card that is already fitted zooms in to 150% with the card’s bottom edge at the bottom of the window, which is where a long agent answer ends. The status bar says “zoomed”. `ui.cardZoom` sets the zoom (1.1 to 4, and `0` turns the behaviour off, so a second `Cmd 1` does nothing new); the older name `ui.readZoom` still works. While it is on, `Cmd Up` and `Cmd Down` pan three rows inside the card. Typing and `Enter` still reach the shell and bring the view back to the bottom. `Cmd 1` again or `Cmd 2` leaves it, and so does panning or zooming by hand. The palette has it as “Canvas: zoom in on the focused card’s bottom”. ### Maximising a card [Section titled “Maximising a card”](#maximising-a-card) `Cmd Shift Enter` makes the focused card fill the window, and pressing it again puts the card back. `"ui.hideLabelWhenMaximised": true` leaves the card’s label off while it fills the window. ### How a fit frames the cards [Section titled “How a fit frames the cards”](#how-a-fit-frames-the-cards) Every fit (`Cmd 1`, `Cmd 2`, `Cmd 3`, the double-clicks) leaves `"ui.fitPadding"` pixels around what it frames, 48 by default; `0` lets the cards touch the window’s edges. A fit never zooms past 100%, so a small card stays its own size in the middle of the window; `"ui.fitMagnify": true` lifts that, and a fit then zooms in until the card fills the window. `Cmd 1` on a card that was split frames the whole slot, both halves together; `"ui.fitSplitSlot": false` makes it fit that card alone, so it fills the window. Interface size is separate from zoom: `Cmd Shift =` and `Cmd Shift -` make the app’s own chrome (labels, title bar, status bar, palette, dialogs) bigger or smaller, never terminal text. ## Moving between cards [Section titled “Moving between cards”](#moving-between-cards) * `Cmd Alt` + arrow, or `Cmd Alt J K L`, moves focus to the neighbour. * `Ctrl Tab` is Cmd+Tab for cards: hold Ctrl, press Tab to step through the cards you worked in, most recent first, release to go there. Cards you only crossed with the arrows are left out unless you stayed. * `Cmd J` puts a letter on every card; press one to go there and frame it. (`Cmd F` finds text inside the card you are on.) * The palette lists every card by name. Several cards can be selected at once, and close, split, fit and group then act on all of them: * Drag on empty canvas to draw a selection rectangle. Every card it touches is selected, and the card nearest where the drag started gets the focus. `Shift` + drag adds to the selection, and `Escape` during the drag puts the previous selection back. A click without a drag deselects. * `Cmd` + click a card to add it, or a selected card to take it out. On the one card you are in, `Cmd` + click still opens links. * `Shift` + click on a card’s body, label or frame also adds it or takes it out. * `Cmd A` selects every card of the workspace (“Focus: select every card” in the palette). In a locked editor or browser card `Cmd A` stays the text’s or the page’s. * `Cmd Shift` + arrow extends the selection to the neighbour. * Dragging any selected card by its frame or label moves the whole selection. * `Cmd Alt Shift` + arrow moves the whole selection one block that way, as one piece: into free space, or trading places with the cards there. It refuses, with a notice, when that would split a card or land in another group. `Cmd Z` undoes it in one step. While a dialog, the palette, the address bar or the shortcuts panel is open, it keeps every Cmd and Ctrl shortcut to itself, so text shortcuts work in its field and nothing moves the canvas behind it. Their rows and buttons also take a click, and a click outside closes any of them, as `Escape` does. Anything you can click in them shows a hand pointer and lights its row. ## Groups and workspaces [Section titled “Groups and workspaces”](#groups-and-workspaces) A group is a named frame around a set of cards: `Cmd G` groups the focused card, `Cmd Shift G` dissolves its group, `Cmd [` and `Cmd ]` step between groups. A workspace is a separate canvas with a tab in the title bar. `Cmd Shift N` makes one, `Ctrl 1` to `Ctrl 9` jump to one, `Cmd Shift [` and `Cmd Shift ]` step. Each tab wears one dot per card, in the cards’ reading order, lit in the card’s state colour, so you can see from another workspace that something there wants you. Drag a tab onto another tab to put it in that place: a vertical line shows where it will land, at the left edge of the tab you are over when you drag left and at its right edge when you drag right. Dragging a tab does not move the window. Double-click a tab’s name to rename the workspace. Ctrl+Cmd+drag, the system’s way to move a window by its body, no longer moves the main window. From the keyboard, “Workspace: move this tab left” and “move this tab right” in the palette do the same. The order is saved, and `Ctrl 1` to `Ctrl 9` follow it. With `"ui.workspaceIsolation": true`, `Ctrl Tab` walks only the current workspace’s cards and the status bar counts only them; the palette still lists every card, so it stays the way across. “Card: move to workspace…” in the palette sends the focused card, or the selection, to another workspace or a new one. The card takes a free slot there and you stay where you are. “Group: move to workspace…” does the same for the focused card’s whole group, with its frame, its name and its cards in the same arrangement and sizes. It lands in the first free block of the other workspace. ## Card labels and numbers [Section titled “Card labels and numbers”](#card-labels-and-numbers) Every card has a label in its corner: the name you gave it (`Cmd Shift R`), else the running process, else the directory. It also wears a number, `#7`, the lowest one free. `ift attach 7` reaches that card’s shell from any terminal. The label sits top right by default. `"ui.cardLabelPosition"` moves it to `"top left"`, `"bottom left"` or `"bottom right"` (the words in either order); a card in an ssh session shows its ssh badge at the other end of the same edge. ### Locking a browser card [Section titled “Locking a browser card”](#locking-a-browser-card) A page needs the keyboard for itself, so a browser card works like a locked editor. Click into the page, or press `Enter` on a card you arrived at with the arrows, and the keyboard is the page’s: the ring turns the warning colour and the status bar says so. Chrome’s own chords work then (`Cmd T`, `Cmd W`, `Cmd 1` to `Cmd 9` for tabs). Press `Escape` twice within 400 ms to let go; a single `Escape` goes to the page, which uses it. `Cmd Escape` lets go at once. `Cmd Shift P` opens the command palette from a locked page too. ## The right-click menu [Section titled “The right-click menu”](#the-right-click-menu) Right-click opens the native macOS menu, with each command’s shortcut at the right edge and the rows that cannot run now greyed. What it holds depends on where you click: * **A terminal**: Copy, Paste, Find…, Search the Web for Selection, Clear Buffer and Show Transcript, then the card rows below. * **An editor**: Save, Find…, Go to Line…, Transform (every text transform), Show File Tree and Blame, then the card rows below. * **A card’s frame or label**: the card rows below. A click on a terminal’s or an editor’s frame or label opens the same menu as a click in its text. * **Bare canvas**: New, Select All Cards, Undo Layout, Redo Layout, Reopen Closed Card, Fit All Cards, Actual Size, Tidy into a Block, Command Palette…, Settings and Keyboard Shortcuts. * **A workspace tab** (the click does not switch to it): Rename…, New Workspace, Move Left, Move Right and Close Workspace. * **A file or folder in an editor’s tree**: the row lights up while the menu is open. Open, Reveal in Finder, Copy Path and Copy Relative Path. * **A tab of an editor or browser card**: switches to that tab, then New Tab, Close Tab and Reopen Closed Tab. A browser tab also has Reload, Copy Address and Open in System Browser. * **A browser page**: Back and Forward when there is somewhere to go, Reload, Cut, Copy and Paste where they apply, and Open Page in System Browser. On a link: Copy Link Address, Open Link in New Tab, Open Link in New Card and Open Link in System Browser. The card rows end the menu of a terminal, an editor and a card’s frame or label, in this order: Split Right, Split Down, New, Group…, Size, Move to Workspace…, Canvas (Fit Card, Fit Selection, Fit All Cards, Actual Size, Tidy into a Block, Select All Cards), Rename…, Protect, Mask (terminals only), Clear State Colour and Close. With several cards selected, a right-click on one of them keeps the selection and opens a menu for all of them: Group, Protect, Clear State Colour, Fit Selection, Move to Workspace… and Close. Rename, Split and Size are left out, since they are for one card. A right-click on a card outside the selection selects that card alone. A terminal program that uses the mouse, such as vim, tmux or htop, still gets the plain right-click. Hold `Shift` to open the menu over it. A label that ends in an ellipsis, in the menu and in the command palette, asks you for something more before it acts: a name, a file, an address. One without it acts at once. ## Closing and protecting [Section titled “Closing and protecting”](#closing-and-protecting) A card closes when its shell exits, so `exit` or Ctrl+D does what `Cmd W` does. `Cmd Shift T` reopens the last card you closed, where it was, as in a browser. Closing a terminal card does not kill its program on the spot: a build or an agent mid-turn runs to its end, and `Cmd Shift T` or `Cmd Z` brings the card back with it still live. See [Terminal cards](../terminal/#closing-a-card). `Cmd Shift L` protects a card: `Cmd W` refuses it, its workspace will not close around it, and if its shell exits a fresh one takes over. `Cmd Shift H` masks a card while somebody reads your screen: a decoy (by default `log stream`) runs over it at the same size, and nothing you type reaches the card underneath. `Enter` or `Escape` lifts it.

# Card states

> What the four border colours mean and where they come from.

A card’s border has four colours because there are four questions: | Colour | State | Means | | ------ | ------- | ------------------------------------------------------------------------- | | Violet | working | an agent is mid-turn, or a command has been running for 5 seconds or more | | Yellow | waiting | blocked on you: a permission prompt, or a question | | Red | failed | a command exited non-zero, or the agent’s turn failed | | Green | done | the turn or the long command finished | A shell doing nothing has no colour. Four hues rather than shades of one, because two oranges are one colour at 40% zoom. ## Agents [Section titled “Agents”](#agents) Claude Code, Pi, Codex, OpenCode and Cursor report through hooks (`ift install-claude-hooks`, `install-pi-hooks`, `install-codex-hooks`, `install-opencode-hooks`, `install-cursor-hooks`; see [Install](../install/#agent-hooks)). The card goes violet when a turn starts, yellow when the agent asks for permission or asks you something, and green when the turn ends. What each agent reports differs a little: | Agent | Working | Waiting | Failed | Done | | ----------- | ------- | -------------------------------- | ------ | ---- | | Claude Code | yes | permission prompts and questions | yes | yes | | Pi | yes | its prompts | no | yes | | Codex | yes | approval prompts only | no | yes | | OpenCode | yes | permission prompts and questions | yes | yes | | Cursor | yes | no | yes | yes | Pi and Codex send nothing when a turn fails, so a failed turn there does not turn the card red; Codex’s questions do not show as waiting either. Cursor has no hook while an approval dialog is open, so the card stays violet until you allow or deny the command. OpenCode keeps its sessions in a database, so it has no transcript card (`Cmd I`). Green is news, so it does not stay: once you have looked at a done card for a moment (about a second and a half) or typed into it, it goes grey. “Card: clear the state colour” in the palette greys any card’s ring and dot by hand once you have seen what it had to say. ## Any command [Section titled “Any command”](#any-command) A zsh started in a card reports each command’s start and exit status (OSC 133 marks) through a small shim the app installs, which then loads your own zsh files as usual. From that: * A command that runs 5 seconds or more goes violet, then green if it exits 0. A quick `ls` never colours the card, or every shell card would be green and green would say nothing. * A command that fails goes red however quick it was. Ctrl+C (exit 130) does not count as a failure. * The next command clears the last result. * A full-screen program (vim, htop, less) never colours the card. Programs that print OSC 9;4 progress or OSC 9, 777 or 99 notifications colour the card too, whatever the shell. Only zsh gets the marks for now, and only shells started after you installed or updated the app: a shell already running keeps the environment it started with. ## Workspace tabs [Section titled “Workspace tabs”](#workspace-tabs) Each workspace tab wears one dot per card, in reading order, grey until that card has something to say. A done card keeps its dot green until you have looked at that card, so a workspace you only passed through still tells you which turns finished there. ## When a colour looks wrong [Section titled “When a colour looks wrong”](#when-a-colour-looks-wrong) Every state change is appended to `agent.log` in `~/Library/Application Support/dev.ekinertac.infiniterm/`: the time, the card, the event, and what it did. Shell commands appear as `[shell]` lines with how long they ran. The log is capped at half a megabyte and never leaves the machine. Agent state is not saved across restarts, so nothing comes back claiming to be working days after the agent died.

# Configuration

> Settings and keybindings files, themes, snippets, and what the app touches.

Configuration lives in `~/.config/infiniterm/`, four files in two pairs, plus the folder `ui-themes/` for the look of the app (see [UI themes](#ui-themes)): 
```plaintext
settings.json              yours, only what you changed
settings.default.json      every setting with its default, commented
keybindings.json           yours, only what you rebound
keybindings.default.json   every binding, commented
```
 The `.default` files are rewritten at every launch, so editing them does nothing. Read them to see what exists, copy a line into your file and change it there. An upgrade never touches your files; new settings appear in the defaults. Each of the four files starts with a link to the reference page for its keys. Your files can be symlinks into a dotfiles repo: a save writes the file the link points at and keeps the link. `Cmd ,` opens settings and `Cmd Shift ,` keybindings, each as a pair of editor cards. Changes apply on save, no restart, also when you save from another editor. A file that does not parse, or has the wrong kind of value (text where a number goes), is not applied: your previous settings stay, and the status bar says `settings.json not applied` with the reason until you save a valid file. `keybindings.json` works the same way. Unknown names, numbers out of range and trailing commas are accepted. In `settings.json` the setting names complete as you type (see [JSON with a schema](../editor/#json-with-a-schema)). ## Settings [Section titled “Settings”](#settings) Keys are flat and dotted, so an override is one line: 
```jsonc
{
  "terminal.fontSize": 16,
  "ui.showFps": true
}
```
 Comments and trailing commas are allowed. Every setting is on the [settings reference](../../reference/settings/). ## Keybindings [Section titled “Keybindings”](#keybindings) 
```jsonc
{
  "cmd+shift+k": "card.clear",
  "cmd+k": null
}
```
 A new `keybindings.json` starts with commented examples; delete the `//` to switch one on. They are another chord to leave a locked editor, turning off the single-Escape unlock, `F2` for go-to-line with a `when`, moving workspace tabs and stepping through themes from the keyboard, `Cmd O` to open a file and `Cmd Alt C` to start Claude Code. A binding set to `null` is removed, which gives the key back to the terminal. A chord must hold `cmd`, with two exceptions: `ctrl` plus a digit, and `ctrl+tab`. A terminal needs Ctrl, Alt and bare keys for itself, but Ctrl plus a digit mostly means nothing to a shell. (On an xterm-compatible terminal `Ctrl 3` sends Escape; if you live in vim, rebind it.) A third exception is a chord with a `when` that is false in a terminal, described next. ### Bindings that apply only sometimes [Section titled “Bindings that apply only sometimes”](#bindings-that-apply-only-sometimes) Give a chord an object with a `when` and the binding applies only while that holds: 
```jsonc
{
  "cmd+shift+e": { "command": "browser.leave", "when": "editorTextFocus" },
  "cmd+t": { "command": null, "when": "editorTextFocus" }
}
```
 The first line binds `Cmd Shift E` to `browser.leave` only in a locked editor. The second unbinds `Cmd T` there and nowhere else (`"command": null` removes the binding in that situation). To give one chord different commands in different places, use a list of objects. The last one whose `when` holds wins. The plain shape above still works. A `when` joins conditions with `&&` and `||`, negates with `!`, compares with `==` and `!=`, and groups with parentheses. Text goes in single or double quotes, and `true` and `false` are allowed. For example `cardKind == 'editor' && !editorHasSelection`. | Key | True when | | ---------------------- | ------------------------------------------------------------------------------------------------------- | | `cardKind` | the focused card’s kind: `terminal`, `editor`, `browser`, `diff`, `transcript`, `page` or `none` | | `terminalFocus` | a terminal card is focused | | `editorFocus` | an editor card is focused, arrowed to or locked | | `editorTextFocus` | an editor card is focused and locked | | `browserFocus` | a browser card is focused | | `cardLocked` | the focused editor or browser card holds the keyboard | | `overlay` | what is open over the canvas: `none`, `palette`, `prompt`, `omnibox`, `shortcuts`, `find` or `switcher` | | `phantomFocus` | an empty slot is focused | | `multiSelection` | more than one card is selected | | `suggestWidgetVisible` | the editor’s completion list is open | | `findWidgetVisible` | the find bar is open | | `editorHasSelection` | the editor has text selected | A key without `cmd`, such as `Escape`, `F2` or a letter, can be bound this way, but only with a `when` that is false in a focused terminal: `editorTextFocus`, `browserFocus` or `phantomFocus` do, `cardLocked` does not. That way a binding can never take a terminal’s input. Otherwise the file reports an error and that binding is ignored. A mistake inside a `when`, such as an unknown key or a bracket left open, is reported the same way. The shortcuts panel and `ift commands` list only plain bindings so far, not the ones with a `when`. Chords follow the physical key, not the character your layout prints on it, so `cmd+=` is the key right of `-` on every keyboard. `Cmd H`, `Cmd M` and `Cmd Q` belong to the menu and cannot be rebound. Every command id is on the [commands reference](../../reference/commands/). In the app, the shortcuts panel (`Cmd /`) shows each command’s id beside its label and finds commands by it: Up and Down highlight one, and `Cmd C` copies its id, ready to paste into `keybindings.json`. ## Themes [Section titled “Themes”](#themes) All 500-odd schemes from iTerm2-Color-Schemes ship with the app; Violite is the default. Your own `.itermcolors` files go in: 
```plaintext
~/Library/Application Support/dev.ekinertac.infiniterm/themes/
```
 “Theme: switch…” in the palette lists the theme you have first, marked active, then every other one A to Z. Each one is applied as you move through the list, with the canvas left undimmed so the cards show its real colours, and the list keeps its order while you do. `Escape`, or a click outside the list, puts back the one you started on; `Enter` keeps the new one. The theme colours the app’s chrome, the editor’s syntax and the card labels too. ## UI themes [Section titled “UI themes”](#ui-themes) The look of the app is not in `settings.json`. It lives in `ui-themes/<name>.json` in the config folder, one file per look. `"ui.theme"` in `settings.json` picks the file (default `"default"`). “UI theme: switch…” in the palette lists them and previews each one live; `Escape` puts the old look back. A file applies as you save it. A file with a mistake is not applied: a notice says why and the look you had stays. To make another look, copy `ui-themes/default.json` and change it. The default file is created at the first launch and lists every key as a commented example with its default. A ui theme holds these keys: * the window: `ui.windowOpacity`, `ui.windowBlur`, `ui.windowColor`, `ui.icon`; * the background picture: `ui.backgroundImage`, `ui.backgroundImageFit`, `ui.backgroundImageInterval`, `ui.backgroundImageFade`; * the cards and canvas: `ui.cardRadius`, `ui.cardOpacity`, `ui.showGrid`, `ui.inactiveDim`, `ui.unfocusedDim`, `ui.hideLabelWhenFitted`, `ui.cardGradient`, `ui.cardGradientAngle`, `ui.focusRingWidth`; * the interface font: `ui.fontFamily`, `ui.fontSize`, `ui.fontWeight`, `ui.fontWeightBold`; * the bars: `titlebar.background`, `titlebar.border`, `statusbar.background` and `statusbar.border`. A background is `#rgb`, `#rrggbb`, `canvas`, `card`, `bar` or `transparent`. A border is a colour or `none`; * the workspace tabs: `tab.background`, `tab.activeBackground`, `tab.gradient`, `tab.opacity`, `tab.border`, `tab.activeBorder`, `tab.separator`, `tab.radius`, `tab.icons`, `tab.iconStyle`, `tab.iconMap`; * the card header: `card.header`, `card.headerIcons`, `card.headerButtons`, `card.headerButtonsActiveOnly`. The first launch that has this feature moves any of these keys out of your `settings.json` into `ui-themes/default.json`. Your comments stay, and a note in `settings.json` says where the keys went. After that, a look key typed into `settings.json` is ignored, with a notice. In a window opened with `ift join`, the host’s settings apply but the look is your own. ### Card gradient and focus ring [Section titled “Card gradient and focus ring”](#card-gradient-and-focus-ring) Everything in this part and the next two is off until a theme sets it. A theme without these keys looks as before. `ui.cardGradient` takes two colours, `#rgb`, `#rrggbb` or `#rrggbbaa`, for example `["#3a2c27", "#1f1a18cc"]`. `ui.cardGradientAngle` is the direction in degrees, 0 to 360. The default, 180, runs top to bottom. `ui.cardOpacity` still applies to both colours, so the gradient stays translucent over the window. Browser cards stay flat. With a gradient on, the gradient reaches the focus ring and a resting card has no dark hairline border. A card with an agent in it keeps its coloured border. `ui.focusRingWidth` sets the width of the focus ring in screen pixels, 0 to 10, at every zoom. With 0, the default, the ring is 3, 4 or 5 pixels, by zoom. The gap between a card and its ring is as wide as the ring, so a thinner ring also closes the gap. ### Workspace tabs [Section titled “Workspace tabs”](#workspace-tabs) * `tab.background` is the fill of a tab that is not chosen, and `tab.activeBackground` is the fill of the chosen tab. Values are `#rgb`, `#rrggbb`, `#rrggbbaa`, `canvas`, `card`, `bar` or `transparent`. Unset, an idle tab has no fill. * `tab.gradient` is two colours, top to bottom, for the chosen tab. It replaces `tab.activeBackground`. `[]` keeps the flat fill. * `tab.opacity`, 0.1 to 1, multiplies the alpha of every tab fill. * `tab.border` and `tab.activeBorder` are a one pixel outline, a colour or `none`. * `tab.separator` is a thin line between idle tabs, a colour or `none`. No line touches the chosen tab. * `tab.radius` rounds the corners, 0 to 40 pixels. `tab.icons: true` puts an icon on each tab for the program that runs in the workspace’s focused card. When no card is focused, it uses the first card. A shell at its prompt shows the shell. `tab.iconStyle` is `"glyph"` (default) or `"image"`. A glyph is a Nerd Font glyph, and the app has glyphs for common shells, runtimes and coding agents. An image is a file in `ui-themes/<theme name>/icons/`, where the theme name is the file name without `.json`. The file is `<program>.svg` or `<program>.png`, or `default.svg` or `default.png` for the rest. A program with no file gets a glyph. `tab.iconMap` maps a program name to a glyph or to a file name ending in `.svg` or `.png`, for example `{"bun": "bun.svg", "default": ""}`. A file name must be a plain name, with no folder in it. The key `default` covers programs not listed. ### Card header [Section titled “Card header”](#card-header) `card.header: true` adds a header row inside terminal, transcript and page cards. It shows the card’s name, and the corner chip is not drawn while the header is on. The header is 30 pixels high at 100% zoom, and the card’s body gets the rest. A terminal then has fewer rows and the same number of columns. Dragging the header moves the card. Editor, diff and browser cards keep their own tab strip and get no header. * `card.headerIcons: true` shows the program’s icon at the left. It uses `tab.iconStyle` and `tab.iconMap`, so a card and its tab agree. * `card.headerButtons` lists the buttons, left to right, from `"split-right"`, `"split-down"`, `"maximise"` and `"close"`. Each runs the command of that name. No button shows unless listed. * `card.headerButtonsActiveOnly: true` shows the buttons only on the focused card. The other headers show the icon and the name, and nothing can be clicked where the buttons would be. With the header on, the chip’s agent colour is not drawn. The card’s border still shows the state. ## The window and the canvas [Section titled “The window and the canvas”](#the-window-and-the-canvas) The keys below go in a ui theme file, not in `settings.json`. `ui.windowOpacity` (0.1 to 1) lets the desktop show through the canvas, title bar and status bar, and `ui.windowBlur` blurs it. `ui.backgroundImage` puts a picture behind the canvas: `"dusk"`, `"aurora"` or `"ember"` come with the app, or give a path to your own; `ui.backgroundImageFit` is `"cover"` (crop to fill) or `"contain"`. A picture is opaque, so it hides the desktop. Give a list instead, `["dusk", "~/Pictures/lake.jpg"]`, and the pictures take turns in that order: each stays `ui.backgroundImageInterval` seconds (300 by default), with a crossfade of `ui.backgroundImageFade` seconds (2 by default, `0` for a cut). An entry that does not exist is skipped. Only two pictures are in memory at a time, so a long list costs no more than a short one. `ui.cardOpacity` lets the canvas and the picture show through card backgrounds while the text stays solid; browser cards stay opaque. `ui.cardRadius` rounds the corners of cards and group frames, in pixels at 100% zoom (0 to 40, default 0 for square corners); the border, the focus ring, the label and the tabs follow it. The window’s own corners stay as macOS draws them. `"ui.showGrid": false` leaves the canvas plain. “Window: change the title bar and Dock colour” in the palette tints the title bar and the workspace tabs, and badges the Dock icon. Pick a named colour (each one shows as you move through the list, `Escape` puts it back) or “Custom hex colour…” for a code like `3b82f6`. The choice is saved as `ui.windowColor` in the ui theme in force, a name or a hex code, empty for none. In an `ift connect` window the same command sets that server’s colour instead, and “Default: from the host name” goes back to the automatic one. `ui.icon` picks the picture in the Dock: `"default"` (four outlined cards) or `"filled"`. It changes when you save the file or switch the ui theme. The window colour badge stays on top of it. The icon in Finder and Launchpad stays the default, because a running app cannot change it. `ui.statusBarPwd` (off by default) shows the focused terminal card’s folder in the status bar, with your home folder as `~`. It is left out when the card’s label already is the path, and a long path is cut so the build number stays. `ui.statusBarPwdSide` puts it on the `"left"` (default) or the `"right"`. `"ui.hideBuildNumber": true` in `settings.json` hides “build N” at the right end of the status bar. ## The interface font [Section titled “The interface font”](#the-interface-font) The workspace tabs, card labels, status bar, palette and dialogs use the macOS system font. `ui.fontFamily` changes it (a font name, for example `"Menlo"` to bring back the monospace look), `ui.fontSize` sets its size, and `ui.fontWeight` and `ui.fontWeightBold` set the normal and bold weights. Terminal, editor and document text keep their own settings (`terminal.fontFamily` and the rest), and `Cmd =` and `Cmd -` still change only the terminal. A change applies as you save. These keys are in the ui theme too. ## Snippets [Section titled “Snippets”](#snippets) `Cmd Ctrl S` lists your snippets and pastes the one you pick into the focused card, the same way `Cmd V` would, so Claude takes a multi-line prompt as one block. Snippets are plain files in `~/.config/infiniterm/snippets/`, one per snippet. The file name without its extension is the snippet’s name; the contents are pasted as written, less one trailing line break. The picker’s last row opens the folder. ## What the app touches [Section titled “What the app touches”](#what-the-app-touches) * Your shells, one per card, started as your login shell with `INFINITERM_CARD_ID` in the environment. Nothing is typed into them that you did not type. * `~/.config/infiniterm/` for settings, keybindings and snippets, and `~/Library/Application Support/dev.ekinertac.infiniterm/` for the canvas, drafts, themes, the window frame, `agent.log`, the browser profile and address-bar history. Deleting `workspace.json` there resets the canvas and leaves your settings alone. Any of these files can be a symlink: every file infiniterm writes is written where the link points, and the link stays. * macOS privacy prompts, only when a program in a card asks for something macOS guards (Photos, the camera, your Documents folder and others). Nothing is asked at install or launch. See [privacy prompts](../terminal/#privacy-prompts). * `ps`, `lsof` and `git` as subprocesses, to label cards and for the diff and blame cards. * The network only from browser cards, the update check, address-bar suggestions from Google, which are off unless you turn on `browser.suggestions`, one request to api.lemonsqueezy.com when you run `ift licence <email> <key>`, ssh to the hosts you name in `ift connect`, and a download from GitHub for `ift connect --install`. No account, no telemetry.

# Editor cards

> Editing files on the canvas, ift as your EDITOR, multiple cursors, tabs, saving, and the diff card.

An editor card is a file on the canvas: syntax highlighting for 17 languages through tree-sitter, find and replace, go to line (`Ctrl G`), comment toggle, and a file tree beside it (`Cmd K`). There is no LSP, on purpose; the completions are words from your files and, for JSON files with a schema, keys and values (below). A scrollbar at the right edge shows when the file is longer than the card. ## Opening files [Section titled “Opening files”](#opening-files) * `ift some/file.rs` run inside a terminal card opens the file in an editor laid over that terminal, ready to type in, and waits until you close it, the way vim does. So `EDITOR=ift` or `GIT_EDITOR=ift` works for `git commit`. * `ift -n some/file.rs` opens it as a card of its own and returns at once. `ift file.rs:20` opens with line 20 in the middle of the view. * `ift ~/Code/project` opens a card with the file tree rooted there. * “Editor: open this card’s folder” in the command palette does the same from the card you are on: an editor beside it with its file tree on the folder the card is in. It is the twin of “Diff: this card against git HEAD”. * “Editor: open a file…” in the palette opens the macOS file panel: a file opens in an editor card, a folder opens with its tree. Drag the line between the tree and the text to make the tree wider or narrower; the card keeps that width. “Card: sidebar wider” and “narrower” in the palette do the same from the keyboard. * `Cmd N` opens an empty editor, and `Cmd` + click on a path in a terminal opens the file beside it. A file that does not exist yet opens empty, and the first save creates it; closing without saving leaves nothing on disk. ## Typing into it [Section titled “Typing into it”](#typing-into-it) An editor you arrived at with the arrows is a card like any other and takes no keys, so nothing typed at the canvas can land in a file. Click into the text or press `Enter` to lock the keyboard to it: the ring turns the warning colour and the status bar says so. While locked, `Cmd T` / `Cmd W` open and close tabs, `Cmd 1` to `Cmd 9` jump between them, and `Cmd S` saves. Middle-click on a tab closes it. `Escape` lets go once it has nothing else to close: the first press closes a completion list, the find bar, extra cursors or a selection, and the next one unlocks. `Cmd Escape` unlocks at once, and `Cmd Shift P` opens the command palette from a locked editor, as from any card. To use another chord for it, set `"cmd+escape": null` and, for example, `"cmd+shift+e": "browser.leave"` in `keybindings.json`. A chord can also apply only while an editor is locked, see [bindings that apply only sometimes](../configuration/#bindings-that-apply-only-sometimes). Typing a quote, a backtick or an opening bracket over selected text wraps it: select `foo`, type `(`, get `(foo)`. The text stays selected, so a second press wraps it again. ## Words from your files [Section titled “Words from your files”](#words-from-your-files) Type two letters and a list of words from the file opens under the caret, nearest to the caret first, then words from the card’s other tabs, marked with the tab’s name. Where the file has a grammar, words inside comments and strings are left out. From three letters, letters in order match too: `gtl` finds `getTotalLength`. `Tab` takes the top row. `Enter` takes a row only after you chose it with Up or Down, so typing a word and pressing `Enter` is still a new line. `Escape` closes the list. To turn it off, set `"editor.completeWords": false`. ## JSON with a schema [Section titled “JSON with a schema”](#json-with-a-schema) A `.json` or `.jsonc` file with a `"$schema"` key near the top completes from that schema: a path beside the file, or an `https` address, downloaded once and kept. Type a quote for its keys, or a quote after a colon for the allowed values, `true` / `false` and the default. The list opens while you type a word, not after a space, a comma or a new line, and not when you move the caret. Your own `settings.json` needs no `$schema`: type `"ui.` and every `ui.*` setting is listed with its default, and the selected one with its description. Letters without a dot match anywhere in the name, so `fitpad` finds `ui.fitPadding`. `Tab` takes the highlighted row. `Enter` takes it only after you moved to it with Up or Down; otherwise `Enter` makes a new line as usual. `Escape` closes the list. ## Multiple cursors [Section titled “Multiple cursors”](#multiple-cursors) * `Cmd` + click adds a cursor or removes one. * `Ctrl Shift Up/Down` adds a cursor on the line above or below. * `Cmd D` adds the next occurrence of the selection; `Ctrl Cmd G` selects every occurrence. * `Cmd Shift L` splits a selection into one cursor per line. * `Escape` goes back to one cursor. Typing, deleting and moving work at every cursor. Copy, paste and the line commands still act on the main one, and an edit made at several cursors takes several `Cmd Z` to undo. ## The diff card [Section titled “The diff card”](#the-diff-card) `ift diff` opens your changes against git HEAD (`ift diff src/` only under a path). The card is an editor in a read-only diff mode, so it keeps the editor’s features. * **Left:** the changed files, each with its `+added` and `-removed` counts. A long name is cut from the front, so the end of the name stays. * **Right:** the file’s diff. It has the syntax colours of the file’s language, two line-number columns (old and new) with `+` and `-` signs, green added lines and red removed lines. Unchanged stretches are folded under “N unchanged lines”. There is a real caret and selection, `Cmd C` copies, `Cmd F` finds, and `Cmd B` adds a blame gutter. Long lines can wrap, and `Cmd D`, `Cmd L`, the word and line moves and the fold keys work as in an editor. Added and removed lines are coloured by their own file’s syntax. An unchanged stretch is a fold: click its gutter, press `Enter` on the line, or press `Cmd Alt ]` to open it. * **Keys.** The card locks like an editor card. Click into it or press `Enter` to go in. On `ift diff <folder>`, a second `Enter` opens the file under the list cursor. In the list, `Right` or `Enter` opens the file and puts the focus on its text; `Left` at column 0 goes back to the list. `Cmd Alt Left` and `Cmd Alt Right` also move between the list and the text. `Cmd K` works on the list in three steps: with the list hidden it shows the list and puts the keys in it; with the keys in the text it moves them to the list, which stays visible; with the keys in the list it hides the list. A diff card opens with the list visible, so the first `Cmd K` from the text moves the keys to the list. `Escape` leaves the card, and `Cmd W` on a locked diff closes it. Bare arrow keys no longer work until you have gone in. * **Not there yet:** a right-click menu with a Copy row, and the picture of a changed image. ## Saving and closing [Section titled “Saving and closing”](#saving-and-closing) `Cmd S` saves. Saving an untitled buffer asks for a name, starting on its directory with `untitled.txt` and only the name selected; an existing file is asked about before it is replaced. Closing unsaved work asks Save, Don’t Save (`Cmd D`) or Cancel, as macOS does, and Save closes the card only once the file is written. Unsaved changes survive a quit of the app. A file changed on disk under a clean buffer is reloaded.

# ift and sessions

> Drive the canvas from a shell, and keep shells running when the app quits.

`ift` is the app’s command-line side. Run from inside a card, it acts on the canvas; run from any terminal, it reaches the running app over its socket. ## Opening things [Section titled “Opening things”](#opening-things) 
```sh
ift                    # launch infiniterm, or focus it if running
ift ~/Code/project     # an editor card with a file tree rooted there
ift src/main.rs        # edit the file over this terminal card, like vim
ift -n src/main.rs     # the file in a card of its own, returning at once
ift -t src/main.rs     # the file as a tab of an editor card
ift -t src/main.rs 2   # ...of card 2 (a number like 2 or #2, or an id)
ift src/main.rs:42     # ...at line 42 (file:42:7 for a column)
ift terminal ~/a ~/b   # a terminal card per folder, its shell starting there
ift diff               # changes against git HEAD, as a card (see Editor cards)
ift diff src/          # only under a path
```
 Run inside a terminal card, `ift <file>` lays an editor over that card and waits until you close it, so `EDITOR=ift` works for `git commit`. A file that does not exist yet opens empty and the first save creates it, so any word that is not one of `ift`’s commands is taken as a file name. See [Editor cards](../editor/). `ift terminal <folder>...` makes a terminal card for each folder on the workspace you are looking at and focuses the last one. It starts infiniterm first when it is not running. `ift terminal --workspace <id|name|new> <folder>...` opens the cards on another workspace and shows it. Give the workspace’s id or its exact name. `new` makes a workspace first, and `--name <text>` names it. Without `--workspace`, nothing changes. `ift workspaces` lists the workspaces from left to right: id, name, number of cards, and `*` on the one on screen. It prints a table on a terminal and tab-separated rows without a header into a pipe. `ift -t <path> [card]` adds the file as a tab of an editor card. Without a card it uses the focused editor card, and opens a card of its own when the focus is not on one. A file that is already open is switched to, not opened twice. A terminal, an unknown card and a directory are refused, and the message says why. A path beats a verb: a directory called `ls` in front of you opens the directory. ## Naming and grouping the card you are in [Section titled “Naming and grouping the card you are in”](#naming-and-grouping-the-card-you-are-in) 
```sh
ift name "api server"
ift group backend      # creates the group if needed
```
 ## Listing [Section titled “Listing”](#listing) 
```sh
ift ls                 # cards: id, group, directory, state, remote, number
ift commands           # every command: id, label, key
ift usage 30           # which commands and gestures you used in 30 days, and which you never did
ift omni rust          # what the address bar would show for "rust"
ift --version          # the version of this ift
```
 On a terminal these print a padded table. Into a pipe they print tab-separated rows without a header, so `ift ls | cut -f1` works. `ift ls --agents` lists only the cards that run an agent, one tab-separated line each: card number, agent, session id, state, directory. The session id is the one `claude --resume` takes. For a Cursor card the lost-session resume line is `cursor agent --resume <id>`, and for an Antigravity card `agy --conversation <id>`. Exit codes: 0 ok, 1 infiniterm is not running, 2 bad usage. ## Driving another card [Section titled “Driving another card”](#driving-another-card) These take a card by its number (`7` or `#7`, the one on its label, which stays the same after a reboot) or by its id. 
```sh
ift send 7 "npm test" --enter     # type into card 7's shell and press Enter
ift send 7 --key ctrl-c           # just a key
ift read 7                        # what card 7's terminal shows now
ift read 7 --lines 20             # only the last 20 lines
ift read 7 --all                  # the scrollback too
ift close 7                       # close it, like Cmd+W
ift focus 7                       # go to it: show its workspace, focus it, fit it
ift run canvas.tidy               # run any command from `ift commands`
```
 `ift focus` moves the view to the card, as picking it in the palette does. `ift send` types into the card without moving the focus or the view. The text goes first, then the keys in the order you give them. `--enter` presses Enter; `--key` takes `enter`, `esc`, `tab`, `backspace`, `ctrl-c`, `ctrl-d`, `ctrl-l`, `ctrl-z`, `up`, `down`, `left` or `right`, and can be given more than once. `ift read` prints the live screen, also when the window is hidden. `ift close` follows the same rules as `Cmd W`, so a closed terminal is parked first; a protected card (`Cmd Shift L`) refuses and says how to unprotect it. `ift run` runs a command on the card in focus, as the palette would, and refuses an id it does not know. Together they let a script watch one card and answer in it. [tools/restart-claude.sh](https://github.com/ekinertac/infiniterm/blob/master/tools/restart-claude.sh) is one: it finds every Claude card with `ift ls --agents`, sends `/exit`, reads the resume command Claude prints, and types `claude --resume` back into the same card. It is an example, not a feature: it clears a prompt line you had not sent, and it does not keep a `CLAUDE_CONFIG_DIR` other than the default. ## Sessions that outlive the window [Section titled “Sessions that outlive the window”](#sessions-that-outlive-the-window) Each terminal card’s shell runs under its own small daemon, `iftd`, which holds the pty. Quitting the app leaves your shells running; reopening it replays what they printed into the same emulator, byte for byte, so a Claude Code session comes back as it was. This is the default backend (`terminal.backend: "daemon"`). A daemon keeps the last 4 MiB of output (`terminal.sessionBuffer`) and writes it to disk every two seconds while output arrives. After a power cut or a reboot, the card replays that above a fresh shell with a `[session lost]` line, and a card that ran Claude has `claude --resume <id>` in its history: Up, Enter. Nothing keeps a process alive across a reboot. ## Reaching a shell from elsewhere [Section titled “Reaching a shell from elsewhere”](#reaching-a-shell-from-elsewhere) 
```sh
ift sessions           # card number and label for each running session
ift sessions --full    # every column: id, pid, cwd, command, started, card, label
ift attach 7           # this terminal becomes card #7's shell
```
 `ift attach` takes the card’s number (the `#7` on its label), which survives a reboot; the session id does not. It works whether the app is running or not, so you can reach a card over ssh from your phone. A session has one client at a time. Attaching takes it from the app: the card shows a banner and ignores keys until you detach with `Ctrl \`, then the app takes it back within a second. ## Servers [Section titled “Servers”](#servers) `ift connect me@server` opens a second window whose terminal cards run on that server. Installing `ift` there, colours, agents and troubleshooting have a page of their own: [Servers](../servers/). `ift join <host>` opens a window on another Mac’s running canvas instead, described there too. ## tmux [Section titled “tmux”](#tmux) `terminal.backend: "tmux"` puts each card in a tmux window in a session named `infiniterm` instead, reachable with `tmux attach -t infiniterm`. It is not the default: tmux is a second terminal emulator in the path and it corrupted Claude Code’s redraws in ways the daemon does not. `"pty"` gives plain shells that end when the app quits.

# Install and first launch

> Download the app, put ift on your PATH, and wire up agent state.

infiniterm runs on Apple Silicon Macs with macOS 13 or later. It is free for personal use; paid work, freelance included, needs a [commercial licence](https://infiniterm.lemonsqueezy.com/checkout/buy/0b6837dd-c037-493e-a530-72f6273fdf3c), $29 per person, one time. ## Install [Section titled “Install”](#install) 
```sh
curl -fsSL https://infiniterm.app/install.sh | sh
```
 It downloads the latest release, checks its checksum, its signature and its notarization the way the app’s own updater does, copies it into `/Applications`, and puts `ift` on your PATH. An app already installed is left alone, since it updates itself. [Read the script](/install.sh) first if you like. Agent hooks edit the agent’s config, so the script asks before wiring them, and only for the agents it finds (Claude Code, Pi, Codex, OpenCode, Cursor, Antigravity). With nobody at a terminal to answer (an agent running the install, a CI job) it skips them and prints the commands. To decide up front, end the line with `| sh -s -- --hooks claude,pi,codex,opencode,cursor,antigravity` (any of them) or `| sh -s -- --no-hooks`. ## Homebrew [Section titled “Homebrew”](#homebrew) 
```sh
brew install --cask ekinertac/tap/infiniterm
```
 The cask links `ift` onto your PATH too. The app updates itself, so `brew upgrade` leaves it alone. If you installed the app from the DMG before, add `--adopt` so Homebrew takes over the copy you have. ## Download by hand [Section titled “Download by hand”](#download-by-hand) The app is signed and notarized, so Gatekeeper opens it without a warning, and it updates itself. 1. Download the `.dmg` from the [latest release](https://github.com/ekinertac/infiniterm/releases/latest). 2. Open it and drag infiniterm into Applications, then launch it once. 3. In any card, put `ift` on your PATH: 
   ```sh
   /Applications/infiniterm.app/Contents/MacOS/ift install
   ```
 This symlinks `ift` into `~/.local/bin` and writes its zsh completion. If either directory is not on your `PATH` or `fpath`, it prints the line to add. ## Build from source [Section titled “Build from source”](#build-from-source) The source is public. You need Rust, the CEF binary distribution and a checkout of cef-rs for its bundler; the README has the steps. Builds are yours to use, not to hand to anyone else. ## Agent hooks [Section titled “Agent hooks”](#agent-hooks) Card borders show what an agent in the card is doing. Each agent reports through hooks, installed once from any shell: 
```sh
ift install-claude-hooks      # Claude Code: edits ~/.claude/settings.json
ift install-pi-hooks          # Pi: installs an extension into ~/.pi/agent
ift install-codex-hooks       # Codex: edits ~/.codex/hooks.json (or $CODEX_HOME)
ift install-opencode-hooks    # OpenCode: writes a plugin to ~/.config/opencode/plugins
ift install-cursor-hooks      # Cursor: ~/.cursor/hooks.json and hooks/infiniterm-cursor-hook.sh
ift install-antigravity-hooks # Antigravity CLI: ~/.gemini/hooks and ~/.gemini/config/hooks.json
```
 Codex asks you to approve new hooks once: run `/hooks` inside Codex after installing. `ift install-pi-hooks DIR` takes a different agent directory, for a wrapper that runs Pi against its own. The Cursor hook is a small script that needs `python3` on the Mac; it covers Cursor’s agent CLI and the IDE’s agent, and the card shows violet while a turn runs but never yellow, since Cursor has no hook while an approval dialog is open. It has not been tried on a live Cursor session yet, because the CLI needs a subscription: the hook path, the payload names and the resume command come from Cursor’s documentation. If a Cursor card shows the wrong colour, please open an issue. The first Cursor hook script reported nothing, so if you installed it before this version, run `ift install-cursor-hooks` again to replace it. Antigravity CLI (`agy`) loads hooks when a session starts, so start a new `agy` session after installing. The card is violet while a turn runs, green when it finishes and red when it ends in an error. Antigravity has no event for a permission prompt, so a turn waiting for your approval shows violet, never yellow. All six accept `--dry-run`, which prints what would change and changes nothing. They are safe to run again, after an update or from a dotfiles script: they add nothing the second time. `install-claude-hooks` merges eight hook entries into your `settings.json` and leaves everything else in it alone (permissions, env, other hooks), and it refuses to touch a file that does not parse. If `settings.json` (or the Codex, OpenCode or Pi file) is a symlink into a dotfiles repo, the installer writes the file it points at and keeps the link. Each prints the file it changed. An agent session that was already running keeps the settings it started with, so start a new session to see its card change colour. To check it works, give the agent a prompt: the card’s border goes violet. If it does not, `agent.log` in `~/Library/Application Support/dev.ekinertac.infiniterm/` shows whether any hook event arrived. To remove them: delete the entries whose command runs `infiniterm-hook` from `~/.claude/settings.json` and `~/.codex/hooks.json`, delete `~/.pi/agent/extensions/infiniterm.ts` and `~/.config/opencode/plugins/infiniterm.js`, and remove infiniterm’s entries from `~/.cursor/hooks.json` plus `~/.cursor/hooks/infiniterm-cursor-hook.sh`. Other commands need no setup: a zsh started in a card reports each command’s start and exit status to the app. See [Card states](../card-states/). ## Shell history per card [Section titled “Shell history per card”](#shell-history-per-card) This is for zsh. Other shells keep their usual history, see [Which shell](../terminal/#which-shell). Each card gets its own zsh history file, so a new card does not open with every other card’s past, and after a reboot a card that ran Claude has `claude --resume <id>` as its last history entry. macOS sets `HISTFILE` before your `.zshrc` runs, so add one line to `.zshrc`: 
```zsh
HISTFILE="${INFINITERM_HISTFILE:-$HOME/.zsh_history}"
```
 Outside infiniterm the variable is unset and your usual history file is used. That keeps each card’s history in its own file, and zsh writes it when the shell exits. A card you leave open for days has not written yet, and `~/.zsh_history` (or a tool that reads it) never sees what you typed in a card. To copy each command to your main history as you enter it, add this to `.zshrc` as well: 
```zsh
autoload -Uz add-zsh-hook
zmodload zsh/datetime
_ift_copy_history() {
  [[ -n $INFINITERM_HISTFILE ]] || return 0
  local nl=$'\n' line=": ${EPOCHSECONDS}:0;${1%$'\n'}"
  line=${line//$nl/\\$nl}
  print -r -- $line >> ~/.zsh_history
  return 0
}
add-zsh-hook zshaddhistory _ift_copy_history
```
 It does nothing outside infiniterm, because `INFINITERM_HISTFILE` is unset there. mcfly keeps its own database and records commands with its own hook, so the hook above adds nothing for it. If you want mcfly’s `Ctrl R` to read `~/.zsh_history` as well, set `export MCFLY_HISTFILE=~/.zsh_history`; to do that only inside infiniterm, guard it with `[[ -n $INFINITERM_HISTFILE ]]`. ## Registering a licence [Section titled “Registering a licence”](#registering-a-licence) Optional. The app never asks for the key and works the same without it; the key in your receipt email is your proof of purchase either way. To have the About window say who the Mac is licensed to: 
```sh
ift licence you@example.com XXXXXXXX-XXXX-XXXX-XXXX-XXXXXXXXXXXX
```
 It asks Lemon Squeezy once whether the key is an infiniterm licence bought with that email, and saves it in `licence.json` beside the canvas. Nothing re-checks it later. Bare `ift licence` says whether this Mac is registered. It exits 3 when the key or email is refused and 4 when Lemon Squeezy cannot be reached. ## Updates [Section titled “Updates”](#updates) The app checks for a new build at launch and every hour. A newer build is downloaded, its signature and notarization are checked, and it is installed the next time the app restarts. The status bar says “update N ready” until then. “Check for Updates…” in the app menu checks now. “About infiniterm” in the app menu (or “App: about infiniterm” in the palette) shows the version and build you are running; `Enter`, `Escape` or a click outside closes it. The check is a plain GET of `latest.json` with nothing about you in it. ### What’s new after an update [Section titled “What’s new after an update”](#whats-new-after-an-update) The first time you open a newer version after an update, the changelog appears in a sheet over the canvas, newest release first, without the days not yet released. `Escape` or the × in its top right corner closes it. The arrows, `Page Up`, `Page Down`, `Home`, `End` and the wheel scroll it. Any other key, or a click outside, only makes the sheet flash: nothing is typed anywhere. It does not appear on a first install. “Help: show what’s new” in the palette opens it at any time. To stop it opening by itself, set `"ui.showWhatsNew": false`. The app keeps the version it last ran in `last_version` in its data folder. ## Your first minute [Section titled “Your first minute”](#your-first-minute) * `Cmd T` opens a terminal card. `Cmd W` closes it. * `Cmd Shift P` is the command palette: everything the app does is in it. * A first launch opens a “Start here” page and nothing else: `Cmd T` makes the first terminal beside it, and `Cmd Alt ←` comes back to it. “Help: open the welcome card” opens it again later. * `Cmd /` lists every shortcut, searchable. * “Help: open the docs” in the palette opens these pages inside the app, as a card with the page list beside it. * “Help: open the changelog” in the palette shows what changed in each release, newest first, as a page card beside the one you are on. It is the same text as the what’s-new sheet, in a card you can keep. * `Cmd` + scroll zooms, `Cmd` + drag pans. Bare scroll and drag belong to the card under the pointer. * `Cmd 2` fits every card in the window, `Cmd 1` fits the focused one.

# Servers

> Connect to a server with ift connect, install ift on it, and join another Mac's canvas with ift join.

`ift connect` opens a second infiniterm for a server. It has its own window, its own Dock icon and its own canvas. Its terminal cards run on the server over ssh. Nothing from your own canvas moves there. ## What you need [Section titled “What you need”](#what-you-need) * A Mac with infiniterm, and `ssh` login to the server **with a key**. ssh must not ask for a password. A host name from your `~/.ssh/config` works as well as `user@host`. * `ift` and `iftd` on the server. `iftd` is the small daemon that keeps each shell running. A Linux server (x86\_64 or aarch64) gets both from `--install`. A server that is a Mac uses the app already installed there. * Windows servers are not supported. ## Connect for the first time [Section titled “Connect for the first time”](#connect-for-the-first-time) 1. Test the host. Nothing is changed. 
   ```sh
   ift connect me@server --check
   ```
 2. If it says `ift` or `iftd` is missing on a Linux server, install them: 
   ```sh
   ift connect me@server --install
   ```
 3. Connect. The first window opens with one terminal card in the server’s home folder. 
   ```sh
   ift connect me@server
   ```
 Next time, run step 3 again. It brings the same cards back. ## What `--install` does [Section titled “What --install does”](#what---install-does) This Mac downloads the package for its own version from the GitHub release and checks its checksum on this Mac. It sends the package to the server through ssh. The server needs no internet, no `curl` and no Rust. * Root gets `/usr/local/bin`. Any other user gets `~/.local/bin`. `ift connect` looks in both places, so it finds `ift` even when `~/.local/bin` is not on the PATH of a non-interactive ssh login. * `--platform linux-x86_64` or `--platform linux-aarch64` skips asking the host which one it is. * `--from <package>` installs from a file you already have instead of downloading. * If the server’s `ift` has a different version from your app, `ift connect` tells you. Run `--install` again to update it. ## Closing the window and coming back [Section titled “Closing the window and coming back”](#closing-the-window-and-coming-back) The shells live in `iftd` on the server, one per card. Closing the window, quitting the app or losing the network leaves them running. `ift connect me@server` brings back the same cards, with their scrollback. From any other shell, `ift sessions` on the server lists the sessions, and `ift attach 7` takes over card number 7. See [ift and sessions](../ift-and-sessions/#sessions-that-outlive-the-window). ## One window per server [Section titled “One window per server”](#one-window-per-server) Each server has its own look and its own files, so you can tell the windows apart at a glance. * **Colour and name.** The title bar leans toward a colour, a chip shows the server’s name, and the Dock icon has a badge. The colour comes from the host name, the same every time. `--color 3b82f6` and `--name prod` set them. “Window: change the title bar and Dock colour” in the palette changes the colour later. * **Settings.** A new server starts with the default settings, not a copy of yours. It keeps its own from then on. To reset one, delete `~/.infiniterm/remotes/<host>/config`. * **Files.** The canvas and settings of a server are saved under `~/.infiniterm/remotes/<host>/`. A long host name is shortened there, because a socket path has a length limit. * **No browser cards.** A browser would run on your Mac, not on the server, so the window refuses them. ## Agents on the server [Section titled “Agents on the server”](#agents-on-the-server) Claude Code, Codex and the other agents show their state on the card in a server window, as on your own canvas. Run the install command for the agent **on the server**, once: 
```sh
ift install-claude-hooks
ift install-codex-hooks
```
 One extra ssh connection carries the hook messages back to the window. It also lets `ift ls`, `ift send` and the rest reach the window from a shell on the server. The server side of that connection is a socket at `/tmp/infiniterm.sock`. See [Install](../install/#agent-hooks) for the other agents. ## When it does not connect [Section titled “When it does not connect”](#when-it-does-not-connect) | `ift connect` says | Do this | | --------------------------------------- | ------------------------------------------------------------------- | | `ift is not installed on the server` | Run `ift connect me@server --install`. | | `iftd is not installed on the server` | Run `ift connect me@server --install`. | | `ssh could not log in without a prompt` | Set up key login for that host, and test with `ssh me@server true`. | | the server’s `ift` is another version | Run `ift connect me@server --install` to match your app. | ssh runs in batch mode, so it never stops to ask for a password or a question. ## Joining a canvas that already exists [Section titled “Joining a canvas that already exists”](#joining-a-canvas-that-already-exists) `ift connect` makes a new canvas that runs on a server. `ift join` is the other way round: it opens a window on the canvas of **another Mac’s infiniterm** and gives you full control of it, as if you sat at that Mac. 
```sh
ift join me@mac-mini            # the host: an ssh alias, user@IP or an IP
ift join me@mac-mini --check    # only test whether the host can be joined
```
 You see the host’s cards, labels and agent colours, and a live terminal for each terminal card. What you do happens on the host: typing goes to the host’s shell, closing a card closes it there, `Cmd T` starts a shell on the host, and moving, resizing, grouping, renaming and workspaces change the host’s canvas. Your zoom, position and focus stay your own. Browser cards show as a card that says what it is and where, and they move and close like any card. Editor, file tree, diff, transcript and page cards work on the host’s files, as the next list says. If you and the host change the canvas at the same moment, both changes stay; your change wins only when you both change the same thing on the same card. * **Login.** Key login works without a prompt. The first time, ssh asks its usual questions in the terminal you ran `ift join` from: the host’s fingerprint and, if there is no key, the password. Run from a launcher or a script, it shows the same questions as macOS dialogs. A host that only takes a password is asked once, and the window’s connections share that one login. A host key that has changed is an error with the new fingerprint, never a question. * **The host’s app can be closed.** `ift join` then starts `ift serve` on the host and tells you so. `ift serve` holds that Mac’s saved canvas and keeps its cards running for viewers. Plain `ift serve` runs in the foreground until `Ctrl C`. `ift serve --detach` runs it in the background and returns once it answers; its output goes to `serve.log` in the data folder. `ift serve --stop` ends it, waiting up to 15 seconds, and the cards keep running. `ift join` runs `--detach` for you on a host with no app. When you start infiniterm on that Mac, it stops `ift serve` itself (no flag, no command), loads the canvas serve just saved and takes over, with the same cards and shells still running. Whoever is joined reconnects by itself within seconds. If `ift serve` does not stop within 10 seconds, the app shows a dialog naming the process and exits. A host whose `ift` is too old to have `serve` is told to update. * **Linux hosts.** A Linux server that runs infiniterm’s sessions but never had the app shows one card for every shell already running. You can type in them, add cards (`Cmd T` makes a shell) and close them. * **Files.** Every file you open in a joined window is a file on the host. An editor card shows the host’s file. You can edit and save it: the save goes to the host. If the file changed on the host after you opened it, the host refuses the save and your text stays. Save again to overwrite on purpose. The card follows changes on the host and keeps its text if the host cannot be reached. A file it could not read stays locked, so it cannot be saved over. A file deleted on the host says so once and keeps its text; saving writes it again. * **File tree.** The editor’s tree lists the host’s folders, for example after `ift -n .` or `Cmd K` on a host card. It says “Loading from the host…” until the list arrives, and shows the host’s error as text if a folder cannot be read. The tree and the open file follow changes on the host within about half a second. * **Git marks.** An editor card shows the added and changed lines in its gutter, from the host’s git. A commit on the host shows in the marks within about 10 seconds. A file outside a repository has no marks. * **Diff and transcript cards.** A diff card lists the files that changed in the host’s git, shows both sides of a file, and supports blame and `Cmd K`. It follows the file as it changes on the host. A git error from the host is shown as text in the card. A transcript card reads the agent’s session file on the host and follows it as the session grows. It shows only what the host has. Page cards (Markdown) show the host’s page, and a link in it opens on the host. * **Pictures and backgrounds.** A picture file in an editor card is fetched from the host and drawn, and follows the file if it changes there. In the host’s canvas background list, a bundled name is the app’s own picture. Any other entry, such as `~/Pictures/x.jpg`, is a file on the host. The copies are kept in the `host-pictures` folder of the app’s data folder. * **Paths.** `Cmd` + click on a path in a joined terminal looks for the path on the host. The host opens an editor or folder card beside the terminal, and your window moves to it and focuses it. A path that is not on the host gives a notice. `ift ./file` typed in a joined terminal shows its editor in your window, and `Cmd W` closes it there and on the host. * **Drops and pastes.** A file dropped on a joined terminal, or an image pasted with `Cmd V` or `Ctrl V`, goes to the host first. It lands in `~/.infiniterm/drops/<id>/` on the host (an image as `clipboard.png`), and the card is given that path. `Ctrl V` with text on your clipboard, or with no image, still goes to the program as a key. A folder, a file over 64 MB, or a host with an older `ift` uses ssh for the copy instead. The host removes drop folders older than a week at the next send. * **Settings.** The window uses the host’s settings and keybindings: font, theme, keys. A change in the host’s file reaches the open window within a second. A host file with an error is not applied. Your host colour, chip and window frame stay your own. “App: open settings” and “App: open keybindings” open the host’s files, beside the host’s defaults, as editor cards that save to the host. The first time, the window asks the host where its settings folder is. A save is applied on the host and reaches every window joined to it. Changing a setting any other way from the joined window is refused with a notice: change it on the host. * **Lost connections.** A card whose connection ends keeps its last screen and shows a short red line, “Lost the connection to the host; joining again”, with the cause in a smaller line under it. Both lines are cut at the card’s edge. The card then joins its session again by itself, waiting 2 seconds and then longer, up to 30. A key typed into it meanwhile is refused with a notice. `Cmd R` makes a card join its session again at once. If the host’s app quits or restarts, the window waits and joins again. * **Restarting the window.** “App: restart”, and the restart that installs an update, bring the joined window back as the same viewer of the same host. If a window for the host is already open, `ift join` says so, with its process number, and brings that window to the front. * **Closing cards.** A close in a joined window closes only the cards you closed in that window, on the host, the normal way. `Cmd Shift T` brings them back, and a shell is kept alive for a while. Cards that are only missing from your copy of the canvas stay open on the host. If the host app was restarted since your last change, that change is dropped and a notice says “the host was restarted; your last change was not applied”. * **Versions.** Use the same build, or a newer one, on both Macs. Update the window and the host together. A window from before the close change cannot close a card on the host. An older `ift` on the host shows no git marks, polls files every 2 seconds, and sends drops over ssh. A browser card from the host stays a placeholder: its page does not load in your window. * **Switching it off.** The host’s join socket is owner-only. The setting `join.enabled` is on by default; set it to `false` and the app closes the join socket, so nothing can join. It applies to the app: `ift serve` runs only when someone asked to join. Nothing is shown or sent unless something joins. ## Not built yet [Section titled “Not built yet”](#not-built-yet) For `ift connect`: editor and diff cards on the server’s files, so `ift file` and `EDITOR=ift` work in a server window. Windows servers.

# Terminal cards

> Font size, find, visual mode, selecting on the zsh command line, a card in its own window, and what closing a card does to its program.

A terminal card runs your login shell in the card’s directory (zsh gets the most, see [Which shell](#which-shell)). Every key without Cmd goes to it untouched, so vim, tmux and readline keep working. ## Font size [Section titled “Font size”](#font-size) `Cmd =` and `Cmd -` make the terminal font one point bigger or smaller, in every terminal card at once, and the size is saved. “Terminal: default font size” in the palette goes back to 14. The canvas zoom is `Cmd` + scroll or a pinch. ## Find [Section titled “Find”](#find) `Cmd F` searches the card you are on, the whole scrollback included. The bar opens inside that card, at its top right under the label. Every match is highlighted, the bar shows a count, and it starts on the newest match, so `Enter` steps up the output. `Cmd G` and `Cmd Shift G` step while the bar is open. `Cmd E` searches for the selected text. Lowercase searches ignore case; a capital letter makes the search match case. `Escape` closes the bar and leaves the current match selected where it is, so `Cmd C` copies it. ## Visual mode [Section titled “Visual mode”](#visual-mode) `Cmd Shift C` puts a keyboard cursor over the card’s output and scrollback, for copying without the mouse. The card wears a VISUAL tag, and nothing you type reaches the shell while it is on. * Move with the arrows, `Alt` or `Cmd` + arrows, Home/End and Page Up/Down, or with vim’s `h j k l`, `w b e`, `0 $`, `g G`. * `Shift` + a move selects, the Mac way. `v`, `V` and `Ctrl V` start a character, line or block selection, the vim way. * `Cmd C` or `y` copies and keeps you in the mode. * `Escape` is the only way out. `Cmd Shift` + arrow stays the canvas’s selection key, so select to a line end with `Shift End`. ## Selecting on the command line [Section titled “Selecting on the command line”](#selecting-on-the-command-line) In zsh, the line you are typing selects like a Mac text field: * `Shift Left/Right`, `Shift Alt Left/Right` and `Shift Home/End` select. * Typing, pasting, `Backspace` or `Delete` replace the selection. * `Cmd C` copies it and `Cmd X` cuts it. A mouse selection in the output wins over it for `Cmd C`. * `Cmd Backspace` and `Cmd Delete` delete to the start and the end of the line, in Claude Code too. This comes from the shell integration the app installs, so it works only in shells started after you installed or updated the app, and only in zsh. There is no mouse selection or click-to-move on the command line. ## Closing a card [Section titled “Closing a card”](#closing-a-card) Closing a terminal card does not kill its program on the spot: * A build, or an agent in the middle of a turn, runs to its end. Anything that has been quiet for a minute (no output, no CPU under its shell, no agent turn) is then ended. * A closed card whose agent is waiting for you is kept until the app quits. The status bar says so, “#7 … (closed) is waiting for you: Alt+T”, and `Alt T` reopens it. At any other time `Alt T` goes to the terminal as usual. * `Cmd Z` or `Cmd Shift T` reopen the card with its program still live and the screen redrawn from its scrollback, as long as it has not ended yet. Quitting the app is different. It does not end any open card: each shell runs in its own `iftd`, so it keeps running, and the next launch reconnects every card to its shell with the screen redrawn from its scrollback. A shell ends only when you exit it, when you close its card and it stays quiet for a minute, or when the Mac restarts (the card then shows its saved output, a `[session lost]` line and a fresh shell). A card you closed that was still running when you quit is not kept. The next launch ends every shell that no saved card claims, so it ends then, not at the quit. This needs the default backend (`terminal.backend: "daemon"`). Under `pty` or `tmux` a closed card’s program ends at once. ## A terminal in its own window [Section titled “A terminal in its own window”](#a-terminal-in-its-own-window) `Cmd Shift O` takes the focused terminal card into a window of its own. The card keeps its place on the canvas as an empty card that says “In its own window”, and keys sent to it on the canvas do nothing while it is out. The window’s terminal refits when you resize the window. Close the window (`Cmd W` or the red button) and the card gets its canvas size back. In the window, `Cmd =` and `Cmd -` change the font size, `Cmd K` clears, `Cmd Shift C` is visual mode, and copy, paste and `Cmd Left` / `Cmd Right` work as in a card. Find and the command palette are not there yet. Only terminal cards can go out for now. ## Redraw [Section titled “Redraw”](#redraw) `Cmd R` asks the program in the focused terminal card to paint its screen again. It clears a scrambled Claude Code card and leaves the scrollback alone. “Terminal: redraw” in the palette and Redraw in the card’s right-click menu do the same. In a window opened with `ift join`, it makes the card join its session again, which has the same effect. ## Which shell [Section titled “Which shell”](#which-shell) A card starts the shell in `$SHELL`. Only zsh gets the shell integration: the state colours for plain commands, one history file per card, and the Shift and arrow selection on the command line. Another shell runs as a plain terminal. Agent hooks still report from it, because they do not depend on the shell. If `$SHELL` is bash and you want zsh, run `chsh -s /bin/zsh` and log in again. Or set `"terminal.shell": "/bin/zsh"` in `settings.json`; that applies to new cards only. Support for bash, fish and nushell is planned. ## Settings worth knowing [Section titled “Settings worth knowing”](#settings-worth-knowing) These go in `settings.json`; every setting is on the [settings reference](../../reference/settings/). * `"terminal.copyOnSelect": true` copies a mouse selection the moment you let go. * `"terminal.scrollMultiplier"` sets scroll speed, from 0.1 to 10 (default 1). * `"terminal.padding"` is the space between a card’s edge and its text, 0 to 60 (default 6). Open cards resize to it at once. * `"terminal.env": ["EDITOR=ift"]` adds environment variables to new cards. * `"terminal.fontFamily"` is read as a list, like `["JetBrains Mono", "Menlo", "monospace"]`: a family that is not installed is skipped and the next one is used. A list that ends with `monospace` gets an installed monospace font when no named family is there. Before, the first name was used even when it was missing. * `"terminal.shell"` takes arguments too, like `"/bin/zsh -l"`. ## Cursor colour [Section titled “Cursor colour”](#cursor-colour) A block cursor draws the letter under it in the theme’s cursor text colour, or black or white when that would not contrast. `terminal.cursorColor` and `editor.cursorColor` (a hex colour such as `"#ff9900"`; empty follows the theme) set the cursor’s colour, and the letter under it follows. ## Links and paths [Section titled “Links and paths”](#links-and-paths) Hold `Cmd` over a link or a path that exists and it underlines; `Cmd` + click opens it beside the card, a file in an editor card and a URL in a browser card. A double-click on a link selects the whole address. Links a program marks itself (OSC 8: `ls --hyperlink`, `rg --hyperlink-format`, `gcc`, and the markdown links in an agent’s reply) are underlined at rest and open on `Cmd` + click, whatever their visible text says; only `http` and `https` addresses open, since the text of a link can lie. Every new terminal card sets `FORCE_HYPERLINK=1` so Claude Code prints real links; a card that is already open keeps its old environment, and `"terminal.env": ["FORCE_HYPERLINK=0"]` turns it off. Issue and pull request numbers are links too: in a card whose directory is a GitHub checkout, `#349` opens that issue or pull request, and `owner/repo#349` works in any card. A bare number needs a space, bracket or quote before it and no letter after it. Holding `Cmd` over any link draws a strong double underline and turns the pointer to a hand. Dropping a file from the Finder onto a terminal pastes its shell-escaped path. ## Claude Code’s fullscreen mode [Section titled “Claude Code’s fullscreen mode”](#claude-codes-fullscreen-mode) Claude Code’s `/tui fullscreen` mode does not work properly in infiniterm: most of it misbehaves, and there is no fix planned. Run `/tui default` in the Claude Code session, which is the way to use it here. ## Privacy prompts [Section titled “Privacy prompts”](#privacy-prompts) A program in a card can use what macOS guards: Photos, Contacts, Calendars, Reminders, the camera, the microphone, speech recognition, your location, Bluetooth, other apps (Automation), the Desktop, Documents and Downloads folders, Accessibility, Screen Recording, Input Monitoring and the local network. The first time a program asks, macOS shows its usual dialog. Nothing is asked when you install or launch infiniterm, and infiniterm itself uses none of them. The grant is listed under infiniterm in System Settings > Privacy & Security, because macOS sees the app, not the program in the card. Each one is asked once; change it there later. Full Disk Access is never asked for. If a script needs it, for example to read `~/Library/Mail`, add infiniterm by hand in System Settings > Privacy & Security > Full Disk Access. HomeKit and Siri are not available to programs in a card.
